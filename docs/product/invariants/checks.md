# Invariant register — Checks

[Invariant register](../invariants.md) · [Spice product model](../README.md)
## Checks

| Label | Invariant |
| --- | --- |
| <a id="checks-check-settings-have-one-source"></a>**Check settings have one source** | Check settings live in one place that hooks, studies, docs, and tests all read. |
| <a id="checks-direct-study-commands-may-take-flags"></a>**Direct study commands may take flags** | Direct study commands may take flags; the commit gates run the defaults. |
| <a id="checks-flex-is-headroom-not-a-new-limit"></a>**Flex is headroom, not a new limit** | Flex is headroom, not a new limit: the first accepted breach latches a file to its base limit until an accepted run measures it at or below base. |
| <a id="checks-accepted-reconciliation-is-scoped"></a>**Accepted reconciliation is scoped** | An accepted partial run publishes only the keys it observed and preserves unrelated state; an accepted exhaustive run also prunes keys absent from its complete inventory. |
| <a id="checks-sticky-latches-and-live-claims-are-repository-shared"></a>**Sticky latches and live claims are repository-shared** | One run-start ledger is shared by every selected arm. Accepted latches and time-boxed flex claims are visible to every actor in the repository; provenance-seeded jitter changes a ceiling, never state ownership or visibility. |
| <a id="checks-ceilings-are-jittered-per-path-and-resolved-provenance"></a>**Ceilings are jittered per path and resolved provenance** | A ceiling varies with the canonical path and the first available provenance seed in the fixed resolution order. The selected seed source remains evidence rather than being flattened into actor identity. |
| <a id="checks-wide-measures-diff-against-a-baseline"></a>**Wide measures diff against a baseline** | Wide measures diff against a baseline so only regressions fail. |
| <a id="checks-some-ceilings-are-absolute-zero"></a>**Some ceilings are absolute zero** | Some ceilings are absolute zero — test-only public symbols, assertion-free tests. |
| <a id="checks-a-requested-gate-findings-dispatch-files-deferred-work"></a>**A requested gate-findings dispatch files deferred work** | When explicitly requested for one registered instrument, gate-findings dispatch files each reported finding as deferred, traceable work rather than only printing. A study alone never files. |
| <a id="checks-dirty-work-renders-the-same-pressure-as-steering"></a>**Dirty work renders the same pressure as steering** | Dirty work renders the same pressure as steering, not as a block. |
| <a id="checks-a-gate-is-never-closed-by-weakening-it"></a>**A gate is never closed by weakening it** | A gate is never closed by weakening it. |
| <a id="checks-tests-assert-present-observable-properties-in-preference-to-absence"></a>**Tests assert present, observable properties in preference to absence** | Tests assert present, observable properties in preference to absence. |
| <a id="checks-the-selected-gate-battery-is-deterministic-ordered-and-immutable"></a>**The selected gate battery is deterministic, ordered, and immutable** | One run captures the explicitly selected gate arms and their order before execution. The selection cannot grow, shrink, or reorder while the run is in flight; unselected registered gates are not implicitly added. |
| <a id="checks-each-selected-step-s-failure-is-collected-and-the-run-continues"></a>**Each selected step's failure is collected and the run continues** | Each selected step's failure is collected and the run continues where its dependencies permit, so one commit attempt reports the whole selected picture rather than the first finding. |
| <a id="checks-a-passing-installed-hook-prints-nothing"></a>**A passing installed hook prints nothing** | A passing installed hook emits no terminal diagnostic. A direct selection command returns its complete typed report. |
| <a id="checks-an-arm-that-cannot-execute-returns-a-named-refusal"></a>**An arm that cannot execute returns a named refusal** | An arm that cannot execute returns a named refusal state with the evidence that explains it; it never impersonates a pass or admitted absence. |
| <a id="checks-a-measured-pass-retains-the-limits-it-applied"></a>**A measured pass retains the limits it applied** | A measured pass retains the limits it applied, so it is evidence about which thresholds were in force. |
| <a id="checks-not-applicable-is-explicit-admissible-evidence"></a>**Not-applicable is explicit admissible evidence** | A selected arm with no applicable input emits typed not-applicable evidence with a reason and exact declaration-owned provenance. It admits the run but is neither a measured pass, an explicit exclusion, nor a refusal. |
| <a id="checks-direct-runs-preserve-typed-terminal-evidence"></a>**Direct runs preserve typed terminal evidence** | Direct runs preserve passed, not-applicable, excluded, and named refusal states. The enclosing commit decision admits only passed and contract-owned absence or exclusion; it never erases the evidence distinctions. |
| <a id="checks-gate-state-is-published-only-with-an-accepted-run"></a>**Gate state is published only with an accepted run** | Proposed latch creation, healing, rename propagation, and pruning remain transaction-local until the selected run is accepted. A refused run leaves every pressure ledger byte-for-byte unchanged. |
| <a id="checks-steps-contributed-by-configuration-are-skipped-unless-the-staging-step-passed"></a>**Steps contributed by configuration are skipped unless the staging step passed** | Steps contributed by configuration are skipped unless the staging step passed, so an extension never runs against a half-staged tree. |
| <a id="checks-policy-compiles-an-elastic-ceiling-to-one-checked-integer"></a>**Policy compiles an elastic ceiling to one checked integer** | Policy applies the finite multiplier, optional clamps, and any ratchet once to produce one checked integer ceiling. Non-finite input, an invalid range, or an unrepresentable result refuses rather than selecting a fallback. |
| <a id="checks-a-refusal-caused-by-a-latch"></a>**A refusal caused by a latch** | A refusal caused by a latch rather than by the value says so and names the ledger holding it. Over-the-limit and held-at-base are different diagnoses. |
| <a id="checks-a-healed-latch-retires-only-with-an-accepted-run"></a>**A healed latch retires only with an accepted run** | Measuring a latched subject at or under base proposes retirement, but the retirement publishes only when the entire selected run is accepted. A failed run cannot partially heal persistent state. |
| <a id="checks-an-emptied-ledger-is-deleted"></a>**An emptied ledger is deleted** | An emptied ledger is deleted rather than left as an empty file, so a healed subject leaves no trace. |
| <a id="checks-latches-follow-renames-additively"></a>**Latches follow renames additively** | Latches follow renames additively: a renamed subject carries its latch forward without the old name being silently dropped. |
| <a id="checks-jitter-is-applied-over-the-headroom"></a>**Jitter is applied over the headroom** | Jitter is applied over the headroom rather than over the limit, so a jittered ceiling can never fall below base. |
| <a id="checks-jitter-seed-resolution-has-one-provenance-retaining-order"></a>**Jitter seed resolution has one provenance-retaining order** | Jitter uses the first available value in this order: published task session, published commit, active actor, candidate blob, then canonical candidate path. The report retains both the selected value and its source. |
| <a id="checks-jitter-is-deterministic"></a>**Jitter is deterministic** | The same captured path, resolved seed, and policy always produce the same integer ceiling, so replaying unchanged evidence never moves the limit. |
| <a id="checks-live-breaches-on-shared-subjects-are-claimed"></a>**Live breaches on shared subjects are claimed** | Live breaches on shared subjects are claimed and time-boxed. At run start an elapsed claim is treated as absent and pruning is proposed, but only an accepted run publishes its removal. |
| <a id="checks-the-earliest-claimant-owns-a-contested-subject"></a>**The earliest claimant owns a contested subject** | The earliest claimant owns a contested subject, with a deterministic tie-break, so ownership never depends on scan order. |
| <a id="checks-a-finding-whose-subject-is-held-by-a-peer-informs-and-passes"></a>**A finding whose subject is held by a peer informs and passes** | A finding whose subject is held by a peer informs and passes; only unclaimed findings block. The redirect names the holder and the expiry. |
| <a id="checks-every-run-binds-one-actor-and-run-start-claims"></a>**Every run binds one actor and run-start claims** | Every battery requires one named active actor and captures the run-start claims into its verdict semantics. A revision-selected run may observe those claims, but rejects reconciliation before durable publication. |
| <a id="checks-a-limit-has-one-declared-kind"></a>**A limit has one declared kind** | A limit is a threshold, a set equality, a differential, or binary — and a measure declares which kind it is. |
| <a id="checks-a-measure-whose-baseline-cannot-be-read-must-not-report-clean"></a>**A measure whose baseline cannot be read must not report clean** | A measure whose baseline cannot be read must not report clean; a missing baseline and an empty baseline produce the same set and must not produce the same verdict. |
| <a id="checks-a-gate-run-captures-the-exact-staged-selection"></a>**A gate run captures the exact staged selection** | Before measurement, the run captures the selected paths, staged bytes, modes, and digests as one immutable input. A later index or working-tree edit cannot change what that run judges. |
| <a id="checks-selectors-are-mutually-exclusive"></a>**Selectors are mutually exclusive** | Selectors are mutually exclusive; ambiguous selection is refused rather than resolved by precedence. |
| <a id="checks-the-appliance-s-own-runtime-state-is-excluded-from-every-selector"></a>**The appliance's own runtime state is excluded from every selector** | The appliance's own runtime state is excluded from every selector, so a study can never take its bookkeeping as evidence about the repository. |
| <a id="checks-the-fully-staged-rule-is-the-intersection-of-staged-and-unstaged-names"></a>**The fully-staged rule is the intersection of staged and unstaged names** | The fully-staged rule is the intersection of staged and unstaged names: a partly staged file is refused before capture. If the index moves after capture, the run is refused rather than judging or publishing against mixed generations. |
| <a id="checks-every-waiver-is-declared-and-enumerable"></a>**Every waiver is declared and enumerable** | Every waiver is declared and enumerable. There is no silent suppression. |
| <a id="checks-an-allowlist-names-the-specific-thing-it-permits"></a>**An allowlist names the specific thing it permits** | An allowlist names the specific thing it permits; a count is never a waiver, because permitting three of these permits the wrong three. |
| <a id="checks-a-scoped-rule-retunes-a-bound-over-a-declared-path-set"></a>**A scoped rule retunes a bound over a declared path set** | A scoped rule retunes a bound over a declared path set. It changes the limit and cannot disable the measure. |
| <a id="checks-a-step-may-be-disabled-by-configuration"></a>**A step may be disabled by configuration** | A step may be disabled by configuration, and the check system audits its own disablements, so turning a gate off is a visible act rather than an absence. |
| <a id="checks-waivers-are-tracked"></a>**Waivers are tracked** | Waivers are tracked, so every clone sees the same exceptions; an exception that lives on one machine is a local divergence, not an exception. |
| <a id="checks-only-registered-instruments-may-file-work"></a>**Only registered instruments may file work** | Only registered instruments may file work, and only when asked. A study does not decide on its own to put something on the board. |
| <a id="checks-filing-is-idempotent-against-a-finding-s-identity-within-its-project"></a>**Filing is idempotent against a finding's identity within its project** | Filing is idempotent against a finding's identity within its project: re-running an instrument reuses the open task rather than filing a second. |
| <a id="checks-a-finding-s-identity-survives-the-board-s-own-normalization"></a>**A finding's identity survives the board's own normalization** | A finding's identity survives the board's own normalization, which is what makes it a key rather than a label. |
| <a id="checks-a-completed-predecessor-never-blocks-re-filing"></a>**A completed predecessor never blocks re-filing** | A completed predecessor never blocks re-filing; recurrence files afresh with an annotation naming the resolved task, so the link is recorded rather than inferred. |
| <a id="checks-study-work-is-filed-deferred-and-carries-no-due-date"></a>**Study work is filed deferred and carries no due date** | Study work is filed deferred and carries no due date, so time spent parked does not consume the priority clock. |
| <a id="checks-a-study-task-carries-the-same-required-origin-as-any-other-task"></a>**A study task carries the same required origin as any other task** | A study task carries the same required origin as any other task, inheriting the acting claim when none is given. |
| <a id="checks-findings-and-filed-work-are-coextensive"></a>**Findings and filed work are coextensive** | Findings and filed work are coextensive; an instrument reports what it found and dispatch decides what becomes a task, so an instrument cannot pre-seed or suppress its own filing. |
| <a id="checks-the-retained-selected-tree-is-the-sole-source-authority"></a>**The retained selected tree is the sole source authority** | One private immutable tree contains the exact staged-index or named-revision objects bound to the run's source identity. An arm consumes it directly or through a verified exact sealed mirror with separate outputs; a mirror never widens or replaces selected source. |
| <a id="checks-the-caller-s-checkout-stays-read-only-for-the-whole-measurement"></a>**The caller's checkout stays read-only for the whole measurement** | The caller's checkout stays read-only for the whole measurement, so concurrent control-plane commands keep observing reality. |
| <a id="checks-a-companion-lock-is-the-liveness-authority-for-a-private-root"></a>**A companion lock is the liveness authority for a private root** | Cleanup reclaims a private root only after acquiring its exact companion lock. A directory name or process-shaped suffix is never enough evidence that a root is abandoned. |
| <a id="checks-cleanup-removes-the-workspace-before-its-lock"></a>**Cleanup removes the workspace before its lock** | While holding the companion lock, cleanup lifts the read-only seal, removes the workspace, and unlinks the lock only after removal succeeds, retaining enough evidence for a later safe reclamation after interruption. |
| <a id="checks-configuration-fails-loudly"></a>**Configuration fails loudly** | Configuration fails loudly: unknown keys are rejected at load in every layer, and an invalid bound is an error rather than a silent fall back to the default. |
