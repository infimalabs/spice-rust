# Invariant register — Distribution and conduct

[Invariant register](../invariants.md) · [Spice product model](../README.md)
## Distribution

| Label | Invariant |
| --- | --- |
| <a id="distribution-release-notes-derive-from-history"></a>**Release notes derive from history** | Release notes derive from history; there is no maintained changelog to drift. |
| <a id="distribution-implement-and-revert-pairs-in-one-range-are-suppressed"></a>**Implement-and-revert pairs in one range are suppressed** | Implement-and-revert pairs in one range are suppressed; phase pairs dedupe by task. |
| <a id="distribution-the-release-gate-runs-the-complete-strict-battery-over-one-immutable-source"></a>**The release gate runs the complete strict battery over one immutable source** | Release execution selects the exact source commit named by the accepted plan and runs the complete canonical strict battery over that immutable tree. Every arm must admit before the version bump or any external publication. |
| <a id="distribution-inspection-is-free-of-consequence"></a>**Inspection is free of consequence** | Inspection is free of consequence: checking the gates, drafting the notes, and previewing the range never bump, commit, tag, push, or publish. |
| <a id="distribution-an-install-has-one-canonical-status-bearing-receipt"></a>**An install has one canonical status-bearing receipt** | One canonical receipt records the exact plan, prior images, operation progress, and status needed to resume or unapply. Its complete file image and native generation condition every atomic replacement. |
| <a id="distribution-external-publication-renders-its-complete-ordered-plan"></a>**External publication renders its complete ordered plan** | Every verb with externally visible publication effects renders its complete ordered plan and performs no such effect until execution is explicitly requested. Ordinary local mutations need transactional contracts, not ceremonial previews. |
| <a id="distribution-an-execution-request-pins-the-digest-of-the-plan-that-was-read"></a>**An execution request pins the digest of the plan that was read** | An execution request pins the digest of the plan that was read. If fresh observation derives another plan, execution refuses with the current expected and operator-supplied plan identities; it does not invent an operation-level diff. |
| <a id="distribution-plan-identity-covers-every-input-to-publication"></a>**Plan identity covers every input to publication** | Plan identity covers the repository, action, version, source and release commits, exact target matrix, ordered operations, notes, artifacts, proof receipts, sealed manifest, and captured preconditions. The correctness operation intrinsically means the complete canonical strict battery, so no mutable gate subset sits outside the plan. |
| <a id="distribution-step-order-is-part-of-what-the-plan-commits-to"></a>**Step order is part of what the plan commits to** | Step order is part of what the plan commits to. Target-specific effects execute only in the resolved order encoded by the sealed plan. |
| <a id="distribution-preconditions-that-can-be-evaluated-without-effect-are-evaluated"></a>**Preconditions that can be evaluated without effect are evaluated** | Preconditions that can be evaluated without effect are evaluated while the plan is built, before anything expensive or irreversible begins. |
| <a id="distribution-local-release-progress-admits-only-three-exact-shapes"></a>**Local release progress admits only three exact shapes** | Publish admits the clean source commit at its source version, that same commit with only `dist/VERSION` changed exactly to the requested version, or the clean deterministic release commit. Tag-and-announce admits only the last shape. Every other tracked change, commit, version, or HEAD shape refuses; no task claim is inferred. |
| <a id="distribution-every-target-binds-the-same-source-and-the-publication-index-binds-version-once"></a>**Every target binds the same source, and the publication index binds version once** | Both target payloads bind one exact source identity. The canonical publication index binds the product version, source, sealed manifest, release notes, and both native targets once; any disagreement refuses before effect planning. |
| <a id="distribution-the-target-matrix-is-exact-and-ordered"></a>**The target matrix is exact and ordered** | The sealed release contains `aarch64-apple-darwin` followed by `x86_64-unknown-linux-musl`, exactly once each. Missing, extra, duplicated, or reordered targets refuse before effect planning. |
| <a id="distribution-the-version-the-bump-produces-must-equal-the-version-the-plan-named"></a>**The version the bump produces must equal the version the plan named** | The version the bump produces must equal the version the plan named, or the run aborts before anything is committed. |
| <a id="distribution-a-named-release-commit-carries-its-own-declared-version"></a>**A named release commit carries its own declared version** | A named release commit carries its own declared version; a requested version that disagrees with it is refused. |
| <a id="distribution-a-version-names-exactly-one-commit"></a>**A version names exactly one commit** | A version names exactly one commit. An existing tag pointing somewhere else refuses rather than being moved. |
| <a id="distribution-publication-builds-each-sealed-target-from-the-exact-source-commit"></a>**Publication builds each sealed target from the exact source commit** | Each `TargetPayload` binds its schema, native target triple, exact source identity, application, embedded-application and native-executable digests, build pins and their digest, and an ordered path, mode, size and digest inventory. Publication never substitutes ambient checkout state. |
| <a id="distribution-proof-runs-outside-the-candidate-checkout"></a>**Proof runs outside the candidate checkout** | Each native target payload is proved outside the candidate checkout, with only the sealed payload and declared proof inputs admitted. Candidate source and ambient build output cannot satisfy the probe. |
| <a id="distribution-proof-receipts-are-detached-and-locally-validated"></a>**Proof receipts are detached and locally validated** | Proof emits a detached receipt binding the target, payload digest, ordered battery digest, complete replay digest, sealed environment identity, and clean or refused standing. Receipt structure and every referenced digest are recomputed locally before acceptance. |
| <a id="distribution-sealing-occurs-after-proof"></a>**Sealing occurs after proof** | The release manifest is sealed only after every required target has a valid detached proof receipt; the seal binds target payloads and receipts into one immutable multi-target release identity. |
| <a id="distribution-the-artifact-gate-discards-prior-build-output"></a>**The artifact gate discards prior build output** | The artifact gate discards prior build output, stages the freshly built native payload, and probes that staged executable itself with only declared proof inputs admitted. |
| <a id="distribution-first-parent-landings-produce-single-entries"></a>**First-parent landings produce single entries** | Only first-parent landings are counted, so one merged unit of work contributes one entry rather than one per internal commit. |
| <a id="distribution-landings-sharing-a-task-identity-collapse-into-one-entry"></a>**Landings sharing a task identity collapse into one entry** | Landings sharing a task identity collapse into one entry, held where that task first landed and described by its latest wording. |
| <a id="distribution-a-revert-pairs-with-the-landing-whose-history-contains-the-reverted-commit"></a>**A revert pairs with the landing whose history contains the reverted commit** | A revert pairs with the landing whose history contains the reverted commit, not with one whose identifier equals it. |
| <a id="distribution-every-entry-carries-at-least-one-reference-back-into-history"></a>**Every entry carries at least one reference back into history** | Every entry carries at least one reference back into history, and entries preserve the order in which the work landed. |
| <a id="distribution-entries-group-by-the-project-each-commit-itself-declares"></a>**Entries group by the project each commit itself declares** | Entries group by the project each commit itself declares; a commit declaring none lands in a general grouping rather than disappearing. |
| <a id="distribution-a-trailing-handle-is-stripped-from-a-description-only-when-it-matches-that-commit-s-own-recorded"></a>**A trailing handle is stripped from a description only when it matches that commit's own recorded** | A trailing handle is stripped from a description only when it matches that commit's own recorded identifier. |
| <a id="distribution-the-window-runs-from-the-highest-versioned-prior-release-tag-reachable-from-the-release-commit"></a>**The window runs from the highest-versioned prior release tag reachable from the release commit** | The window runs from the highest-versioned prior release tag reachable from the release commit, addressed through its fully qualified ref namespace; with no prior tag it degrades to a bounded window of recent landings and says so. |
| <a id="distribution-curation-owns-the-region-above-the-generated-inventory"></a>**Curation owns the region above the generated inventory** | Curation owns the region above the generated inventory; everything from the inventory down is regenerated at publication against the real release commit. |
| <a id="distribution-notes-are-refused-when-they-are-an-untouched-draft"></a>**Notes are refused when they are an untouched draft** | Notes are refused when they are an untouched draft, when they still carry the placeholder, or when the curated region holds nothing but banner and headings. |
| <a id="distribution-credentials-are-obtained-and-validated-before-the-first-externally-visible-action"></a>**Credentials are obtained and validated before the first externally visible action** | Credentials are obtained and validated before the first externally visible action, not at the moment they are used. |
| <a id="distribution-each-externally-visible-effect-is-rehearsed-when-the-endpoint-supports-it"></a>**Each externally visible effect is rehearsed when the endpoint supports it** | Each externally visible effect is rehearsed against its real endpoint in a no-effect mode when that endpoint provides one; otherwise the plan names the unrehearsable boundary explicitly. |
| <a id="distribution-publication-exposes-only-the-sealed-release-object"></a>**Publication exposes only the sealed release object** | The source commit, target payloads, proof receipts, manifest, tag, and announcement all name the same sealed release identity. Publication waits for each external acknowledgement required by the plan and fails loudly when it does not arrive. |
| <a id="distribution-every-publication-step-converges"></a>**Every publication step converges** | Every publication step converges rather than duplicating, so a release interrupted partway through is completed by re-running it. |
| <a id="distribution-an-operator-interruption-terminates-with-a-status-distinct-from-a-gate-failure"></a>**An operator interruption terminates with a status distinct from a gate failure** | An operator interruption terminates with a status distinct from a gate failure. |
| <a id="distribution-what-the-operator-reviews-before-authorizing-an-installation-is-produced-purely-by-observation"></a>**What the operator reviews before authorizing an installation is produced purely by observation** | What the operator reviews before authorizing an installation is produced purely by observation, and is the same resolved plan that later executes. |
| <a id="distribution-an-approval-of-executable-repository-configuration-binds-an-exact-snapshot-of-it"></a>**An approval of executable repository configuration binds an exact snapshot of it** | An approval of executable repository configuration binds an exact snapshot of it; applying refuses when the live configuration differs from what the operator saw. |
| <a id="distribution-install-progress-is-published-by-receipt-generation"></a>**Install progress is published by receipt generation** | Before the first receipt-owned repository effect, the canonical receipt is accepted as writable. Immutable content-addressed rollback material may be staged earlier but has no authority until that receipt authenticates it. Each subsequent progress or terminal status is compare-and-swap published from the exact prior receipt generation, so concurrent or stale writers refuse. |
| <a id="distribution-no-change-precedes-its-accepted-receipt-state"></a>**No change precedes its accepted receipt state** | No installation change is made until the receipt state describing its exact operation and prior image has been formed and accepted durably; completion is recorded before the next operation begins. |
| <a id="distribution-each-record-carries-the-complete-prior-state-of-what-it-touched"></a>**Each record carries the complete prior state of what it touched** | Each record carries the complete prior state of what it touched — the previous value, the previous permissions, and whether the file, setting, or parent directory existed at all. |
| <a id="distribution-prior-state-is-captured-once-at-first-application"></a>**Prior state is captured once, at first application** | Prior state is captured once, at first application; a repeat never re-derives it from state the installation itself produced. |
| <a id="distribution-reversal-runs-the-recorded-operations-in-exact-reverse-order-of-application"></a>**Reversal runs the recorded operations in exact reverse order of application** | Reversal runs the recorded operations in exact reverse order of application, and refuses a record whose order is not the exact inverse. |
| <a id="distribution-reversal-restores-only-what-still-matches-what-was-applied"></a>**Reversal restores only what still matches what was applied** | Reversal restores only an exact receipt-owned installed identity. If the target differs, reversal refuses as drift without overwriting it; the current receipt remains the recovery authority and no terminal uninstalled status is published. |
| <a id="distribution-a-container-is-removed-only-when-the-installation-created-it-and-it-is-still-empty"></a>**A container is removed only when the installation created it and it is still empty** | A container is removed only when the installation created it and it is still empty. |
| <a id="distribution-identity-drift-preserves-the-target-and-current-receipt"></a>**Identity drift preserves the target and current receipt** | A drift refusal preserves both the changed target and the current receipt. Repair or deliberate reconciliation is separate; retry resumes that same receipt rather than inventing a successful partial uninstall. |
| <a id="distribution-an-interrupted-operation-blocks-an-opposing-or-new-installation-until-resumed"></a>**An interrupted operation blocks an opposing or new installation until resumed** | Interrupted apply and unapply are resumable and idempotent. While either is incomplete, the same receipt must resume; an opposing or new installation refuses rather than interleaving. |
| <a id="distribution-the-canonical-receipt-is-retained-after-terminal-state"></a>**The canonical receipt is retained after terminal state** | The canonical receipt remains after an ordinary clean apply or unapply reaches terminal state, preserving status, exact prior images, and progress. An ordinary refresh retains the pre-first-install reversal images and superseded installed identities; unapply restores that original filesystem state and terminates the current receipt. Only the admitted version-7 migration authenticates a rollback snapshot whose reversal restores the exact pre-migration assets and receipt. Absence is never synthesized by deleting provenance. |
| <a id="distribution-the-canonical-receipt-is-published-atomically-with-compare-and-swap"></a>**The canonical receipt is published atomically with compare-and-swap** | Each receipt generation is a bounded, self-contained canonical document published atomically through a real non-symbolic file and conditioned on the exact previous generation. |
| <a id="distribution-an-unreadable-noncanonical-or-inconsistent-receipt-refuses"></a>**An unreadable, noncanonical, or inconsistent receipt refuses** | An unreadable, truncated, noncanonical, linked, or internally inconsistent receipt refuses; it is never repaired, truncated, or treated as evidence that nothing is installed. |
| <a id="distribution-generated-artifacts-live-in-a-directory-the-product-owns"></a>**Generated artifacts live in a directory the product owns** | Generated artifacts live in a directory the product owns and are activated by redirecting the host tool there, never by writing into the location the repository already uses for the same purpose. |
| <a id="distribution-every-generated-artifact-carries-an-ownership-digest"></a>**Every generated artifact carries an ownership digest** | Every generated artifact carries an ownership digest, so an untouched installation is distinguishable from a locally modified one and from a newer generated shape. |
| <a id="distribution-when-a-setting-s-prior-scoped-value-differs-from-the-value-that-was-actually-taking-effect"></a>**When a setting's prior scoped value differs from the value that was actually taking effect** | When a setting's prior scoped value differs from the value that was actually taking effect, the preview shows both. |

## Conduct

| Label | Invariant |
| --- | --- |
| <a id="conduct-a-refusal-that-can-name-a-way-out-leads-with-the-exact-repair-action"></a>**A refusal that can name a way out leads with the exact repair action** | A refusal that can name a way out leads with the exact repair action, then the diagnostic. A command is runnable as printed; an interaction-only repair is named directly rather than fabricated as a command. |
| <a id="conduct-repair-first-refusal-exemptions"></a>**Repair-first refusal exemptions** | Two exemptions: a refusal with no repair action stays a bare diagnostic; a refusal about the invocation stays one contract statement. |
| <a id="conduct-gate-reports-are-a-third-shape"></a>**Gate reports are a third shape** | Gate reports are a third shape — the finding board is evidence, then a summary. |
| <a id="conduct-absence-of-evidence-is-not-evidence-of-absence"></a>**Absence of evidence is not evidence of absence** | Absence of evidence is not evidence of absence. |
| <a id="conduct-authoritative-degradation-is-loud"></a>**Authoritative degradation is loud** | Every degradation of authoritative observation, a durable fact, or an already-visible primary operation is loud. Silent failure is confined to two non-authoritative shapes that cannot fabricate or alter a fact: decoration beside an intact operation, and conservative pre-publication filtering that publishes no unconfirmed candidate. Neither may widen into fallback behavior. |
| <a id="conduct-prefer-the-good-property-never-block-on-it"></a>**Prefer the good property, never block on it** | Prefer the good property, never block on it: cross-review, launch advance, rewriting, and adjudication are each attempted and none is required. |
| <a id="conduct-one-visible-path"></a>**One visible path** | One visible path — no parallel compatibility behavior. Durable data advances through one ordered, unbroken, forward-only migration chain. |
| <a id="conduct-the-agent-is-a-user-with-its-own-surface"></a>**The agent is a user with its own surface** | The agent is a user with its own surface, and its tone is a stated requirement: capability, not restriction. |
| <a id="conduct-observation-initializes-nothing"></a>**Observation initializes nothing** | Observation initializes nothing — no repository, worktree, team state, claim, hook, or steering. |
| <a id="conduct-each-capability-tier-is-independently-usable"></a>**Each capability tier is independently usable** | Each capability tier is independently usable; a user may stop at any rung. |
| <a id="conduct-unknown-is-not-the-same-as-clear"></a>**Unknown is not the same as clear** | Unknown is not the same as clear. A check that could not run does not report what a check that ran and found nothing reports. |

## The properties most worth guarding

Ranked by how quietly they fail rather than by importance.

- **[Proof runs outside the candidate checkout](#distribution-proof-runs-outside-the-candidate-checkout)** — a proof that can see candidate source or ambient build output may validate the wrong executable while appearing green.
- **[Only lifecycle authority launches or renews occupants](lifecycle.md#lifecycle-only-the-lifecycle-authority-transitions-an-agent)** — rendering must not launch. A refresh becoming a launch storm is
   invisible until it is expensive.
- **[A card whose position did not change receives no style write](lifecycle.md#surface-a-card-whose-position-did-not-change-receives-no-style-write) / [A card's column and span latch between geometry replays](lifecycle.md#surface-a-card-s-column-and-span-are-decided-once)** — zero-write and latched columns. Both look correct in a
   screenshot and fail only under concurrency.
- **[Prior state is captured once, at first application](#distribution-prior-state-is-captured-once-at-first-application)** — prior state re-derived on a repeat install records the
   installer's own output as what was there before. Nothing is wrong until the
   uninstall, which then restores the wrong thing.
- **[Self-authored review is ranked last, never excluded](identity.md#work-self-authored-review-is-ranked-last-never-excluded)** — review preference implemented as a hard refusal starves the review
   phase whenever peers are busy.
- **[A resume cursor belongs to one exact stream](identity.md#identity-a-resume-cursor-belongs-to-one-exact-stream)** — accepting a cursor across an application generation or resident epoch can silently splice incompatible histories.
- **[A failed enumeration is not evidence of absence](lifecycle.md#topology-a-failed-enumeration-is-not-evidence-of-absence) / [Absence of evidence is not evidence of absence](#conduct-absence-of-evidence-is-not-evidence-of-absence)** — an empty enumeration read as absence destroys state on a
   transient error.
- **[A fact whose classification disagrees with the evidence backing it aborts the projection](session.md#session-a-fact-whose-classification-disagrees-with-the-evidence-backing-it-aborts-the-projection)** — a projection that degrades instead of aborting produces a record
   indistinguishable from a good one, and everything downstream inherits it.
- **[A deferred render does not commit its fingerprint](lifecycle.md#surface-a-deferred-render-does-not-commit-its-fingerprint)** — a deferred render that commits its fingerprint leaves a
   permanently blank surface with no error.
