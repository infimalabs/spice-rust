# Invariant register — Identity, steering, and work

[Invariant register](../invariants.md) · [Spice product model](../README.md)
## Identity and authority

| Label | Invariant |
| --- | --- |
| <a id="identity-a-task-s-born-stamp-is-its-only-stored-identity"></a>**A task's `born` stamp is its only stored identity** | The rendered handle derives a key from the project's rightmost segment and is never stored, so re-homing renames for free. Every surface resolves a handle by its stamp alone: a handle rendered under another project names the same task, the stem never grants or narrows visibility, and answers render the current handle. Stamp order is not creation chronology; journal sequence and durable queue origin are. |
| <a id="identity-an-occupant-address-is-its-birth-position"></a>**An occupant address is its birth position** | An occupant's only peer address is the journal position of the one `lane::started` fact recording its birth. It is derived from that fact, never minted or stored, so occupants started in the same instant keep distinct addresses. Proof reads exactly the addressed position and refuses rather than picking when no birth, a non-birth fact, or a repeated birth is found. |
| <a id="identity-an-address-executes-only-for-its-seated-occupant"></a>**An address executes only for its seated occupant** | An address resolves only while the residency seats that exact occupant on its birth lane; it never follows the lane to a successor. Resident restart adoption keeps the occupant and its address. Every wake, resume, import, and renewal seats a different occupant with its own address, and the predecessor's address expires. What an address already published is [bound to its lane](#steering-an-authored-msg-packet-admits-each-proved-recipient), not to the address. |
| <a id="identity-a-discovered-seat-address-resolves-to-the-occupant-shown"></a>**A discovered seat address resolves to the occupant shown** | The session briefing names the reader's own address and its teammates' addresses, and `spice lane list` shows each lane's address. Only a seated occupant whose birth is proved exactly once on that lane shows one, and it is the address the resolver executes; a vacant seat or unproved birth shows as unavailable, never as a guessed or predecessor address. |
| <a id="identity-a-human-principal-is-born-once-by-an-explicit-admission"></a>**A human principal is born once by an explicit admission** | `spice principal admit [--name NAME] [--email EMAIL] [--operator]` journals one `principal::admitted` fact naming a fresh principal identity, its profile (display name and email, copied from the repository's Git `user.name` and `user.email` unless either is given), and its roles; that identity and the admission's journal position never change. The admission's reply shows that principal's connection capability once; the journal keeps only its digest. `spice principal profile PRINCIPAL` and `spice principal role grant\|revoke PRINCIPAL ROLE` each write their own fact and move only that principal's head, and `spice principal list` reads every head in birth order with its [code](#identity-a-principal-code-is-its-birth-position) and the commit instant of the admission that bore it. `spice principal deauthorize PRINCIPAL` retires an issued capability for good, refusing `hello::capability-unknown` to its next presentation and ending that principal's open sessions. The app's global-menu **Principals** section reads the same list and sends these same commands; it shows an admission's capability once, as the opening link `ORIGIN/#CAPABILITY`, and stores it nowhere. Git is only the source an admission copies, never later display or routing authority. A resident's first start on a journal holding no principal admits the repository's human from its Git identity with the operator role; later starts admit nobody. These commands, the list included, are the operator's: a lane's or a principal's without the operator role refuses at admission, and a revocation or deauthorization that would leave no connectable principal (the earliest-born, or one holding a capability) holding the operator role refuses (`principal::last-operator`), at command time and again at commit. No principal carries an MSG selector or addressing route. |
| <a id="identity-a-principal-code-is-its-birth-position"></a>**A principal code is its birth position** | A principal's code is the journal position of the `principal::admitted` fact that bore it, spelled as the shortest vowel-free base-52 text, the spelling an occupant address uses. It is derived from that birth and never stored, so a profile edit, role change, or capability retirement never moves it and no two principals share one; a spelling resolves only against principal admissions, so a lane birth's position names no principal, and an empty, zero, leading-zero, out-of-alphabet, or overflowing spelling is no code. The connected directory carries each principal's code; `spice principal list` and the app's **Principals** section show it beside the canonical identity, which the management commands keep taking. A code identifies a person and nothing more: it grants no delivery, wake, inbox, role, capability, or command target, and since an occupant address names only a `lane::started` birth, an `MSG` or `ASK` spelling a code proves no occupant. A human is reached through a pointer-only `#KEY`, which names a direction and so implies the principal who sent it and that principal's code. |
| <a id="identity-operator-authority-is-a-principals-current-role"></a>**Operator authority is a principal's current role** | One predicate decides operator authority: does the acting principal's current role head hold the operator role? Operator-only commands and controls, connected-command admission, lane selection, steering wake, operator-direction recognition, and review coverage authority all ask it. Each human connection authenticates through its own principal's capability and authors as `human:<principal>`. The earliest-born principal's capability is minted per resident generation and served by local discovery. The app bootstrap serves that capability only to an opener presenting no principal capability after the listener's local, trusted-network, or authenticated access boundary admits it. An opener presenting a capability receives that exact capability only while it currently authenticates a born principal; an unknown, deauthorized, or lane capability refuses and never falls back to another principal. Nothing authors the historical `operator` actor; its recorded facts act as the earliest-born principal, and before any principal is born it holds the operator role. Any born principal holds connected authority whatever its roles; a lane is refused with the same authority refusals as before. The resident republishes the role heads and capability bindings after each admission, grant, revocation, or deauthorization, so the change governs that principal's next command on the same connection. Immutable history keeps naming the principal that wrote it: a revocation does not reattribute earlier facts. |
| <a id="identity-a-human-reads-under-its-principals-recorded-profile"></a>**A human reads under its principal's recorded profile** | Every surface naming an acting or authoring human reads that principal's recorded profile, never Git configuration. The resident derives display initials (the first letters of the recorded name's first two words), which are the human's short name, and the Gravatar from the profile. Connected-readable `principal::directory-read` carries every principal's display identity and [code](#identity-a-principal-code-is-its-birth-position) in birth order plus only the reader's current roles; the operator-only `principal::read` administrative list remains unavailable to a principal without that role. Display resolves an actor exactly as authority does: `human:<principal>` names that principal, and the historical `operator` actor names the earliest-born. The app reads the directory before subscribing, shows each connection its own principal's badge and inbox heading, and attributes each authored item, quote byline, and room line to its author's principal as an agent is attributed: by short name alone, never the full recorded name or code, and by code only when its profile yields no initials. CLI reads (task show history; room history, inbox, and results; quotes, including a lane's `spice://quote`) print a human whose principal is born the same way: its short name alone, or `CODE` alone when its profile yields no initials, where `CODE` is that principal's code; the historical `operator` actor prints the earliest-born principal's. The principal directory and profile surfaces, which exist to show and edit the full identity, keep the full recorded name. A lane, the resident, and a human naming no born principal print the bare actor; `--json` and exported ledgers carry the actor without its name or code, so applying a ledger still recognizes its annotations. |
| <a id="identity-retained-settings-retries-cross-to-principal-display"></a>**Retained settings retries cross to principal display** | A writable open crosses each retained `settings::set` reply from the retired single `operator` display to the current principal directory exactly once. When a bootstrap principal has been born, that retired display belongs to it; an older reply from before any principal birth carries an empty directory. Every directory entry a retained reply carries, crossed or already directory-shaped, gains the [code](#identity-a-principal-code-is-its-birth-position) of the principal it names, derived from that principal's admission; an entry naming no born principal refuses the open. The crossed receipt retains its command identity, committed position, fast-mode value, and exact-retry path, and current command execution has no release-specific branch. |
| <a id="identity-a-historical-operator-fact-reads-as-the-earliest-born-principal"></a>**A historical operator fact reads as the earliest-born principal** | Every read that names an author resolves a fact recorded under the historical `operator` actor to `human:<principal>` of the earliest-born principal, at read time over the principal heads: task history steps, notes, and closures; the ledger's step headings, which `spice doc` recognizes in the same spelling; task relations; the review graph and handout; room history; preparation withdrawals; a task's steering-origin author; quote authors; the app's steering directive contexts; and the lane recall chronology. Admitting, granting, or revoking later principals never moves it, and before any principal is born the actor reads as `operator`. Every other actor reads as itself. Resolution writes nothing: journal rows, digests, `spice journal verify`, and the fact stream keep the recorded actor. |
| <a id="identity-an-operator-item-reaches-the-principal-it-answers"></a>**An operator item reaches the principal it answers** | An open operator item reaches exactly one principal, read from the actor its authority already records: a lane's MSG or ASK naming `#KEY` reaches the principal that sent that direction, and an ANS returns to the principal that opened its ASK. Each resolves at read time as [a historical operator fact](#identity-a-historical-operator-fact-reads-as-the-earliest-born-principal) does, so a historical operator direction and a retained operator route naming no direction reach the earliest-born principal. `spice room inbox` reads as the local owner, the earliest-born principal, and pages and counts only the items reaching it; the app inbox shows an item once its conversation text read names this principal, or when that read fails. Addressing stays `#KEY` and `#TASK`: no person selector exists. |
| <a id="identity-every-fact-has-exactly-one-authority"></a>**Every fact has exactly one authority** | Every fact has exactly one authority. Consumers ask the owner rather than re-deriving from a cheaper nearby source. |
| <a id="identity-a-lane-command-stays-in-its-launch-repository"></a>**A lane command stays in its launch repository** | A lane's installed Git-common appliance identifies the repository authority that launched it. When that lane addresses a healthy resident from another repository, the client refuses before opening the lane surface or submitting a command, names the addressed authority, and directs the lane to the operator or an explicit document handoff; no identity or fact crosses repositories. An absent lane surface under the same Git-common authority remains a resident-publication handoff and keeps the ordinary bounded wait. Operator commands carry no lane repository identity and are unchanged. |
| <a id="identity-a-resume-cursor-belongs-to-one-exact-stream"></a>**A resume cursor belongs to one exact stream** | One authenticated stream carries an authoritative snapshot followed by accepted facts in monotone sequence within one resident epoch, applied exactly once in that order. A cursor resumes only its exact application generation and resident epoch; a mismatch or gap requires a fresh snapshot rather than a guessed merge. |
| <a id="identity-durable-facts-and-heads-remain-distinct-from-rebuildable-index-rows"></a>**Durable facts and heads remain distinct from rebuildable index rows** | A derived index may share the authority store and transaction, but rebuilding it never mutates immutable facts or heads. |
| <a id="identity-a-projection-family-must-declare-its-source"></a>**A projection family must declare its source** | A projection family declares its source, its progress record, its replay horizon, its refill, and what it can still say when the source no longer reaches back. |
| <a id="identity-room-relevance-is-shadow-evidence-before-automation"></a>**Room relevance is shadow evidence before automation** | A room relevance observation is an append-only Spice fact naming its anchor, a journal progress horizon, one to eight exact available or explicitly unavailable sources, a finite classification, and its explanation, exceptions, and uncertainty. Only a relevant contribution can declare progress; declines, duplicates, stale activity, missed opportunities, agreement, message count, silence, and elapsed time cannot. After each commit the resident observes every settled [question result](#identity-room-questions-separate-delivery-from-result-authority) asked in a task room exactly once, under the result's own identity, at the result head's position, citing the ASK's fact and the fact that answered or closed it: an answer is unknown with unknown progress, because the settlement it cites cannot tell evidence from agreement, a decline is declined, a timeout is a missed opportunity, and a cancellation is stale activity, none of them progress; a result asked outside any room is never observed. Only the operator assesses an observation, once, with `spice room assess OBSERVATION confirmed|false-positive|unknown TEXT`. `spice room relevance HANDLE` and `spice://task/HANDLE/room/relevance` page a room's observations whole in identity order with their sources and assessments, beside whole-room classification, progress, and assessment counts. Observing, assessing, and reading change no delivery, participant, result, task, claim, group, view, review, or authorization authority. |
| <a id="identity-a-completed-lane-owes-one-passive-design-request"></a>**A completed lane owes at most one passive Design request before allocation** | A claim alone creates no Design request. At the natural break after `task::done`, the resident compares the completed task's title, description, acceptance, and at most the first 4096 UTF-8 bytes of its validation with every current [passive](#work-working-group-standing-makes-a-design-active-or-passive) filed Design's title, description, and itemized open questions. Terms keep the Design-awareness normalization. The document-frequency corpus is the 256 most recently revised task statements, open or completed, with each title, description, and acceptance term present at most once per statement. A document term appearing $c$ times has weight $(1+\ln c)(1+\ln((N+1)/(df+1)))$; each sparse vector is L2-normalized, and its cosine with the completed work ranks the Design. Empty or non-overlapping documents never qualify. A score of 0.15 is the minimum; the highest score wins, ties breaking by durable Design identity. The ordinary resident pass records one Spice-owned `room::noticed` fact naming the exact Design statement, lane, occupant, completed task, claim, and up to six strongest weighted-overlap terms sorted by spelling. If that pass has not run, `spice task next` records the same deterministic choice before answering; either path reads an existing record without duplicating or rescoring it, and allocation never passes an owed request. Both paths admit the record through one guard that rereads only what can change the chosen request: the lane's occupant, the completed claim and task statement, newer lane work—any claim the lane won after the exact owing `task::done`, whether still active or already completed—the chosen Design's statement, openness, and passive standing, the lane's publication in its room, and any request recorded for that occupant's completion or Design after the choice was observed. Unrelated journal writes, including other lanes' claims, never refuse admission; a moved authority refuses `board::witness-moved` naming the stale cause, and `task next` chooses again a bounded number of times. One `spice room contribute HANDLE KIND TEXT` or `spice room leave HANDLE --clause TEXT` publishes the answer and discharges it; any earlier publication by that lane suppresses the Design across occupants. A concluded, deleted, active, or intake-phase Design releases an unanswered request. A statement edit does not: the request stays owed and names the Design's current title, statement revision, pitch—the first substantive description sentence—and an in-order bounded prefix of whole open questions, while its record keeps the statement and terms it matched. A recorded request keeps the asked lane listening to the Design's room, named as asked in room standing and catch-up beside its leave command, until that lane [leaves](#identity-a-lane-leaves-a-room-by-an-attributed-act); its leave is a room publication, so the lane is never asked about that Design again. The request adds no claim, workflow state, participation, steering, wake, or assignment. `spice room awareness HANDLE` (`spice://task/HANDLE/room/awareness`) continues to page every durable request with its exact statement and matched terms in journal order. |
| <a id="identity-a-designs-newest-return-is-told-once-to-its-active-holder"></a>**A Design's newest decision feedback is told once to its active holder** | A resolved decision is the operator's immutable, version-scoped verdict on every output, with optional per-output and overall comments; a historical return remains the version-scoped reason a candidate went back. Neither changes the candidate, statement, workflow, or claim, and only accepted outputs gain authorization. `spice room history HANDLE` shows each complete decision. The newest decision carrying a rejected output, output comment, or overall comment is the Design's next input until a holder has been told it. After each task, claim, residency, or decision-authority change, the resident finds each open grouped Design whose active claim an occupied lane holds and skips input already named by a `room::relayed` record. Otherwise the exact occupant's supervisor must confirm the private notice before the resident commits one Spice-owned `room::relayed` record naming the decision, lane, occupant, and exact claim win; missing doors, occupant mismatch, write failure, or claim movement record nothing. A claim race leaves the input owed to the new holder. A crash after confirmation but before recording may repeat the same purpose-coalesced informational notice but creates no duplicate authority. Unheld or passive Designs retain the input until a later active claim, and restart does not redeliver a completed record. The notice names the Design, candidate, decision, every verdict comment and overall comment, clipped to one datagram while history keeps it whole; it needs no acknowledgment and starts no work. |
| <a id="identity-an-operator-room-post-records-before-any-listener-catch-up"></a>**An operator room post records before any listener catch-up** | `spice room post HANDLE TEXT` resolves the current task handle to its born stamp and commits the complete text once under the command identity. Its reply reports every current listener's occupied, vacant, unavailable, or unknown topology state; a vacant listener waits for its next start, while a room with no current listener offers explicit Start/direction. The browser confirms every successful post by clearing its composer and raises no success notice. While no lane currently listens and no later lane contribution, message, answer, or leave proves receipt, the post's own card carries an accessible Unheard mark explaining that starting or directing a lane will have it read; the mark derives from room and listener authority, so reloads and other clients agree. Recording creates no participant acknowledgment, claim, wake, interruption, or lane participation. Only a room whose anchor is unresolved takes a new post: a completed, closed, or deleted anchor refuses with `room::anchor-settled` naming its standing and writes nothing, and the browser composer of a settled Design names that standing and offers no post. A settled room's history stays readable, and receipts and question results already open in it still settle. |
| <a id="identity-room-coordination-reuses-native-steering-and-possession"></a>**Room coordination reuses native steering and possession** | `spice room start` and `spice room resume` commit one scoped operator direction and an immutable room marker together. `ADDRESS` must name the current address of an occupied seat; a simulated, degraded, or other unoccupied seat refuses before submission with its address and disposition, so no direction or marker is written. The request names the unresolved criterion, bounded contribution, and stop condition; its recipient acquires the anchor or exact related preparation only through ordinary native task possession. When that recipient does not hold the anchor, the direction names `spice task capture HANDLE`, the exact native command that claims it without relying on allocator selection. The same transaction rechecks that the target lane holds no active claim other than this anchor; a concurrent win on another task refuses the coordination without publishing its direction or marker. Filing visibility continues to keep hidden controller anchors out of automatic allocation. `spice room put-aside` cancels only unanswered room coordination and, when the anchor is held, sends its holder a checkpoint/free direction without freeing the claim. The journal admits each marker only from the operator, directly after the same write's directions it names: a start's room coordination direction, a put-aside's cancellations of that room's coordination directions, exactly and in order, and its stop to the lane holding the active claim win it cites; commit, replay, and verification refuse every other shape. Coordination state reads from each room's latest markers alone, so it stays operable however much history the room holds; each coordination write is guarded on those markers, so at most one request is live. The stop projection remains visible for that exact claim win until ordinary completion, free, or lapse changes native possession; the reply asks the initiating browser to hide the room without storing browser state. |
| <a id="identity-an-operator-rule-bounds-automated-room-resumes"></a>**An operator rule bounds automated room resumes** | `spice room start` or `spice room resume` with `--auto-resume N` records on its room marker the operator's rule for up to N (1 through 8) automated resumes, to the same target and scope. While the room's latest marker carries that rule with budget left and nothing has put the room aside since, the resident resumes exactly when the target acknowledged the latest request, the anchor is pending and unclaimed, and a room publication by another party follows both that acknowledgment and the target's latest room publication. The resume runs the operator Resume's own staging, guards, and refusals and writes only its direction and marker; the marker names the authorizing marker, its step, and that publication. A pending request, silence, agreement with no new input, the target's own publications, a decline, a lapse, a cancellation, an unseated target, a settled or claimed anchor, and a spent budget each write nothing, so an unchanged cycle stops. A Start or Resume without the flag ends the rule, and `spice room status` shows the live rule's limit and steps spent. The journal admits an automated marker only as the next step of its room's latest rule, within its limit, after no put-aside, citing a publication in that room. |
| <a id="identity-a-room-reads-back-from-its-owning-sources"></a>**A room reads back from its owning sources** | `spice room history HANDLE` and `spice://task/HANDLE/room` resolve the handle to its born stamp, so any spelling a re-homed task has carried reads the same room under its current handle, and page its publications oldest first. Each row names its sender, its author occupant for an agent packet, and every directed route with that directive's current steering receipt; its text comes from the authority that owns it, the journal fact for an operator post or operator answer and the author's tape for a packet. A packet or operator answer that conversed also names its verb, its operator item receipt, and its question result at their current heads, each apart from the room record itself. Coordination publications occupy that same order and link the journal fact that owns their marker. A source that no longer yields the bytes renders unavailable with its reason, never as empty text. Publications are never cut: limits count whole publications, and a withheld page continues at the first withheld one, so following continuations visits each once. A malformed or unknown handle, or a cursor naming no publication of this room, refuses. Reading joins, acknowledges, delivers, and wakes nothing. |
| <a id="identity-room-questions-separate-delivery-from-result-authority"></a>**Room questions separate delivery from result authority** | Every selector freezes its own typed operator, lane, or task destination and optional task context at admission. A lane's operator route may instead name the key of an operator direction the operator sent that lane; admission, replay, and verification refuse one off the operator destination, unknown, addressed to another lane, or not from the operator, and the direction's text stays owned by its steering head. Each directed lane route of an MSG or ASK, and each answer returned to a lane requester, is exactly one native steering directive that the same write opened. A lane author's directive is a peer message told from its own record; an operator's directive is operator direction. Each goes to that lane in that route's context, and no room receipt head shadows it. Native steering owns that delivery's key, inbox, ACK and NAK, wake, lapse, recovery, dead letter, and renewal. An ASK's directive carries its public result handle as its key. Each operator-destination route and each answer returned to the operator opens one operator item: the publication stamp keys an MSG item, the result handle keys an ASK item, and the answer's stamp keys a return item. An item lapses only at or after its bounded expiry, and only the resident lapses it. An expired item has lapsed, never decided: only the operator recovers it, returning it to pending under the same key with a fresh bounded expiry. ACK settles only its delivery. NAK of a live ASK directive or ASK item also declines its pending result in the same fact, while a NAK after the result settled moves only the delivery. The result keeps immutable source, context, and deadline and one guarded pending-to-terminal head; no directive or item lapse, recovery, dead letter, or renewal changes, extends, or reopens it. ANS must match the stored respondent and context. In one write it settles the result, retires the still-live ASK directive or item (an ANS that leaves a live ASK directive unretired refuses), and opens the one nonrecursive return delivery to the stored requester. Content admission reserves bounded ACK/NAK capacity before accepting bytes, routes, or pending results, so saturation cannot partly settle an answer or strand a control return. The journal owns this authority as write-once publications with guarded operator item and result heads that replay rebuilds. A lane admits only its own transcript hunk, while the operator's text and clauses are owned by their own facts. Only the operator controls an item, only stored parties or the operator decline or cancel, and only the resident times out a result, at or after its deadline. Lateness is decided by the commit instant, so an ANS at or after the deadline refuses even before any timeout lands. Pending results are bounded per requester, while MSG, controls, and other requesters still admit. A fact that would move nothing, or whose first consequence refuses, writes nothing. |
| <a id="identity-room-conversation-controls-are-attributed-commands"></a>**Room conversation controls are attributed commands** | Only the operator runs `spice room ack|nak ITEM... --clause TEXT`, `spice room answer RESULT TEXT [--context HANDLE]`, `spice room recover ITEM`, and `spice room assess OBSERVATION VERDICT TEXT`; a lane settles its own deliveries with ACK/NAK prose. `spice room decline|cancel RESULT --clause TEXT` closes a pending [question result](#identity-room-questions-separate-delivery-from-result-authority) for its stored respondent or requester, and the operator closes for a stored lane party only with `--override`, which is refused when the operator is that party. Each control reads the heads it moves and guards their positions, so a raced control refuses `room::control-moved` and writes nothing; every refusal names the item or result state it observed and the command that repairs it. A multi-item control reports every item and question result it moved in input-item order. An operator answer is one write: the result settles, a still-pending ASK item settles, one operator direction returns `ANS RESULT: TEXT` to the requesting lane in the question's context, and the answer is published in that one room. The journal envelope's actor attributes every decision. `spice room inbox` and `spice://room/inbox` page every pending or lapsed operator item whole in key order, each with its publication text from its owning source and an ASK's result; `spice room result RESULT` and `spice://room/result/RESULT` read one result with its parties, deadline, state, its closer and override mark, and its answer's return receipt. These reads name recorded publications, participant receipts, and results apart, leave review coverage and execution authorization to `preparation show`, and change nothing. |
| <a id="identity-a-lane-leaves-a-room-by-an-attributed-act"></a>**A lane leaves a room by an attributed act** | Each room in a lane's catch-up names that lane's current listening reasons and `spice room leave HANDLE --clause TEXT`. Only a lane leaves, under its own actor, and the leave is recorded once as a `room::left` publication that room history and standing show with its clause; a repeated leave while one is in force records nothing. A leave in force ends listening derived from contribution, recent activity, and Design requests it postdates, so later room publications reach that lane in no catch-up. The lane's next contribution or a later lane-addressed packet restores listening only for publications in the new listening interval; it never replays publications skipped while the leave held. Native work on the anchor or related tasks, a live coordination or stop request, and an owed receipt or question result keep the lane listening, and the leave reply names each. Leaving never frees a claim, settles a delivery, or answers a question. |
| <a id="identity-a-lane-contributes-typed-problem-space-records-to-an-open-design"></a>**A lane contributes typed problem-space records to an open Design** | `spice room contribute HANDLE KIND TEXT [--source SOURCE...]` appends one immutable `room::contributed` publication to an open Design's room: one whose current heads have Design intent, pending status, no completion, and phase `design`. KIND is `reason-for`, `reason-against`, `evidence`, or `question`; the record names that kind, its lane author as actor, its time, its trimmed nonempty text of at most 4096 bytes, and zero to eight distinct exact sources, each spelled as its JSON `{"kind":"journal","fact":"SEQ"}`, `{"kind":"contribution","room":"DESIGN","publication":"PUBLICATION"}`, `{"kind":"transcript",...}` hunk, or `{"kind":"artifact","digest":"DIGEST"}`. The answer names the room, the publication, the kind, and `source`, the one canonical contribution spelling that cites it, which a candidate reference or a later contribution takes unchanged with no journal lookup or sequence encoding. Only a lane contributes, under its own actor. Admission witnesses the Design's statement and workflow heads and every source at one snapshot: a journal fact at or before that snapshot, a contribution published in its named room before it, a transcript hunk the tape still reads, or an artifact retained on that Design. A missing, hidden, changed, unreadable, or unsupported source refuses `room::contribution-source-unavailable` naming it, and a concluded Design refuses `room::contribution-design-concluded`. At commit the journal applies the same actor, bounds, and openness checks again, requires each cited journal fact to precede the contribution, each cited contribution to be published, and each transcript range to be accounted, and admits the fact only beside its matching successful command receipt, whose one source witness per citation records what admission resolved; verification refuses a contribution without that receipt. `spice room history HANDLE` and `spice://task/HANDLE/room` keep every publication in one chronological page, render a contribution with its kind, text, and each source available or typed unavailable, never fabricated, and group the page's contributions by kind in journal order; `--contributions` (`?contributions`) pages only contributions. Untyped posts and packets stay conversation and are never reinterpreted. Writing or reading a contribution changes no task statement or workflow, claim, working group, candidate, decision, or output authorization. |
| <a id="identity-design-maturity-is-bounded-advisory-evidence"></a>**Design maturity is bounded advisory evidence** | Every admitted completion-bound `room::noticed` request, every typed `room::contributed` record, and every `room::left` from a lane asked at a retained statement head incrementally update one Design's projection. A new contribution records the exact Design statement head its command witnessed; retained contributions from before that field existed remain in an explicit unrecorded-head bucket. A leave declines at the newest retained head that asked its lane; a leave from an unasked lane is no decline, and a lane that contributes at that head counts as contributed instead. Each retained head reads as asked lanes that contributed, declined, and have yet to answer; the browser readout and `spice room awareness` show those counts, and room history shows each decline's clause. The projection keeps at most four exact recent statement heads and 64 sorted lane identities per set, folds older heads into one fixed aggregate, and never scans room history while rendering. Fresh means no contribution. Steeped requires reason-for, reason-against, evidence, and three distinct contributing lanes; all other contributed states are steeping and name every missing dimension. Questions, requested reach, declines, and yield remain visible but cannot satisfy maturity. Crossing steeped supplies neutral operator attention only: it changes no standing, task, claim, group, candidate, decision, or authorization. |
| <a id="identity-the-resident-settles-room-deadlines-once"></a>**The resident settles room deadlines once** | While a resident is seated, it arms every pending [question result](#identity-room-questions-separate-delivery-from-result-authority) at its immutable deadline and every pending operator item at its expiry, from durable heads alone, so a restarted resident catches up on each that came due while it was down. At or after that instant it writes one `room::timedout` or `room::lapsed`, guarded on the exact head it armed from: an answer, decline, cancel, disposition, or recovery that commits first leaves it nothing to write. A timeout never touches an item, a lapse never moves a result, neither changes a deadline, and a recovered item is armed again at its fresh expiry. |
| <a id="identity-required-question-evidence-is-explicit-and-assessed"></a>**Required question evidence is explicit and assessed** | A task's statement names the [question results](#identity-room-questions-separate-delivery-from-result-authority) it requires, and only an explicit `spice task require HANDLE --evidence RESULT` adds one, naming a result asked in that task's own room. Ordinary edits preserve the set; only the operator replaces (`--replace RESULT --with RESULT`) or waives (`--waive RESULT`) one, and replay refuses a statement whose set differs from those changes. While any required result is pending, missing, declined, cancelled, or timed out, `spice task done` and a clean review refuse with `task::evidence-unsatisfied` naming each result's state; a task requiring none is unaffected. Answered means available for assessment, never accepted: an ANS completes no review, phase, decision, or authorization. A retained candidate's evidence must be asked in its controller's room, and execution authorization requires each result answered before the latest certifying coverage, so a material change re-retains a candidate that needs fresh assessment. |
| <a id="identity-working-groups-are-one-guarded-partition-of-designs"></a>**Working groups are one guarded partition of designs** | Every working group lives in one journal partition: groups in order, each holding one to six Design tasks in order and exactly one shared Passive, Explore, or Converge stance, no design in two groups, under one revision. The partition decides membership through the same grouping model as teams; `group::move` changes one membership, `group::arrange` faithfully restates group and Design order, `group::disband` removes one standing group and leaves its Designs ungrouped, and `group::stance` changes one standing group's stance. Each witnesses the revision it read, so a stale revision refuses with `group::partition-moved`; a missing group and unchanged stance refuse explicitly. A newly founded group starts in Passive; a retained partition written before stance authority reads its groups as Explore. TURBO is an independent per-group flag: stance changes preserve it and fast-mode changes preserve stance. A group ends when its last Design moves out or when the operator disbands it, is labelled from its first Design, and is never named. The board, room snapshot, native group read, and app catalog read this one partition. Except when a move, disband, or stance change [makes a Design passive](#work-working-group-standing-makes-a-design-active-or-passive), group changes touch no room head, task head, candidate, output, history, or execution authorization. |

| <a id="steering-an-item-is-durable-before-delivery-is-attempted"></a>**An item is durable before delivery is attempted** | An item is accepted as one journal transaction before any delivery reader is notified. Tool intent, filesystem paths, data URLs, DOM position, external URLs, and browser-derived diagrams grant no image quote authority. |

Reasoning, tool arguments, code, quotes, rendered source, negation, hypotheticals, and narration about a header retire nothing. |
| <a id="steering-a-turn-ending-header-retires-at-occupant-exit"></a>**A turn-ending header retires at occupant exit** | When an occupant exits, every live key its final transcript answers retires under the same recognition rules, with the transcript locus as evidence, and no successor wakes to cite it. | <a id="steering-reads-never-retire-an-item"></a>**Reads never retire an item** | A delivery read is not a disposition. `acked`, `declined` (a reasoned refusal, surfaced wherever acknowledgement is), and `canceled` are distinct terminal dispositions, and every live presentation stage admits each of them. |
| <a id="steering-the-agent-skill-is-an-installed-resource"></a>**The agent skill is an installed resource** | `spice://SKILL.md` returns the complete authoritative skill compiled into the executable image currently installed for the repository; line selectors bound the read, while queries and writes refuse. Reading acknowledges, retires, and redelivers nothing, however often omp reads or greps it. A live session's read of its own context refuses as the CLI does. |
| <a id="steering-only-a-serving-seat-is-taught-spice-urls"></a>**Only a seat that serves `spice://` proceeds from its bootstrap** | An omp occupant's first turn waits for omp's answer to the scheme registration and for the resident's start commit to seat that exact occupant, whichever comes later: the inbox kick sent after the commit releases it, so no command the turn runs reaches job admission before the occupant is seated, and a start that is never committed writes no first turn. When omp accepts, that turn and each briefing after compaction carry the scheme guide (the index, collections ending in member URLs, query flags, `continue:` URLs, line selectors, and that writes and authority acts stay `spice` commands), and the briefing names each quoted read a resource serves as its URL; a `spice://session/briefing` read does the same. If the resource read refuses, the binding bootstrap requires the occupant to stop and report the exact refusal rather than substitute a filesystem copy or another release. |
| <a id="steering-escalation-is-driven-by-silence-measured-from-publication"></a>**Escalation is driven by silence measured from publication** | Escalation is driven by silence measured from publication, on a stable lineage key, in three named stages before expiry. An operator resend keeps the key and re-presents the directive at the stage its silence has reached; it never advances presentation beyond that due stage. |
| <a id="steering-lapsed-items-remain-recoverable"></a>**Lapsed items remain recoverable** | A bounded lifetime moves unanswered intent to `lapsed`, which is never a decision. Recovery returns the same directive to live with its key, lineage, stage, and history intact. |
| <a id="steering-pending-inbox-terminal-wake-failure-deadletters-the-lane-s-pending-directives"></a>**PendingInbox terminal wake failure deadletters the lane's pending directives** | An automatic wake for pending steering that fails terminally to start an occupant moves every pending directive on that lane to `deadlettered`; other wake and delivery failures leave them live. Recovery restores a dead-lettered directive with its identity, lineage, and stage, but refuses a peer directive whose lane is gone. |
| <a id="steering-retired-direction-stays-readable-in-a-bounded-window"></a>**Retired direction stays readable in a bounded window** | An inbox read that asks for retirements also returns each visible lane's most recently retired directives, newest first, with their dispositions and retiring facts. A lane sees only its own. |
| <a id="steering-operator-direction-history-pages-whole-fanouts"></a>**Operator direction history pages whole fanouts** | An operator-only history read pages operator-authored directions as whole fanouts, newest first, each with every recipient's disposition. Filters keep or drop a fanout whole. Peer messages, replies, and resident-authored directives never appear. |
| <a id="steering-a-peer-message-is-attributed-to-its-sending-lane-and-carries-no-operator-authority"></a>**A peer message is attributed to its sending lane and carries no operator authority** | An authored [MSG](#steering-an-authored-msg-packet-admits-each-proved-recipient) is the only peer publication. Its delivery names the sending lane and the exact authoring occupant's address, or `unproved` when no single birth proves one, and frames the text as information that cannot override operator steering or task authority. It mints a key and retires, lapses, and quotes like any directive, but a pending peer message never wakes a lane; only operator steering does. |
| <a id="steering-an-answered-peer-message-replies-once-to-its-sender"></a>**An answered peer message replies once to its sender** | Retiring a live peer message journals, in the same write, one reply to the sending lane whose text is the answering header's clause. Each fanout recipient replies only for its own key. The reply addresses the sending lane rather than the occupant, so it is heard at that lane's next seat without waking it, and names the occupant whose session declared the answering transcript, or `unproved` when none did. A reply's own answer produces nothing further, and operator, resident, and taste direction never produce a reply. |
| <a id="steering-an-msg-packet-owns-exactly-its-body-hunk"></a>**An MSG, ASK, or ANS packet owns exactly its body hunk** | `MSG SELECTOR [SELECTOR ...]: BODY`, `ASK SELECTOR: BODY`, and `ANS RESULT[#TASK]: BODY` are read by the acknowledgment header grammar with the same exclusions. An explicit audience is an [occupant address](#identity-an-occupant-address-is-its-birth-position): `ADDRESS` reaches that occupant and `ADDRESS#TASK` also gives the route task context. A [principal code](#identity-a-principal-code-is-its-birth-position) is never an audience. A pointer-only `#KEY` reaches the operator about that authenticated direction, and so implies the principal who sent it; it is the only operator route, so everything a lane tells the operator traces back to something the operator said. A pointer-only `#TASK` records that task's room and reaches nobody. The grammar has no `operator` audience; that retained spelling is recognized only to refuse with `#KEY` guidance. An ASK names exactly one occupant or `#KEY`; a pointer-only `#TASK` names no respondent, so its ASK refuses. An ANS names exactly the public result handle of the question it answers, and its optional context only asserts that question's stored context. A packet retires nothing by its header. The body runs from the colon to the next placed ACK, NAK, MSG, ASK, or ANS header or the end of the prose. The first defect, including a malformed handle, a destination named twice, one room-only task named twice, or an ASK or ANS naming other than one selector, refuses the whole packet; a refused packet never guesses or drops a route or borrows a neighbor's body. |
| <a id="steering-an-authored-msg-packet-admits-each-proved-recipient"></a>**An authored MSG packet admits each proved recipient** | Visible assistant text is the only packet source: each complete streamed assistant text block, a turn's final message included, publishes the packets placed in it. Settled message prose, reasoning, tool arguments, and tool-call intents never publish, even when an intent repeats a packet header. Every recipient resolves against one residency. One guarded write delivers immediately to an address that view seats, or queues one unheard directive when the address proves a logical lane that view leaves vacant. The author's private notice distinguishes delivered, queued, and unavailable addresses; queued traffic wakes nobody. Once a successor is born, the predecessor address stays expired and its refusal names that successor's address even after the lane vacates; it never retargets. An unproved or removed address also receives and queues nothing. A packet that names the author's own address, or whose author has no proved birth, publishes nothing. A packet with no admitted route and no room records that refusal once and never later publishes. Message identity derives from the packet's transcript locus and exact addressed birth, so live, exit, and startup rereads publish it at most once. Startup reread gives every lane holding a declared session its own positive bounded tail-scan allowance, so recovery work on one lane cannot prevent any later lane from being scanned. Once admitted, the directive is bound to its logical lane: through vacancy, start, resume, and renewal it keeps its key, body, and expiry, and whichever occupant next sits there hears and answers it, until the lane [leaves the residency](#steering-pending-inbox-terminal-wake-failure-deadletters-the-lane-s-pending-directives). |
| <a id="steering-an-ask-or-ans-publishes-with-its-result-in-one-write"></a>**An ASK or ANS publishes with its result in one write** | An ASK, an ANS, and an MSG naming `#KEY` also journal one `room::conversed` record in the same write as their directives, freezing the operator route with its direction, each admitted lane route with its context, and each room-only route. An ASK opens one pending [question result](#identity-room-questions-separate-delivery-from-result-authority) whose public handle is a freshly minted steering key; its lane directive carries that key whether immediately delivered or queued for a proved vacant lane. Any other unavailable lane audience publishes nothing. An operator route opens one pending operator item and wakes no lane. Only the question's named respondent lane answers, while its result is pending and before its deadline, and an asserted context must equal the stored one; any other ANS publishes nothing and its author is told why. The answering write settles the result, returns the body to a lane requester's seated occupant in the stored context or opens an operator item for an operator requester, and acknowledges the respondent's still-live ASK directive without a reply of its own. The respondent's NAK of that live directive declines the result instead. A conversation record's identity is its exact transcript hunk, so live, exit, and startup rereads publish it at most once, and the author's private notice names the result it opened or answered. Retained journals may contain an older operator route naming only a task or nothing; replay preserves and presents it, but current packet admission cannot create another. |
| <a id="steering-an-msg-context-records-the-packet-in-its-room"></a>**An MSG context records the packet in its room** | Every `#TASK` context must name an existing task, or the whole packet refuses with no route published. In the same write as its directed messages, the packet records one `room::messaged` publication in each distinct room it names, naming its accounted transcript generation, event locus, the exact body byte range, its author occupant, and the directive each of its directed routes into that room opened, never the whole transcript. The journal admits that record only from the hunk's own lane and only when its directives are exactly the peer messages the same write opened into that room, in order, each sent from that lane by that author at that tape record. A directed `ADDRESS#TASK` message also freezes that room's birth stamp in its steering authority; the recipient's inbox row and `[PEER]` delivery header render the anchor's current task handle from that stamp. A missing anchor head refuses the read rather than dropping or guessing the context. That route also invites the addressed lane into the room: for the room's activity window after the newest `MSG` or `ASK` route that addressed it there, the lane listens to the room and receives its later publications through catch-up. An invitation makes no participant until the lane posts, and grants no claim, read permission, or wake. Recording is not receipt: the author hears one private recorded-in-room notice, no participant acknowledgment is implied, no operator item opens, and nothing wakes. A packet records once per source locus and room, so rereads record nothing, while equal text at another locus is another publication. |
| <a id="steering-a-room-catch-up-cursor-advances-only-by-a-landed-delivery"></a>**A room catch-up cursor advances only by a landed delivery** | Each logical lane has at most one room catch-up cursor, a journal position across all of its rooms. Only a `room::delivered` fact moves it, naming the exact hunk where the delivery landed in an accounted transcript of that same lane and an earlier indexed room publication strictly past the current cursor; replay rebuilds it, and a renewed occupant continues it. Before any delivery, a lane's catch-up starts at its horizon: the position of the one `room::horizon` fact the resident records the first time it reconciles the occupied lane without a cursor. The journal refuses a horizon from any other writer, a second horizon, or one for a lane with a cursor; it claims no delivery or participation, and retained publications at or before it are never owed. Each room's source read begins strictly after that position, so older retained publications are neither decoded nor charged to the source bound; the target lane's current activity is recovered independently from its latest indexed publication. The next catch-up walks publications after the cursor, or else the horizon, in journal order under one item and byte budget shared across rooms, delivers what the lane is owed through the room history's source-backed presentation and exact continuation, and passes over its own packets, directed packets it already received, and rooms it does not currently listen to. It is queued as a private aside for the occupant's next safe boundary, never interrupts an in-flight command and never wakes a lane. Once the exact aside appears in that occupant's transcript, the driver keeps its replacement slot coalesced across intervening commits and compaction until `room::delivered` durably recognizes it; only an unheard, interrupted, or failed delivery retries. A failed landed-evidence write retains that exact observed aside in occupant memory and retries only the write, never its delivery. A changed cursor releases the landed page and admits its next continuation, while renewal cannot transfer occupant-scoped delivery state. Commit reconciliation projects only rooms indexed by a publication transaction and only the lane named by cursor progress; unrelated commits schedule no catch-up projection, while startup and task or residency authority changes retain complete reconciliation. |
| <a id="steering-an-authored-packet-presents-as-an-outgoing-quote"></a>**An authored packet presents as an outgoing quote** | In its author's Chat card, a well-formed MSG, ASK, or ANS renders its body as an outgoing quote when every addressed occupant proves a birth. The quote leads with its card's relative age, even when the packet is the card's only text, and names the author and exact destinations without implying delivery; ASK carries a question badge, ANS carries an answer badge and the result it answers, and optional task context remains visible. The protocol header stays hidden. An unproved addressed occupant keeps the whole packet literal. Retained send annotations without a packet kind mean MSG. |
| <a id="steering-shell-instrumentation-is-one-shot-at-the-agent-s-own-command-boundary"></a>**Shell instrumentation is one-shot at the agent's own command boundary** | The wrapper receives each complete top-level agent command string exactly once and instruments nothing beneath it. The boundary is the process: a sourced script shares the immediate shell's functions, while an executed descendant gets the user's shell unmodified. Exactly-once is structural, distinct packaged environments rather than a counter, so there is no marker to read, forge, or lose. |
| <a id="steering-private-output-relays-end-with-the-immediate-child"></a>**Private output relays end with the immediate child** | When the immediate command process exits, the wrapper revokes inherited output relays and drains committed output, so a background descendant cannot hold it open. |

| <a id="work-claiming-is-atomic"></a>**Claiming is atomic** | The win, active head, owner, and lease commit together, and every repository-backed claim, whether by allocation, explicit capture, or steal, records the holder's measured opening Git boundary. `task capture` may adopt loose commits, dirty paths, or both into an execution task; dirty paths are sealed before the guarded claim and replayed only after its exact recovery-bearing claim commits. | <a id="work-lapse-writes-lapsed-before-readiness-is-derived"></a>**Lapse writes `lapsed` before readiness is derived** | Lapse and explicit free are typed journal transitions to `lapsed` and `freed`, so an intentional end is distinguishable from silence. Once written, the row is not peer-held and readiness is derived from every current predicate; before then the current claim stays authoritative. When the resident commits a lapse, the lane that held the claim receives one private notice at its current occupant, even one seated after the claim was won, naming the task and the expiry that passed; a vacant lane hears nothing, and the notice changes no claim, lease, or allocation state. A private assignment notice for a resident-minted claim waits for the occupant's next step boundary; when the claim ends first, by completion, free, or lapse, the resident tells the occupant that held it, and the notice is withdrawn undelivered, so an ended claim is never announced as newly assigned. |
| <a id="work-queue-age-has-one-durable-origin"></a>**Queue age has one durable origin** | Queue age has one durable origin, and unrelated row modifications do not reset it. |
| <a id="work-allocation-ranks-in-a-fixed-ladder"></a>**Allocation ranks in a fixed ladder** | Allocation ranks by phase-handoff preference, then last-resort class, then effective priority (a prerequisite inherits the highest priority it transitively unblocks), downstream weight, a narrow urgency band, peer spread, and locality. |

Explicit board and Design reads retain the complete planning state throughout. |
| <a id="work-phase-handoffs-use-durable-transition-evidence"></a>**Phase handoffs use durable transition evidence** | A phase transition's workflow head and causal completion fact open a short ownership window without inspecting a phase name. | <a id="work-self-authored-review-is-ranked-last-never-excluded"></a>**Self-authored review is ranked last, never excluded** | The actor's own review, the prior independent-phase owner's row, and rows the actor freed rank last for that actor and are never excluded, so a quiet board hands an actor its own review rather than stalling. |
| <a id="work-locality-is-the-final-tie-break-and-never-overrides-the-graph"></a>**Locality is the final tie-break and never overrides the graph** | Only rows within a narrow urgency band of their group's top compare by locality. Crowding never excludes a row. |
| <a id="work-every-task-names-one-typed-cause"></a>**Every task names one typed cause** | A task's provenance records why it exists, never who filed it, as exactly one of a steering directive (`ack:<key>`), a parent task (`task:<born-stamp>`), an applied document (`doc:<preview-digest>`), an operator Draft (`operator:draft`), or `parentless`, the retained cause that named neither a retained directive nor a retained task.
