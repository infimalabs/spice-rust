## Identity and authority

| Label | Invariant |
| --- | --- |
| <a id="identity-a-task-s-born-stamp-is-its-only-stored-identity"></a>**A task's `born` stamp is its only stored identity** | The rendered handle derives a key from the project's rightmost segment and is never stored, so re-homing renames for free. That abbreviation is presentation only: every other surface treats the complete project as one exact label. Every surface resolves a handle by its stamp alone: a handle rendered under another project names the same task, the key never grants or narrows visibility, and answers render the current handle. Stamp order is not creation chronology; journal sequence and durable queue origin are. |
| <a id="identity-an-occupant-address-is-its-birth-position"></a>**An occupant address is its birth position** | An occupant's only peer address is the journal position of the one `lane::started` fact recording its birth. It is derived from that fact, never minted or stored, so occupants started in the same instant keep distinct addresses. Proof reads exactly the addressed position and refuses rather than picking when no birth, a non-birth fact, or a repeated birth is found. |
| <a id="identity-an-address-executes-only-for-its-seated-occupant"></a>**An address executes only for its seated occupant** | An address resolves only while the residency seats that exact occupant on its birth lane; it never follows the lane to a successor. Resident restart adoption keeps the occupant and its address. Every wake, resume, import, and renewal seats a different occupant with its own address, and the predecessor's address expires. What an address already published is [bound to its lane](#steering-an-authored-msg-packet-admits-each-proved-recipient), not to the address. |
| <a id="identity-a-discovered-seat-address-resolves-to-the-occupant-shown"></a>**A discovered seat address resolves to the occupant shown** | The session briefing names the reader's own address and its teammates' addresses, and `spice lane list` shows each lane's address. With no lanes, its text form says none are seated and names `spice lane add [WORKTREE]` as the next step, while `--json` remains an empty list. Only a seated occupant whose birth is proved exactly once on that lane shows one, and it is the address the resolver executes; a vacant seat or unproved birth shows as unavailable, never as a guessed or predecessor address. |
| <a id="identity-a-human-principal-is-born-once-by-an-explicit-admission"></a>**A human principal is born once by an explicit admission** | `spice principal admit [--name NAME] [--email EMAIL] [--operator]` journals one `principal::admitted` fact naming a fresh principal identity, its profile (display name and email, copied from the repository's Git `user.name` and `user.email` unless either is given), and its roles; that identity and the admission's journal position never change. The admission's reply shows that principal's connection capability once; the journal keeps only its digest. `spice principal profile PRINCIPAL` and `spice principal role grant\|revoke PRINCIPAL ROLE` each write their own fact and move only that principal's head, and `spice principal list` reads every head in birth order with its [code](#identity-a-principal-code-is-its-birth-position) and the commit instant of the admission that bore it. `spice principal deauthorize PRINCIPAL` retires an issued capability for good, refusing `hello::capability-unknown` to its next presentation and ending that principal's open sessions. The app's global-menu **Principals** section reads the same list and sends these same commands; it shows an admission's capability once, as the opening link `ORIGIN/#CAPABILITY`, and stores it nowhere. Git is only the source an admission copies, never later display or routing authority. A resident's first start on a journal holding no principal admits the repository's human from its Git identity with the operator role; later starts admit nobody. These commands, the list included, are the operator's: a lane's or a principal's without the operator role refuses at admission, and a revocation or deauthorization that would leave no connectable principal (the earliest-born, or one holding a capability) holding the operator role refuses (`principal::last-operator`), at command time and again at commit. No principal carries an MSG selector or addressing route. |
| <a id="identity-a-principal-code-is-its-birth-position"></a>**A principal code is its birth position** | A principal's code is the journal position of the `principal::admitted` fact that bore it, spelled as the shortest vowel-free base-52 text, the spelling an occupant address uses. It is derived from that birth and never stored, so a profile edit, role change, or capability retirement never moves it and no two principals share one; a spelling resolves only against principal admissions, so a lane birth's position names no principal, and an empty, zero, leading-zero, out-of-alphabet, or overflowing spelling is no code. The connected directory carries each principal's code; `spice principal list` and the app's **Principals** section show it beside the canonical identity, which the management commands keep taking. A code identifies a person and nothing more: it grants no delivery, wake, inbox, role, capability, or command target, and since an occupant address names only a `lane::started` birth, an `MSG` spelling a code proves no occupant. A human is reached through a pointer-only `#KEY`, which names a direction and so implies the principal who sent it and that principal's code. |
| <a id="identity-operator-authority-is-a-principals-current-role"></a>**Operator authority is a principal's current role** | One predicate decides operator authority: does the acting principal's current role head hold the operator role? Operator-only commands and controls, connected-command admission, lane selection, steering wake, operator-direction recognition, and review coverage authority all ask it. Each human connection authenticates through its own principal's capability and authors as `human:<principal>`. The earliest-born principal's capability is minted per resident generation and served by local discovery. The app bootstrap serves that capability only to an opener presenting no principal capability after the listener's local, trusted-network, or authenticated access boundary admits it. An opener presenting a capability receives that exact capability only while it currently authenticates a born principal; an unknown, deauthorized, or lane capability refuses and never falls back to another principal. Nothing authors the historical `operator` actor; its recorded facts act as the earliest-born principal, and before any principal is born it holds the operator role. Any born principal holds connected authority whatever its roles; a lane is refused with the same authority refusals as before. The resident republishes the role heads and capability bindings after each admission, grant, revocation, or deauthorization, so the change governs that principal's next command on the same connection. Immutable history keeps naming the principal that wrote it: a revocation does not reattribute earlier facts. |
| <a id="identity-a-human-reads-under-its-principals-recorded-profile"></a>**A human reads under its principal's recorded profile** | Every surface naming an acting or authoring human reads that principal's recorded profile, never Git configuration. The resident derives display initials (the first letters of the recorded name's first two words), which are the human's short name, and the Gravatar from the profile. Connected-readable `principal::directory-read` carries every principal's display identity and [code](#identity-a-principal-code-is-its-birth-position) in birth order plus only the reader's current roles; the operator-only `principal::read` administrative list remains unavailable to a principal without that role. Display resolves an actor exactly as authority does: `human:<principal>` names that principal, and the historical `operator` actor names the earliest-born. The app reads the directory before subscribing, shows each connection its own principal's badge and inbox heading, and attributes each authored item, quote byline, and room line to its author's principal as an agent is attributed: by short name alone, never the full recorded name or code, and by code only when its profile yields no initials. CLI reads (task show history; room history, inbox, and results; quotes, including a lane's `spice://quote`) print a human whose principal is born the same way: its short name alone, or `CODE` alone when its profile yields no initials, where `CODE` is that principal's code; the historical `operator` actor prints the earliest-born principal's. The principal directory and profile surfaces, which exist to show and edit the full identity, keep the full recorded name. A lane, the resident, and a human naming no born principal print the bare actor; `--json` and exported ledgers carry the actor without its name or code, so applying a ledger still recognizes its annotations. |
| <a id="identity-retained-settings-retries-cross-to-principal-display"></a>**Retained settings retries cross to principal display** | A writable open crosses each retained `settings::set` reply from the retired single `operator` display to the current principal directory exactly once. When a bootstrap principal has been born, that retired display belongs to it; an older reply from before any principal birth carries an empty directory. Every directory entry a retained reply carries, crossed or already directory-shaped, gains the [code](#identity-a-principal-code-is-its-birth-position) of the principal it names, derived from that principal's admission; an entry naming no born principal refuses the open. The crossed receipt retains its command identity, committed position, fast-mode value, and exact-retry path, and current command execution has no release-specific branch. |
| <a id="identity-a-historical-operator-fact-reads-as-the-earliest-born-principal"></a>**A historical operator fact reads as the earliest-born principal** | Every read that names an author resolves a fact recorded under the historical `operator` actor to `human:<principal>` of the earliest-born principal, at read time over the principal heads: task history steps, notes, and closures; the ledger's step headings, which `spice doc` recognizes in the same spelling; task relations; the review graph and handout; room history; preparation withdrawals; a task's steering-origin author; quote authors; the app's steering directive contexts; and the lane recall chronology. Admitting, granting, or revoking later principals never moves it, and before any principal is born the actor reads as `operator`. Every other actor reads as itself. Resolution writes nothing: journal rows, digests, `spice journal verify`, and the fact stream keep the recorded actor. |
| <a id="identity-an-operator-item-reaches-the-principal-it-answers"></a>**An operator item reaches the principal it answers** | An open operator item reaches exactly one principal, read from the actor its authority already records: a lane's MSG naming `#KEY` reaches the principal that sent that direction. A historical operator direction and a retained operator route naming no direction reach the earliest-born principal. `spice room inbox` reads as the local owner and pages and counts only the items reaching it; the app shows an item once its source text names this principal, or when that read fails. Addressing stays `#KEY` and `#TASK`: no person selector exists. |
| <a id="identity-every-fact-has-exactly-one-authority"></a>**Every fact has exactly one authority** | Every fact has exactly one authority. Consumers ask the owner rather than re-deriving from a cheaper nearby source. |
| <a id="identity-a-lane-command-stays-in-its-launch-repository"></a>**A lane command stays in its launch repository** | A lane's installed Git-common appliance identifies the repository authority that launched it. When that lane addresses a healthy resident from another repository, the client refuses before opening the lane surface or submitting a command, names the addressed authority, and directs the lane to the operator or an explicit document handoff; no identity or fact crosses repositories. An absent lane surface under the same Git-common authority remains a resident-publication handoff and keeps the ordinary bounded wait. Operator commands carry no lane repository identity and are unchanged. |
| <a id="identity-one-kernel-owner-bounds-each-child-process-tree"></a>**One kernel owner bounds each child process tree** | Sill is the appliance process boundary. Unix launches use a new process group; Windows launches start suspended, enter a kill-on-close Job Object before their primary thread resumes, and settle only after both the root handle and the Job's active-process count are terminal. Cancellation and runtime expiry first request the platform's graceful group interruption, then force the whole owner after the declared grace and require kernel-observed reap within the declared bound. Exit, timeout, cancellation, capture failure, cleanup failure, and resource usage remain typed. A holder that keeps only a group's id, such as a resident ending a detached supervisor's occupant or a keeper sweeping its command, reaches the whole tree through sill's group signal: Unix signals the process group, while Windows opens the owner-only Job named for that group, interrupts with `CTRL_BREAK`, and forces by terminating the Job. An emptied or unknown group refuses as not found, and a stale name refuses a new launch rather than adopting it. Git and every other supervised caller use this boundary rather than owning PIDs, descendant probes, signals, or raw child pipes independently. |
| <a id="identity-a-resume-cursor-belongs-to-one-exact-stream"></a>**A resume cursor belongs to one exact stream** | One authenticated stream carries an authoritative snapshot followed by accepted facts in monotone sequence within one resident epoch, applied exactly once in that order. A cursor resumes only its exact application generation and resident epoch; a mismatch or gap requires a fresh snapshot rather than a guessed merge. |
| <a id="identity-durable-facts-and-heads-remain-distinct-from-rebuildable-index-rows"></a>**Durable facts and heads remain distinct from rebuildable index rows** | A derived index may share the authority store and transaction, but rebuilding it never mutates immutable facts or heads. |
| <a id="identity-a-projection-family-must-declare-its-source"></a>**A projection family must declare its source** | A projection family declares its source, its progress record, its replay horizon, its refill, and what it can still say when the source no longer reaches back. |
| <a id="identity-room-relevance-is-shadow-evidence-before-automation"></a>**Room relevance assessment is retained evidence, not automation** | `spice room assess OBSERVATION confirmed|false-positive|unknown TEXT` lets the operator classify an existing relevance observation exactly once. It creates no observation, delivery, participant, task, claim, group, review, or authorization authority. Retained observations remain readable for provenance; current conversation creates no result-backed observation. |
| <a id="identity-a-session-owes-one-open-design-request"></a>**A continuing session owes at most one open Design request before allocation** | A claim or lane name alone creates no Design request. Each admitted vendor session retains bounded successful-task and authored-conversation evidence across occupants that resume its exact lane, vendor, and session identity; a fresh identity starts empty. A successful completion, settled conversation message, eligible open Design filing or revision, completed profile warm, or session resume is one opportunity to evaluate the session profile. The resident fits the 256 most recently revised task statements, open or completed, as one document-frequency corpus and compares every retained task-statement, task-completion, whole-message, and passage view with each current filed open Design's title, description, and itemized open questions. Terms keep the Design-awareness normalization; each document contributes a term once to document frequency, a document term appearing $c$ times has weight $(1+\ln c)(1+\ln((N+1)/(df+1)))$, sparse vectors are L2-normalized, and each candidate qualifies at its effective stance's floor: 0.15 for passive, 0.10 for Explore, and 0.20 for Converge. The highest finite cosine wins and durable Design identity breaks ties; a lower floor never changes score ranking. One opportunity selects at most one Design and one session has at most one unanswered invitation. While one is owed, an opportunity still scores the session's current cards: it records a replacing invitation only when its best match strictly outranks the owed Design under the same corpus, cards, and stance floor, and that newer notice is then the one owed; an equal or lower match records nothing, and an owed Design below its floor bars nothing. Whether a Design is asked is decided on its whole statement; what it asks is every item still owed. Every stance may ask a lane about the Design's quiet and unopposed items whose charge series does not hold that lane; while an item is contested, Converge instead asks a lane already in that item's series to re-charge it at strength 2; a concurred item is never asked. The request lists them in statement order, led by the one whose text, read with the Design's problem sentence, scores best against any retained card view at or above the stance floor. The Spice-owned `room::noticed` fact names the exact Design statement, lane, occupant, continuing session, latest compaction boundary, opportunity, retained evidence card and conversation digest when applicable, task evidence's classification from the phase its claim held, one non-empty whitespace-collapsed excerpt of at most 240 characters of the card's authored validation or prose, at most six strongest weighted-overlap terms sorted by spelling, and each asked item's position, text identity, and state; admission refuses a concurred one; conversation-only opportunities fabricate no task, claim, or completion. Each Design item is asked at most once in one continuing vendor session, and a Design with no item the lane may be asked is asked as a whole at most once. Occupant changes, resident restarts, and durable compaction preserve that suppression and every contribution or leave that settled the request; compaction creates no invitation opportunity and serves only as a selection-to-recording race witness. When a new occupant resumes the session after an earlier occupant's room catch-up carried a still-owed request, the resident restates that same request once, recording it again with the new occupant and its session-resume opportunity, so that occupant's catch-up presents it; an answered or released request is never restated. Prior contribution in the continuing session keeps ordinary bounded room context available while optional activity prominence ages, instead of becoming a new recruitment request. A fresh vendor identity created by lane renewal starts another session without requiring lane deletion. An item request settles on the lane's own later contribution against any listed item or its `spice room leave HANDLE --clause TEXT`, and that session is not asked its other items again; another actor's post or an open question leaves it owed. A whole-Design request settles on any later room record by the lane. The same session may receive a later different Design or item; a declined, closed, deleted, or intake-phase Design does not retarget that opportunity, and editing a requested Design releases the stale invitation without immediately reopening it. Recording revalidates only the exact Design statement, filed open standing, target session, occupant declaration and compaction boundary, the lane's answer to any listed item since that session was declared, and immutable supporting task or transcript source; delivery revalidates the same authority except the compaction boundary, so an unanswered invitation survives a later compaction and every stance or group change. Unrelated journal writes do not move this authority. A replaced session, changed Design, or lost or replaced evidence source refuses or releases explicitly, and a compaction landing between selection and recording refuses the recording. Allocation never passes an owed request. The request quotes the current Design title, the Design's stored pitch (its problem sentence), its opportunity, its supporting work, and its matched terms; an item request then quotes each item verbatim with its position, state, and lanes, invites weighing any one or more via one contribute form or a leave, asks a contested item for a strength-2 re-charge without naming a sign, and offers the supporting task as `--cite`, or says matched conversation is not citable; a whole-Design request instead lists an in-order bounded prefix of whole open questions. `task next` and room catch-up render the same text. Task evidence says the lane implemented, diagnosed or planned, or reviewed the task as its claim's phase was an implementing, plan or Design, or review phase, and names the exact task, statement revision, and completion or claim with `spice task show TASK --history`; conversation evidence says the lane explained it in conversation and names the exact transcript source, member, byte, and length with the `spice session context` command that reads it after compaction; both quote the recorded excerpt. It adds no claim, workflow state, participation, steering, wake, or assignment. `spice room awareness HANDLE` (`spice://task/HANDLE/room/awareness`) pages every durable request in journal order. |
| <a id="identity-a-designs-newest-return-is-told-once-to-its-active-holder"></a>**A Design's newest decision feedback is told once to its active holder** | A resolved decision is the operator's immutable, version-scoped verdict on every output, with optional per-output and overall comments; a historical return remains the version-scoped reason a candidate went back. Neither changes the candidate, statement, workflow, or claim, and only accepted outputs gain authorization. `spice room history HANDLE` shows each complete decision. The newest decision carrying a rejected output, output comment, or overall comment is the Design's next input until a holder has been told it. After each task, claim, residency, or decision-authority change, the resident finds each open grouped Design whose active claim an occupied lane holds and skips input already named by a `room::relayed` record. Otherwise the exact occupant's supervisor must confirm the private notice before the resident commits one Spice-owned `room::relayed` record naming the decision, lane, occupant, and exact claim win; missing doors, occupant mismatch, write failure, or claim movement record nothing. A claim race leaves the input owed to the new holder. A crash after confirmation but before recording may repeat the same purpose-coalesced informational notice but creates no duplicate authority. Unheld or passive Designs retain the input until a later active claim, and restart does not redeliver a completed record. The notice names the Design, candidate, decision, every verdict comment and overall comment, clipped to one datagram while history keeps it whole; it needs no acknowledgment and starts no work. |
| <a id="identity-a-room-observation-records-before-any-listener-catch-up"></a>**A room observation records before any listener catch-up** | `spice room post HANDLE TEXT` publishes one observation, under its command identity, in any non-deleted task's room. Current listeners receive it through bounded catch-up; its author does not. The browser clears the composer only after success. While no lane listens and no later lane contribution, message, or leave proves receipt, the card carries an accessible Unheard mark. Recording creates no acknowledgment, claim, wake, interruption, participation, or listening authority. A deleted anchor refuses; settled-room history and receipts remain readable. |
| <a id="identity-a-design-nudge-is-the-one-push"></a>**A Design nudge is the one push** | `spice preparation nudge HANDLE`, or the Nudge control in the browser's Design menu, is the operator's only way to push an open Design at a lane: one guarded write readies the Design and messages the one free lane whose retained session best matches it, or reports that none could take it. No room command names a recipient, records a coordination marker, or sends a scoped direction. The recipient acquires the anchor only through ordinary native task possession, and filing visibility continues to keep hidden controller anchors out of automatic allocation. |
| <a id="identity-a-room-reads-back-from-its-owning-sources"></a>**A room reads back from its owning sources** | `spice room history HANDLE` and `spice://task/HANDLE/room` resolve the handle to its born stamp and page whole publications oldest first. Each row names its sender, agent author, directed routes, and current receipts. Operator-post text comes from its journal fact and packet text from the author's tape. Missing bytes render typed unavailable rather than empty; a withheld page continues at the first withheld publication. Reading joins, acknowledges, delivers, and wakes nothing. |
| <a id="identity-room-conversation-controls-are-attributed-commands"></a>**Room conversation controls are attributed commands** | Only the operator runs `spice room ack|nak ITEM... [--clause TEXT]`, `spice room reply ITEM TEXT`, `spice room recover ITEM`, and `spice room assess OBSERVATION VERDICT TEXT`; a lane settles its own deliveries with ACK/NAK prose. Each control reads and guards the heads it moves, so a race refuses without writing. Reply atomically settles a pending MSG item acked and returns `RE #KEY: TEXT` as operator direction to its author lane; an unambiguous source room also records that reply there. ACK and NAK settle silently: their optional clause is recorded and reaches no lane. `spice room inbox` and `spice://room/inbox` page pending and lapsed items with source-owned publication text. |
| <a id="identity-a-lane-leaves-a-room-by-an-attributed-act"></a>**A lane leaves a room by an attributed act** | `spice room leave HANDLE --clause TEXT` records one lane-attributed leave only to decline the Design request it owes there; owing none, it refuses `room::leave-nothing-owed` naming its native duties and writes nothing. A later request restores listening only from that new authority; skipped publications do not replay. Packets and contributions create no attention. Leaving never frees a claim or settles a delivery. |
| <a id="identity-a-lane-contributes-typed-problem-space-records-to-an-open-design"></a>**A lane contributes typed problem-space records to an open Design** | `spice room contribute HANDLE --charge=C --question N [--cite KEY...] TEXT` or `spice room contribute HANDLE --ask [--question N] TEXT` appends one immutable `room::contributed` publication to an open Design's room: one whose current heads have Design intent, pending status, no completion, and phase `design`. The record names a charge from -2 to +2 or a question; the one-based question item it weighs within the acceptance of the Design statement head the command witnessed, which a charge requires and admission refuses outside that head's list; its lane author as actor, its time, its trimmed nonempty text of at most 4096 bytes, and zero to eight distinct exact sources. A ±1 charge is an opinion; a 0 or ±2 charge cites at least one source. Each KEY resolves by form before submission: a task handle or stamp to `{"kind":"journal","fact":"SEQ"}` at that task's statement head, a publication stamp to `{"kind":"contribution","room":"DESIGN","publication":"PUBLICATION"}` in this room, a base-52 code to that journal fact, and a hex digest to `{"kind":"artifact","digest":"DIGEST"}`; an unknown handle or unreadable key refuses. A contribution retained from before charges carries the charge its label crossed to (reason-for +1, reason-against -1, evidence 0), names no item, and its crossed intent and answer still prove its receipt; the charge, item, and citation rules bind new writes only. The answer names the room, the publication, the kind, and `source`, the one canonical contribution spelling that cites it, which a candidate reference takes unchanged with no journal lookup or sequence encoding. Only a lane contributes, under its own actor. Admission witnesses the Design's statement and workflow heads and every source at one snapshot: a journal fact at or before that snapshot, a contribution published in its named room before it, a transcript hunk the tape still reads, or an artifact retained on that Design. A missing, hidden, changed, unreadable, or unsupported source refuses `room::contribution-source-unavailable` naming it, and a concluded Design refuses `room::contribution-design-concluded`. At commit the journal applies the same actor, bounds, and openness checks again, requires each cited journal fact to precede the contribution, each cited contribution to be published, and each transcript range to be accounted, and admits the fact only beside its matching successful command receipt, whose one source witness per citation records what admission resolved; verification refuses a contribution without that receipt. `spice room history HANDLE` and `spice://task/HANDLE/room` keep every publication in one chronological page, render a contribution with its charge or question, the item it weighs with that item's text while its witnessed statement is still the Design's current head and otherwise only the item number marked as of an earlier statement, its text, and each source available or typed unavailable, never fabricated, and group the page's contributions by kind in journal order; `--contributions` (`?contributions`) pages only contributions. Untyped posts and packets stay conversation and are never reinterpreted. Writing or reading a contribution changes no task statement or workflow, claim, working group, candidate, decision, or output authorization. |
| <a id="identity-design-maturity-is-bounded-advisory-evidence"></a>**Design maturity is bounded advisory evidence** | Every admitted session-profile `room::noticed` request, every typed `room::contributed` record, and every `room::left` from a lane asked at a retained statement head incrementally update one Design's projection. A new contribution records the exact Design statement head its command witnessed; retained contributions from before that field existed remain in an explicit unrecorded-head bucket. A leave declines at the newest retained head that asked its lane; a leave from an unasked lane is no decline, and a lane that contributes at that head counts as contributed instead. Each retained head reads as asked lanes that contributed, declined, and have yet to answer; the browser readout and `spice room awareness` show those counts, and room history shows each decline's clause. The projection keeps at most four exact recent statement heads, 64 sorted lane identities per set, and 32 question-item charge series, folds older heads into one fixed aggregate, and never scans room history while rendering. A charged contribution records its item's normalized text identity at admission, so a reorder keeps a series and a reword starts another; each series folds nonzero charges in journal order into fixed-size state. An item is quiet with no charge, unopposed while one sign has been seen, concurred when both signs have been seen and the current one-signed run holds two distinct lanes one of which earlier charged the opposite sign, or three distinct lanes, without burying the other side's last strength-2 charge unless the run holds one, and contested otherwise; a lane flipping its own sign sees both signs but cannot alone concur. Judged against the current statement's items, fresh means no contribution, steeped means every item has been charged, some item concurs, and none is contested, so a quiet item blocks and an unopposed one does not, and anything else is steeping and names the lowest contested item, else the lowest quiet one, else the lowest unopposed one, with the input it needs and how many items are still quiet. A removed item leaves the judgment. Zero charges, questions, retained Design-level charges, requested reach, declines, and yield remain visible but never move an item. Crossing steeped readies a Design's first pass and raises its invitation floor to Converge's; beyond that it supplies neutral operator attention only: it changes no standing, task, claim, group, candidate, decision, or authorization. |
| <a id="identity-the-resident-settles-room-deadlines-once"></a>**The resident lapses operator items once** | While seated, the resident arms every pending operator item from its durable expiry. At or after that instant it writes one guarded `room::lapsed`; a disposition or recovery that commits first leaves nothing to write. Recovery returns the same item to pending with a fresh expiry and arms it again. |
| <a id="identity-working-groups-are-one-guarded-partition-of-designs"></a>**Working groups are one guarded partition of designs** | Every working group lives in one journal partition: groups in order, each holding one to six Design tasks in order and exactly one shared Passive, Explore, or Converge stance, no design in two groups, under one revision. The partition decides membership through the same grouping model as teams; `group::move` changes one membership, `group::arrange` faithfully restates group and Design order, `group::disband` removes one standing group and leaves its Designs ungrouped, and `group::stance` changes one standing group's stance. Each witnesses the revision it read, so a stale revision refuses with `group::partition-moved`; a missing group and unchanged stance refuse explicitly. A newly founded group starts in Passive; a retained partition written before stance authority reads its groups as Explore. TURBO is an independent per-group flag: stance changes preserve it and fast-mode changes preserve stance. A group ends when its last Design moves out or when the operator disbands it, is labelled from its first Design, and is never named. The board, room snapshot, native group read, and app catalog read this one partition. Except when a move, disband, or stance change [makes a Design passive](#work-working-group-standing-makes-a-design-active-or-passive), group changes touch no room head, task head, candidate, output, history, or execution authorization. |

## Steering

| Label | Invariant |
| --- | --- |
| <a id="steering-an-item-is-durable-before-delivery-is-attempted"></a>**An item is durable before delivery is attempted** | An item is accepted as one journal transaction before any delivery reader is notified. Every submission is its own item: identical text sent twice persists as two items, never silently merged. Submit cost does not grow with backlog depth. |
| <a id="steering-the-journal-inbox-is-authoritative"></a>**The journal inbox is authoritative** | The journal owns directive lifecycle history and current pending heads. Supervisors and the `inbox` command read it directly; no filesystem rendering participates in delivery or recovery. |
| <a id="steering-a-wholly-withheld-packet-wakes-its-author-once"></a>**A wholly withheld packet wakes its author once** | When a valid authored `MSG` publishes to no one, one transaction records the source-locus `steer::withheld` judgment and one resident control directive carrying its refusal. That exact control has operator-equivalent wake authority, so the author is seated or interrupted to decide what to do and every reread journals nothing. A packet that reaches anyone reports missed addresses only as a non-waking private background notice; grammar-refused text does the same without a durable judgment. |
| <a id="steering-pending-steering-reaches-each-admitted-agent-boundary"></a>**Pending steering reaches each admitted agent boundary** | The command-driven supervisor reads the journal inbox when a seated occupant's first prompt is released and on each resident kick, writes each changed rendering once, and interrupts an in-flight command or tool call for unheard direction. The startup read appends every pending authenticated envelope, in publication order with its media metadata, after the fresh briefing or resumed-seat notice in that first prompt; it acknowledges nothing, records those items as already delivered, and adds no text for an empty inbox. Each read runs the installed `spice` executable rather than the supervisor's own build, so a supervisor that outlives a resident restart onto a newer release still reads that resident's inbox; a read that fails delivers nothing and is retried by the next kick. For OMP, later operator direction uses steering admission: all queued messages retain publication order, reach the model after the current tool result, and precede its next tool call. The interrupted command remains a job; delivery does not stop it. Peer messages remain non-authoritative asides: after their aside is registered they release only a blocking job wait, while running commands, short job operations, and other background notices remain non-preemptive. A reminder restates a key only when its telling changed by arriving or climbing a stage; another key arriving or retiring restates nothing. After a compaction it replays pending steering with one recovery instruction; an empty inbox writes nothing. A key the occupant's visible prose or tool intent answered is withdrawn from every queued reminder, replay, and briefing as those words are decoded, and nothing names it again until the journal climbs its stage, which says the answer retired nothing. Without a running supervisor, delivery waits for the next occupant's start. |
| <a id="steering-delivery-expands-authenticated-quote-links"></a>**Steering delivery expands authenticated quote links** | Delivery replaces each quote link with its durable source text, recursively to a fixed depth; an unavailable or too-deep source becomes a one-line stub naming its target. The journal keeps the linked original, and every reread reconstructs the same delivery. |
| <a id="steering-a-quote-link-reads-as-its-source"></a>**A quote link reads as its source** | `spice quote TARGET`, and an omp occupant's `read` of a `spice://quote/v1` target, answer from the same resolution delivery uses: the recorded author, then the exact source text, with no side effect. An unresolvable target refuses with its stub; a write to any `spice://` URI other than a [task text](#work-a-task-text-write-replaces-only-the-text-its-writer-read) refuses, naming the index. A withdrawn read is never answered. An omp that refuses the scheme's registration runs on without it. |
| <a id="steering-a-retained-image-quote-names-one-authenticated-image"></a>**A retained image quote names one authenticated image** | A quoteable steering attachment or transcript image is identified by its durable source, bounded source ordinal, and decoded-byte media digest, and displays its admitted media name. Resolution rereads that source, selects only the named ordinal, and revalidates the digest; failure yields an unavailable quote rather than another attachment or source prose. Tool intent, filesystem paths, data URLs, DOM position, external URLs, and browser-derived diagrams grant no image quote authority. |
| <a id="steering-acknowledgment-evidence-is-assistant-prose-on-the-lane-tape"></a>**Acknowledgment evidence is assistant prose on the lane tape** | An ACK or NAK header anywhere in authored assistant text, or in the intent a tool call declares, retires its key as the prose lands; no acknowledgment command exists. Its authority locus names the exact tape generation; retained steering evidence without that source refuses at writable open. Reasoning, tool arguments, code, quotes, rendered source, negation, hypotheticals, and narration about a header retire nothing. |
| <a id="steering-a-turn-ending-header-retires-at-occupant-exit"></a>**A turn-ending header retires at occupant exit** | When an occupant exits, every live key its final transcript answers retires under the same recognition rules, with the transcript locus as evidence, and no successor wakes to cite it. An unanswered key stays live for the lane's next occupant, including an MSG addressed to the occupant that left. |
| <a id="steering-reads-never-retire-an-item"></a>**Reads never retire an item** | A delivery read is not a disposition. `acked`, `declined` (a reasoned refusal, surfaced wherever acknowledgement is), and `canceled` are distinct terminal dispositions, and every live presentation stage admits each of them. |
| <a id="steering-the-agent-skill-is-an-installed-resource"></a>**The agent skill is an installed resource** | `spice://SKILL.md` returns the complete authoritative skill compiled into the executable image currently installed for the repository; line selectors bound the read, while queries and writes refuse. Agent prompts carry only a binding bootstrap card: a fresh session and every post-compaction turn must read the resource before work, while an ordinary resumed seat keeps its existing context. The prompt never carries the document body or installation path. Because the supervisor delegates resources through the executable image at the installed path, replacing that image replaces the skill and protocol owner together. |
| <a id="steering-a-lane-read-is-a-spice-resource"></a>**A lane read is a `spice://` resource** | An omp occupant's `read` of `spice://inbox`, `spice://lane`, and `spice://session/briefing`, `/turns`, `/sweep`, or `/context/SESSION` answers what `inbox`, `lane list`, and the matching `session` read render for that lane, under the occupant's own session identity and the grammar of [board reads](#work-a-board-read-is-a-spice-resource); a typed session page also names its continuation as a `spice://` URL. A retained supervisor reads briefings, resume notices, and resources through the executable image currently installed at its path, so a resident replacement also replaces the journal schema and protocol implementation those reads use; the resource image owns the seat's bounded graph continuation cache until another image replaces it. Reading acknowledges, retires, and redelivers nothing, however often omp reads or greps it. A live session's read of its own context refuses as the CLI does. |
| <a id="steering-only-a-serving-seat-is-taught-spice-urls"></a>**Only a seat that serves `spice://` proceeds from its bootstrap** | An omp occupant's first turn waits for omp's answer to the scheme registration and for the resident's start commit to seat that exact occupant, whichever comes later: the inbox kick sent after the commit releases it, so no command the turn runs reaches job admission before the occupant is seated, and a start that is never committed writes no first turn. When omp accepts, that turn and each briefing after compaction carry the scheme guide (the index, collections ending in member URLs, query flags, `continue:` URLs, line selectors, and that writes and authority acts stay `spice` commands), and the briefing names each quoted read a resource serves as its URL; a `spice://session/briefing` read does the same. If the resource read refuses, the binding bootstrap requires the occupant to stop and report the exact refusal rather than substitute a filesystem copy or another release. |
| <a id="steering-escalation-is-driven-by-silence-measured-from-publication"></a>**Escalation is driven by silence measured from publication** | Escalation is driven by silence measured from publication, on a stable lineage key, in three named stages before expiry. An operator resend keeps the key and re-presents the directive at the stage its silence has reached; it never advances presentation beyond that due stage. |
| <a id="steering-lapsed-items-remain-recoverable"></a>**Lapsed items remain recoverable** | A bounded lifetime moves unanswered intent to `lapsed`, which is never a decision. Recovery returns the same directive to live with its key, lineage, stage, and history intact. |
| <a id="steering-pending-inbox-terminal-wake-failure-deadletters-the-lane-s-pending-directives"></a>**PendingInbox terminal wake failure deadletters the lane's pending directives** | An automatic wake for pending steering that fails terminally to start an occupant moves every pending directive on that lane to `deadlettered`; other wake and delivery failures leave them live. A live peer message or reply whose lane leaves the residency dead-letters once with `steer::recipient-lane-removed`, so a lane that takes its place inherits nothing. Recovery restores a dead-lettered directive with its identity, lineage, and stage, but refuses a peer directive whose lane is gone. |
| <a id="steering-retired-direction-stays-readable-in-a-bounded-window"></a>**Retired direction stays readable in a bounded window** | An inbox read that asks for retirements also returns each visible lane's most recently retired directives, newest first, with their dispositions and retiring facts. A lane sees only its own. |
| <a id="steering-operator-direction-history-pages-whole-fanouts"></a>**Operator direction history pages whole fanouts** | An operator-only history read pages operator-authored directions as whole fanouts, newest first, each with every recipient's disposition. Filters keep or drop a fanout whole. Peer messages, replies, and resident-authored directives never appear. |
| <a id="steering-a-peer-message-is-attributed-to-its-sending-lane-and-carries-no-operator-authority"></a>**A peer message is attributed to its sending lane and carries no operator authority** | An authored [MSG](#steering-an-authored-msg-packet-admits-each-proved-recipient) is the only peer publication. Its delivery names the sending lane and the exact authoring occupant's address, or `unproved` when no single birth proves one, and frames the text as information that cannot override operator steering or task authority. It mints a key and retires, lapses, and quotes like any directive, but a pending peer message never wakes a lane; only operator steering does. |
| <a id="steering-an-answered-peer-message-replies-once-to-its-sender"></a>**An answered peer message replies once to its sender** | ACK means the recipient handled the message and its clause is the response; NAK means the recipient declined it and its clause is the reason. Neither header encodes yes, no, or preference: polarity is clause content, so a negative answer is an ACK whose clause says no. Retiring a live peer message journals, in the same write, one reply to the sending lane whose text is the answering header's nonempty remainder of that paragraph up to any earlier placed packet; a blank line returns following narration to the author. Each fanout recipient replies only for its own key. The reply addresses the sending lane rather than the occupant, so it is heard at that lane's next seat without waking it, and names the occupant whose session declared the answering transcript, or `unproved` when none did. A reply's own answer produces nothing further, and operator, resident, and taste direction never produce a reply. An answer longer than one paragraph, or one citing durable sources, goes as an MSG to the sender's address (or `MSG #KEY` for operator direction), followed by a one-paragraph ACK of the key; a Design question is a typed room contribution, not a packet. |
| <a id="steering-an-msg-packet-owns-exactly-its-body-hunk"></a>**An MSG packet owns exactly its body hunk** | `MSG SELECTOR [SELECTOR ...]: BODY` is the only authored packet, read by the acknowledgment header grammar with the same exclusions. An explicit audience is an [occupant address](#identity-an-occupant-address-is-its-birth-position): `ADDRESS` reaches that occupant and `ADDRESS#TASK` also gives the route task context. A [principal code](#identity-a-principal-code-is-its-birth-position) is never an audience. A pointer-only `#KEY` reaches the operator about that authenticated direction, and so implies the principal who sent it; it is the only operator route, so everything a lane tells the operator traces back to something the operator said. A pointer-only `#TASK` records that task's room and reaches nobody. The grammar has no `operator` audience; that retained spelling is recognized only to refuse with `#KEY` guidance. A packet retires nothing by its header. Its body ends at the first blank line or an earlier placed ACK, NAK, or MSG header; line wraps inside that paragraph remain body prose. A header in a Markdown list item or a fenced backtick or tilde block opens no packet. The retired `ASK` and `ANS` spellings are ordinary prose: they publish nothing, refuse nothing, and end no body. The first defect, including a malformed handle, a destination named twice, or one room-only task named twice, refuses the whole packet; a refused packet never guesses or drops a route or borrows a neighbor's body. |
| <a id="steering-an-authored-msg-packet-admits-each-proved-recipient"></a>**An authored MSG packet admits each proved recipient** | Visible assistant text is the only packet source: each complete streamed assistant text block, a turn's final message included, publishes the packets placed in it. Settled message prose, reasoning, tool arguments, and tool-call intents never publish, even when an intent repeats a packet header. Every recipient resolves against one residency. One guarded write delivers immediately to an address that view seats, or queues one unheard directive when the address proves a logical lane that view leaves vacant. An expired address whose birth lane that view seats with a later proved occupant delivers to that occupant: the message records the address it named, the receiver's `[PEER]` header names that earlier occupant and how long after its birth the receiver was born, and the author's private notice names the expired address, the address that heard it, and the same interval. The author's private notice distinguishes delivered, redirected, queued, and unavailable addresses; queued traffic wakes nobody. Once that successor departs too, the older address stays expired and its refusal names the successor's address; an expired address whose lane seats an unproved occupant, left the residency, or whose birth the journal no longer proves receives nothing. An unproved or removed address also receives and queues nothing. A packet that names the author's own lane under any of its codes, current or earlier, or whose author has no proved birth, publishes nothing, and a packet whose routes resolve onto one seat under two codes refuses whole as a repeated recipient, so a packet opens at most one directive per seat. A packet with no admitted route and no room records that refusal once and never later publishes. Message identity derives from the packet's transcript locus and exact addressed birth, so live, exit, and startup rereads publish it at most once. Startup reread gives every lane holding a declared session its own positive bounded tail-scan allowance, so recovery work on one lane cannot prevent any later lane from being scanned. Once admitted, the directive is bound to its logical lane: through vacancy, start, resume, and renewal it keeps its key, body, and expiry, and whichever occupant next sits there hears and answers it, until the lane [leaves the residency](#steering-pending-inbox-terminal-wake-failure-deadletters-the-lane-s-pending-directives). |
| <a id="steering-an-operator-msg-opens-its-item-in-one-write"></a>**An operator MSG opens its item in one write** | An MSG naming `#KEY` journals one `room::conversed` record in the same write as its directives, freezing the operator route with its direction, each admitted lane route with its context, and each room-only route. The operator route opens one pending operator item and wakes no lane. A conversation record's identity is its exact transcript hunk, so live, exit, and startup rereads publish it at most once. Retained pre-cutover operator routes with no direction remain readable; retired question-shaped receipts are historical authority and never re-enter current conversation projections. |
| <a id="steering-an-msg-context-records-the-packet-in-its-room"></a>**An MSG context records the packet in its room** | Every `#TASK` context must name an existing task, or the whole packet refuses with no route published. In the same write as its directed messages, the packet records one `room::messaged` publication in each distinct room it names, naming its accounted transcript generation, event locus, the exact body byte range, its author occupant, and the directive each of its directed routes into that room opened, never the whole transcript. The journal admits that record only from the hunk's own lane and only when its directives are exactly the peer messages the same write opened into that room, in order, each sent from that lane by that author at that tape record. A directed `ADDRESS#TASK` message also freezes that room's birth stamp in its steering authority; the recipient's inbox row and `[PEER]` delivery header render the anchor's current task handle from that stamp. A missing anchor head refuses the read rather than dropping or guessing the context. That route reaches the addressed lane by steering alone: it makes the lane no room listener or participant and grants no claim, read permission, or wake. Posting makes the author a participant but grants it no listening authority; any agent may post into any room without prior invitation, subscription, or participation. Recording is not receipt: the author hears one private recorded-in-room notice, no participant acknowledgment is implied, no operator item opens, and nothing wakes. A packet records once per source locus and room, so rereads record nothing, while equal text at another locus is another publication. |
| <a id="steering-a-room-catch-up-cursor-advances-only-by-a-landed-delivery"></a>**A room catch-up cursor advances only by a landed delivery** | Each logical lane has at most one room catch-up cursor, a journal position across all of its rooms. Only a `room::delivered` fact moves it, naming the exact hunk where the delivery landed in an accounted transcript of that same lane and an earlier indexed room publication or [Design request](#identity-a-completed-lane-owes-one-passive-design-request) strictly past the current cursor; replay rebuilds it, and a renewed occupant continues it. Current attention supplies the per-room lower bound before and after that cursor: native work starts at the current claim's durable win or later task-association authority, a live stop duty starts at its control fact, and an owed Design request starts at its request fact. Each room's source read begins strictly after the later of that authority and the landed cursor, so publications before the current authority and between ended and later duties are neither decoded nor delivered. Renewal and occupant carry preserve one claim's start; completion, free, lapse, relation removal, or control settlement removes its reason; a later authority starts fresh. Retained `room::horizon` facts remain replayable journal history but are not current catch-up authority. The next catch-up walks admitted publications together with the occupant's owed Design request in journal order under one item and byte budget shared across rooms, delivers what the lane is owed through the room history's source-backed presentation and exact continuation, and passes over its own packets, directed packets it already received, and rooms it does not currently listen to. It is queued as a private aside for the occupant's next safe boundary, never interrupts an in-flight command and never wakes a lane. Once the exact aside appears in that occupant's transcript, the driver keeps its replacement slot coalesced across intervening commits and compaction until `room::delivered` durably recognizes it; only an unheard, interrupted, or failed delivery retries. A failed landed-evidence write retains that exact observed aside in occupant memory and retries only the write, never its delivery. A changed cursor releases the landed page and admits its next continuation, while renewal cannot transfer occupant-scoped delivery state. Commit reconciliation projects only rooms indexed by a publication transaction and only the lane named by cursor progress; unrelated commits schedule no catch-up projection, while startup and task or residency authority changes retain complete reconciliation. |
| <a id="steering-an-authored-packet-presents-as-an-outgoing-quote"></a>**An authored packet presents as an outgoing quote** | In its author's Chat card, a well-formed MSG renders its body as an outgoing quote when every addressed occupant proves a birth. The quote leads with its card's relative age, even when the packet is the card's only text, and names the author and exact destinations without implying delivery: an operator-direction route names the principal it reaches, falling back to its `#KEY` concern while that principal read is unavailable, never the invalid context-free `operator` spelling. Optional task context remains visible. The protocol header stays hidden. An unproved addressed occupant keeps the whole packet literal. |
| <a id="steering-shell-instrumentation-is-one-shot-at-the-agent-s-own-command-boundary"></a>**Shell instrumentation is one-shot at the agent's own command boundary** | The wrapper receives each complete top-level agent command string exactly once and instruments nothing beneath it. The boundary is the process: a sourced script shares the immediate shell's functions, while an executed descendant gets the user's shell unmodified. Exactly-once is structural, distinct packaged environments rather than a counter, so there is no marker to read, forge, or lose. |
| <a id="steering-private-output-relays-end-with-the-immediate-child"></a>**Private output relays end with the immediate child** | When the immediate command process exits, the wrapper revokes inherited output relays and drains committed output, so a background descendant cannot hold it open. |

## Work, claims, and allocation

| Label | Invariant |
| --- | --- |
| <a id="work-at-most-one-active-claim-per-actor"></a>**At most one active claim per actor** | At most one active claim per actor. `task next` for an actor already holding one reports that task and its next action without entering allocation. |
| <a id="work-claiming-is-atomic"></a>**Claiming is atomic** | The win, active head, owner, and lease commit together, and every repository-backed claim, whether by allocation, explicit capture, or steal, records the holder's measured opening Git boundary. `task capture` may adopt loose commits, dirty paths, or both into an execution task; dirty paths are sealed before the guarded claim and replayed only after its exact recovery-bearing claim commits. A steal never reuses the displaced holder's opening. Plan completion therefore admits an untouched claim and refuses dirty work or a moved `HEAD`. |
| <a id="work-claim-bound-work-has-two-visible-placements"></a>**Claim-bound work has two visible placements** | A team's task rail follows the member lane bound to each active claim, including a Design or directly Design-controlled Plan whose accountable planning owner remains that Design. A working group's rail presents each distinct member lane actively claiming work associated with one of its Design anchors, labelled and accented from current lane topology, rather than repeating task handles. Association covers the Design task itself, a task that currently depends on it, and selected work whose persistent preparation controller is that Design. Group TURBO and browser speech cover exactly those same lanes. These rails do not change overview partitioning: Design-owned work remains in Planning and out of All open and project scopes. |
| <a id="work-an-explicit-steal-replaces-exactly-the-named-claim"></a>**An explicit steal replaces exactly the named claim** | An explicit steal is immediate and replaces exactly the named current claim or refuses. A steal of a task no actor holds claims it as a capture would and answers `nothing_stolen`, so the caller learns nobody was displaced. The displaced claimant learns through a typed ownership refusal on its next claim operation, not a fabricated steering item. |
| <a id="work-a-live-lease-rolls-with-its-occupant"></a>**A live lease rolls with its occupant** | The resident rolls a claim's lease while its lane seats the occupant holding it, so a lapse follows the occupant leaving rather than a fixed lease running out under long work. A lane that occupant left vacant keeps rolling only until its unfinished deadline-bounded jobs end, so the successor they wake finds the claim live. A successor seated while the claim is live receives it by carry, preserving lineage and elapsed work, not by a fresh win. No lease rolls while no resident runs, so downtime never counts against a holder: resident startup restores each lane's active claim to its holder with at least one rolling window from that startup, even one whose lease ran out while the resident was down, and a holder that does not return lapses once that window passes unrenewed. An occupant whose supervisor still runs a release older than the journal's schema has its commands refused with that cause and the direction to end its turn; the lease keeps rolling meanwhile, and the lane's next turn starts on the installed release holding the same claim. |
| <a id="work-lapse-writes-lapsed-before-readiness-is-derived"></a>**Lapse writes `lapsed` before readiness is derived** | Lapse and explicit free are typed journal transitions to `lapsed` and `freed`, so an intentional end is distinguishable from silence. Once written, the row is not peer-held and readiness is derived from every current predicate; before then the current claim stays authoritative. When the resident commits a lapse, the lane that held the claim receives one private notice at its current occupant, even one seated after the claim was won, naming the task and the expiry that passed; a vacant lane hears nothing, and the notice changes no claim, lease, or allocation state. A private assignment notice for a resident-minted claim waits for the occupant's next step boundary; when the claim ends first, by completion, free, or lapse, the resident tells the occupant that held it, and the notice is withdrawn undelivered, so an ended claim is never announced as newly assigned. |
| <a id="work-queue-age-has-one-durable-origin"></a>**Queue age has one durable origin** | Queue age has one durable origin, and unrelated row modifications do not reset it. |
| <a id="work-allocation-ranks-in-a-fixed-ladder"></a>**Allocation ranks in a fixed ladder** | Allocation ranks by phase-handoff preference, then last-resort class, then effective priority (a prerequisite inherits the highest priority it transitively unblocks), downstream weight, overdue rows (waited past the `[board.next] horizon` since their queue-origin fact, oldest first), the running lane's session match (scores below the lowest Design invitation floor count as zero), and then the oldest queue origin and the handle. |
| <a id="work-agent-allocation-summaries-stop-at-the-design-authorization-boundary"></a>**Agent allocation summaries stop at the Design authorization boundary** | Automatic agent-facing board summaries omit Design roots and outputs that still depend on a Design. Exact execution authorization removes only each accepted output's Design dependency, moving it into the ordinary execution summary. Rejected and unproposed outputs retain the edge. Work a selected Plan later prepares enters only when its ordinary dependency on that Plan is satisfied. Explicit board and Design reads retain the complete planning state throughout. |
| <a id="work-phase-handoffs-use-durable-transition-evidence"></a>**Phase handoffs use durable transition evidence** | A completion that enters a phase other than review with another declared phase after it, without publishing repository history or parking commits, carries its claim: the same write that records the completion and the phase advance mints an active claim on the new phase for the completing lane and occupant, the done answer names that claim and the phase's deliverable, and no allocation or capture by another lane can intervene. A review phase is never carried, because review goes to a peer before its author. A completion that published repository history frees the claim, and its workflow head and causal completion fact open a short ownership window, without inspecting a phase name, that reserves the next phase for peers and admits the prior claimant only as a last resort. A completion into the final declared phase, or one that parks commits, frees the claim without a reservation. |
| <a id="work-self-authored-review-is-ranked-last-never-excluded"></a>**Self-authored review is ranked last, never excluded** | The actor's own review, the prior independent-phase owner's row, and rows the actor freed rank last for that actor and are never excluded, so a quiet board hands an actor its own review rather than stalling. |
| <a id="work-queue-age-is-the-final-tie-break-and-never-overrides-the-graph"></a>**Queue age is the final tie-break and never overrides the graph** | Only rows tied on the session match compare by age: the oldest queue origin wins, then the handle. No claim cell, peer claim, or claim history reorders them, so no age gap is skipped. Crowding never excludes a row, and a strongly matched row may join a peer's project and phase; the claim's overlap warning names it. |
| <a id="work-every-task-names-one-typed-cause"></a>**Every task names one typed cause** | A task's provenance records why it exists, never who filed it, as exactly one of a steering directive (`ack:<key>`), a parent task (`task:<born-stamp>`), an applied document (`doc:<preview-digest>`), an operator Draft (`operator:draft`), or `parentless`, the retained cause that named neither a retained directive nor a retained task. Authored `--origin` admits only `ack:<key>` and `task:<stamp-or-handle>`; any other spelling refuses, naming the canonical form when one exists. No creation path mints `parentless`, and readers use the cause, never its spelling. |
| <a id="work-a-task-flow-is-nonempty-unique-and-self-containing"></a>**A task flow is nonempty, unique, and self-containing** | A flow is a nonempty list of unique lowercase phase names containing the current phase. The board has no global phase vocabulary. |
| <a id="work-a-review-that-changes-nothing-still-advances-the-phase"></a>**A review that changes nothing still advances the phase** | A review that changes nothing still advances the phase, so absence of a commit is not absence of review. Review feedback reaches the phase author under the bare task key. |
| <a id="work-review-feedback-follows-the-author-vendor-session"></a>**Review feedback follows the author's vendor session** | A finding is delivered once to the author lane's seat that continues the vendor session which completed the judged phase: the same occupant, or a later occupant that resumed that session across a seat boundary or compaction. While the author lane is between seats the resident holds the finding and judges it again on each reconcile until a seat appears or the finding outlives its directive lifetime. A renewal that seats another session drops it, because that occupant acclimates from the briefing instead. A finding reviewed from the author's own session is never delivered. |
| <a id="work-a-named-flow-outranks-the-review-omission-default"></a>**A named flow outranks the review-omission default** | A task created without a named flow omits its review phase when every reviewed parent or dependency is pending in review, because that parent's re-review is the closing check. A flow the author names is created exactly as written. |
| <a id="work-dependency-blocking-is-an-eligibility-predicate-not-a-task-transition"></a>**Dependency blocking is an eligibility predicate, not a task transition** | A pending task with an unsettled dependency stays pending but ineligible. A prerequisite settles when completed or deleted, without writing the dependent's workflow. Dependency edits are guarded publications that refuse an absent edge, a cycle, or a removal that leaves a plan relying on child acceptance without a pending accepted child. |
| <a id="work-gate-waits-have-one-resident-owned-classification"></a>**Gate waits have one resident-owned classification** | The resident partitions each open closed allocation gate into exactly one presentation fact: human-actionable blocked work, neutral workflow waiting, or an open Design's [pass cycle](#work-a-design-schedules-each-pass-from-input-after-its-last-pass) state. Normal Plan control and every dependency sequence that still reaches active, ready, review, awaiting-decision, or neutral work are neutral waiting. An open Design, active or passive and in any pass cycle, is a neutral wait for its outputs and every task behind them only while its own unresolved dependency path remains agent-advancing: only the Design itself, while Awaiting decision, needs the operator, so an undecided proposal's outputs, returned or rejected outputs, and work behind a Design still gathering input wait neutrally and never add to blocked or operator-attention counts. A Design cycle never hides a true wall beneath it. Missing authority, missing prerequisites, cycles, and walls at closed, parked, deferred, or environment-held work are blocked through the Design and every dependent because no agent can advance them without a human act.
