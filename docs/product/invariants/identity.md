## Identity and authority

| Label | Invariant |
| --- | --- |
| <a id="identity-a-task-s-born-stamp-is-its-only-stored-identity"></a>**A task's `born` stamp is its only stored identity** | A task's `born` stamp is its only stored identity; the rendered handle derives a key from the project's rightmost segment and is never stored, so re-homing renames for free. Every surface that accepts a handle resolves it by its stamp alone: a handle rendered under an earlier or different project names the same task, the stem never grants or narrows visibility, and answers render the current handle. |
| <a id="identity-the-stored-stamp-orders-represented-instants-without-parsing"></a>**The current stored stamp orders represented instants without parsing** | Within one codec generation, ordinary string comparison orders the microseconds represented by current stamps. Collision rewinds and retained widths make stamp order insufficient for actual creation chronology; journal sequence and durable queue origin remain that authority. |
| <a id="identity-task-collisions-rewind-without-inventing-future-births"></a>**Task collisions rewind without inventing future births** | A current task minting collision probes earlier microseconds one at a time, never a future instant or entropy, and refuses before crossing Unix zero. Batched allocation returns the gathered candidates in ascending stamp order so authored items keep their order; independent colliding mints rely on journal sequence and durable queue origin for chronology. |
| <a id="identity-an-occupant-address-is-its-birth-position"></a>**An occupant address is its birth position** | An occupant's only executable peer address is the nonzero position, within the current appliance journal, of the one `lane::started` fact recording its birth, spelled as shortest-form vowel-free base 52 over the task-stamp alphabet with no width ceiling short of `u64::MAX`. It is derived from that fact, never minted or stored separately, and distinct from task stamps and moment-coded keys; lane and occupant UUIDs remain the internal authority and provenance. Empty text, a character outside the alphabet, zero, a leading zero digit, and a value beyond `u64::MAX` are each refused. Distinct births occupy distinct positions, so occupants started in the same instant keep distinct addresses. |
| <a id="identity-an-address-proves-one-exact-birth"></a>**An address proves one exact birth** | Proof reads the exact addressed position: no fact there refuses `address::unrecorded`, a fact other than `lane::started` refuses `address::not-birth`, and an occupant named by more than one `lane::started` fact refuses `address::repeated-birth` rather than picking one. A proved birth stays readable as history whether or not its occupant is still seated. An occupant's own address derives only from that birth on its lane, never from a later compaction or renewal context anchor; a seat with no retained birth there, including an occupant seated only by a historical `lane::renewed` fact, refuses `address::missing-birth` and receives no substitute address. |
| <a id="identity-an-address-executes-only-for-its-seated-occupant"></a>**An address executes only for its seated occupant** | Executable resolution additionally requires the current residency head to seat that exact occupant on its birth lane; otherwise it refuses `address::expired` and never follows the lane to a successor. Resident restart adoption keeps the occupant and records no new birth, so its address survives. Every wake, vendor-session resume, proposal, import, and renewal successor is a new occupant with its own birth and address, and its predecessor's address expires. |
| <a id="identity-a-discovered-seat-address-resolves-to-the-occupant-shown"></a>**A discovered seat address resolves to the occupant shown** | Agents discover addresses where they already read their lane: the session briefing names the reader's own address in its header and lists every other lane of its team under Peers, and `spice lane list` adds each lane's `address`, typed in `--json` as `seated` with occupant and address, `vacant`, or `unproved` with its refusal reason. Only a seated occupant whose birth the journal proves exactly once on that lane shows an address, and it is the one the resolver executes; a vacant seat or an unproved birth is shown as unavailable, never with a guessed or predecessor address. A fresh launch's first briefing is composed before its occupant's birth is recorded, so its header says the reader's own address is recorded once its session starts, never the vacant or predecessor seat it read; any later briefing names the proved address. The resident projects from its birth index and the daemonless briefing from the journal's `lane::started` facts, by the same rule. Lane UUIDs, task ownership and operator lane management keep their lane identities beside it. |
| <a id="identity-every-fact-has-exactly-one-authority"></a>**Every fact has exactly one authority** | Every fact has exactly one authority. Consumers ask the owner rather than re-deriving from a cheaper nearby source. |
| <a id="identity-the-authenticated-stream-carries-generation-epoch-and-sequence"></a>**The authenticated stream carries generation, epoch, and sequence** | Application generation binds one admitted build, resident epoch binds one resident lifetime, and a monotone sequence totally orders frames within that epoch. |
| <a id="identity-a-resume-cursor-belongs-to-one-exact-stream"></a>**A resume cursor belongs to one exact stream** | A cursor resumes only its exact application generation and resident epoch; a mismatch or gap requires an authoritative snapshot rather than a guessed merge. |
| <a id="identity-stream-sequence-is-monotone"></a>**Stream sequence is monotone** | Stream sequence is monotone within an epoch and frames are applied exactly once in that order. Random identities are never treated as an ordering relation. |
| <a id="identity-one-epoch-bound-stream-carries-snapshot-and-resume"></a>**One epoch-bound stream carries snapshot and resume** | One authenticated epoch-bound stream carries an authoritative snapshot followed by accepted facts in monotone sequence. |
| <a id="identity-durable-facts-and-heads-remain-distinct-from-rebuildable-index-rows"></a>**Durable facts and heads remain distinct from rebuildable index rows** | Durable facts and heads remain semantically and capability-distinct from rebuildable index rows. A profile may co-locate a derived index in the authority store and update or rebuild it in an authority transaction, but projection rebuild must not mutate immutable facts or heads. |
| <a id="identity-a-projection-family-must-declare-its-source"></a>**A projection family must declare its source** | A projection family must declare its source, its progress record, its replay horizon, its refill, and what it can still say when the source no longer reaches back. |
| <a id="identity-authority-admission-has-one-exact-current-shape"></a>**Authority admission has one exact current shape** | Each durable authority admits one exact current shape. A retired shape refuses before storage mutation and names its owning release; a newer, unknown, inconsistent, or unfinalized shape also refuses without rewriting authority. Independent pre-read maintenance may mutate only the stale temporary state it explicitly owns. |

## Steering

| Label | Invariant |
| --- | --- |
| <a id="steering-an-item-is-durable-before-delivery-is-attempted"></a>**An item is durable before delivery is attempted** | An item is accepted as one journal transaction before any delivery reader is notified. |
| <a id="steering-reads-never-retire-an-item"></a>**Reads never retire an item** | Reads never retire an item. `acked`, `declined`, and `canceled` are distinct typed dispositions. |
| <a id="steering-decline-is-a-first-class-terminal-disposition"></a>**Decline is a first-class terminal disposition** | A reasoned refusal is recorded as the terminal `declined` disposition and surfaced everywhere acknowledgement is. |
| <a id="steering-a-peer-message-is-attributed-to-its-sending-lane-and-carries-no-operator-authority"></a>**A peer message is attributed to its sending lane and carries no operator authority** | An authored [MSG](#steering-an-authored-msg-packet-publishes-to-every-named-seated-occupant-or-to-none) is the only peer publication; no command, route, or app control sends a peer message. A peer message's creating fact names its sending lane as `from`, and every delivery names the sender and frames the text as information that cannot override operator steering or task authority. It mints a key and retires, lapses, and quotes like any directive. An MSG is attributed to the exact occupant that authored it, read from its creating `steer::messaged` fact: its delivery names the sending lane and that occupant's address, or `unproved` when no single birth proves one, never an invented address, and its quote and directive-context cards name that occupant, current or historical, never whoever later sits in the sending lane. A departed author with no source card recording its agent is named, as historical, by its lane's label and accent while that lane sits vacant; under a later occupant, or once the lane leaves the roster, the card shows the short lane and occupant identities as unresolved. Every card keeps the exact lane and occupant in its data. Peer messages sent by the retired `steer::tell` command stay readable evidence: their `steer::sent` facts carry `from`, their receipts still verify, and they deliver, quote and back up like any directive, attributed to the sending lane; a Chat quote card names the lane's seated agent with its accent, or the short lane identity when nobody sits there. A peer delivery whose journal records no sending occupant names its lane and says its sender is `unproved`. Every peer delivery teaches the one peer protocol: ACK or NAK it, and send anything new as an MSG. Like taste and resident guidance, a pending peer message or reply never wakes a lane; only operator-authored steering does. Operator direction names no sender. |
| <a id="steering-an-answered-peer-message-replies-once-to-its-sender"></a>**An answered peer message replies once to its sender** | When a lane's transcript ACKs or NAKs a live peer message, the retiring write also journals one `steer::replied` directive to the sending lane, seated or not. Each fanout recipient's answer retires only its own key and replies only for it. The reply is attributed to the answering lane, names the answered key and marker in its typed fields, and its text is only the header's clause: the rest of that header's line, ending before any MSG packet placed later on the line, whose text belongs to that packet and never to the reply. A reply to an MSG is delivered as spoken by the exact occupant that MSG addressed, read back through the reply's cause to the retirement and the MSG it retired, with that occupant's address, or `unproved` when no single birth proves one; a reply to a historical `steer::tell` message says its sender is `unproved`. No card repeats the marker; the peer delivery tells the recipient so, and the answerer never repeats its answer as an MSG. A reply already owed follows lane continuity: it addresses the sending lane, not the sending occupant, so a sender that asked and ended its turn, or the lane's next occupant, hears it at the lane's next seat; like any peer message it never wakes the lane. This is distinct from an MSG's exact-occupant delivery and never resolves a new MSG to an expired address. The reply and the retirement commit together, so a restart neither drops nor repeats it. A reply's own answer produces nothing further, and operator, resident, and taste direction never produce a reply. |
| <a id="steering-acknowledgment-evidence-is-assistant-prose-on-the-lane-tape"></a>**Acknowledgment evidence is assistant prose on the lane tape** | An ACK or NAK header may appear anywhere in authored assistant text on the lane tape. Steering retires automatically as that prose lands; no acknowledgment command exists. Visible commentary qualifies when persisted as assistant text, and so does the intent a tool call declares, which the transcript keeps verbatim when a provider settles the prose before a tool call as a paraphrased reasoning block, and a header retired from an intent presents as an acknowledgement card in the message flow; reasoning and tool arguments never do. Fenced or indented code, block quotes, inline quoted examples, rendered source-context lines, explicit negation, hypothetical wording, and narration about a header do not retire a key. At occupant exit, a header present only in tool arguments is reported as `steer::transcript-evidence-absent` and a quoted key as `steer::ack-missed`; either key stays live. |
| <a id="steering-an-msg-packet-owns-exactly-its-body-hunk"></a>**An MSG packet owns exactly its body hunk** | `MSG ADDRESS [ADDRESS ...]: BODY` is the authored peer-publication packet. It is read by the same grammar as ACK and NAK headers, so the same code, quote, rendered-source, negation, hypothetical and narration exclusions apply, and it never names a steering key or retires a directive; a recipient spelled like a steering key is still an [occupant address](#identity-an-occupant-address-is-its-birth-position). Recipients are alphanumeric tokens separated by header space or commas and closed by a colon. A closed list is an attempt when any token spells an address; an unclosed list is one only when its first token does; anything else is ordinary prose. The body starts after the colon and runs to the next placed ACK, NAK or MSG header or to the end of the prose, with surrounding whitespace trimmed and its inner bytes kept. When that next header is preceded on its line only by list, dash, bracket or item-number framing, the body ends at the start of that line. Quoted or narrated markers neither send nor end a body, and prose before the first header belongs to no packet. The first defect in source order refuses the whole packet: `msg::unterminated` when the colon is missing, `msg::recipient-malformed` for a token that is not an address, `msg::recipient-repeated` for an address named twice, and `msg::body-empty` for a body with only whitespace. A refused packet never guesses or drops a recipient, deduplicates, or borrows a neighbor's body. |
| <a id="steering-an-authored-msg-packet-publishes-to-every-named-seated-occupant-or-to-none"></a>**An authored MSG packet publishes to every named seated occupant or to none** | A packet's only source is a complete assistant text block on its author's lane tape: OMP's streamed `text_end`, which the provider may later settle verbatim or paraphrase into reasoning. Settled message prose, reasoning, tool arguments and tool-call intents never publish, and an incomplete block is never read. The author is the occupant the record's capture binding names (the noticed occupant for a live sweep, the exiting occupant for its closing sweep, the lane's declared session occupant for records after that declaration at startup), never a header's claim or whoever later sits in the lane. One residency view resolves every recipient to the exact occupant it seats. An address naming no seated occupant refuses the whole packet with `msg::recipient-unavailable`, the author's own address with `msg::recipient-self`, and an author without one proved birth on its lane with `msg::sender-unproved`. A publishable packet journals one `steer::messaged` fact per recipient, naming the recipient lane and occupant, the sending lane and occupant, the exact body, and the header's transcript locus as source evidence, in one write guarded on that residency, so a seat change before commit refuses every message and the packet re-resolves against the new residency at most twice more. Each message's directive identity is derived from the packet's locus (tape generation, record, event, header line and column) and its recipient address: rereading a packet live, at exit or at startup finds it already published, while the same body authored at another locus is another message. Each message is ordinary peer steering for its recipient, answered and replied to like any peer message; MSG itself acknowledges and retires nothing. A packet the residency refuses journals one `steer::withheld` fact naming the sending lane and occupant, the packet's locus and the refusal, and only once it is durable does the refusal become a resident diagnostic naming the packet's record, line and column and, for a seated author, a private notice. A refusal that cannot be recorded leaves the packet undecided: its author hears nothing and only an unpublished diagnostic names it. A withheld packet is settled: no later reread publishes it, even after the refused address seats an occupant or the residency stops moving. A packet the grammar refuses records nothing, since its text refuses identically on every read. Startup rereads each lane's recent tail after its session declaration, skipping every packet withheld from that occupant since its birth, so a packet accounted just before a crash still publishes once; recovery runs before the new resident seats any occupant, so such a packet resolves against no occupant born after the previous resident stopped. |
| <a id="steering-an-authored-msg-presents-as-an-outgoing-quote"></a>**An authored MSG presents as an outgoing quote** | In its author's Chat prose card, every well-formed packet whose addresses each prove one occupant birth presents its body, without the header, as one block quote in the existing quote visual language, wearing the authoring occupant's accent. Its lead names that occupant, an outgoing arrow, and every addressed occupant in header order, each by its own seat, else by its lane while that lane sits vacant, else by its address; a later occupant of a recipient's lane never inherits the name, and every name keeps its exact lane, occupant and address in its data. The quote states whom the packet addressed, not whether it was delivered. Packets in tool-call intents, quoted prose, refused by the grammar, or naming an address no birth proves stay literal text, and incoming peer messages and replies keep their dated source attribution, so a sent message never reads as a quote of words its card answers. |
| <a id="steering-a-turn-ending-header-retires-at-occupant-exit"></a>**A turn-ending header retires at occupant exit** | When an occupant exits, every live key its final transcript answers is retired under the same recognition rules live prose disposal applies, journaled with the transcript locus as evidence, and the lane supervisor is notified; no successor wakes to cite the header. A key the final transcript does not answer stays live and still wakes a successor, except an MSG addressed to the departed occupant, which [dead-letters](#steering-pending-inbox-terminal-wake-failure-deadletters-the-lane-s-pending-directives) instead. |
| <a id="steering-escalation-is-driven-by-silence-measured-from-publication"></a>**Escalation is driven by silence measured from publication** | Escalation is driven by silence measured from publication, on a stable lineage key, in three named stages before expiry. |
| <a id="steering-every-live-presentation-stage-admits-the-same-dispositions"></a>**Every live presentation stage admits the same dispositions** | Published, reminded, escalated, and overdue directives all admit `acked`, `declined`, `canceled`, `lapsed`, and `deadlettered`. A delivery read is not a disposition. |
| <a id="steering-pending-inbox-terminal-wake-failure-deadletters-the-lane-s-pending-directives"></a>**PendingInbox terminal wake failure deadletters the lane's pending directives** | A `PendingInbox` automatic wake that returns `Unstarted` or a terminal-class start failure moves every pending directive on that lane to `deadlettered` from its retained live presentation stage. Held-claim, capacity, operator-start, nonterminal-error, and arbitrary delivery-failure paths do not deadletter. The one other path is an MSG whose recipient occupant no longer sits in its lane: the lane's inbox stops delivering it at once, and after the closing sweep of every vacated seat, and at startup after transcript recovery, it moves to `deadlettered` with `steer::recipient-departed`, so no successor inherits it. Recovery preserves identity, lineage, stage, and presentation history, and refuses such an MSG with `steer::recipient-departed`. |
| <a id="steering-submit-cost-does-not-grow-with-backlog-depth"></a>**Submit cost does not grow with backlog depth** | Submit cost does not grow with backlog depth; journal allocation never reads queued bodies. |
| <a id="steering-keys-use-the-current-microsecond-codec"></a>**Steering keys use the current microsecond codec** | The mint advances the indexed Unix-microsecond high-water to at least the current microsecond and selects its first unused nine-character base-52 value. A collision advances exactly one microsecond. Retained eight-character keys remain readable but are never minted. |
| <a id="steering-pending-steering-reaches-each-admitted-agent-boundary"></a>**Pending steering reaches each admitted agent boundary** | Pending steering reaches the agent through the command-driven supervisor, which obtains the current authenticated journal inbox directly. It catches up at occupant start and reads again on resident kicks, deduplicates unchanged renderings, and interrupts in-flight commands for unheard direction. |
| <a id="steering-delivery-expands-authenticated-quote-links"></a>**Steering delivery expands authenticated quote links** | The authenticated inbox replaces every fixed-label quote link with its durable source text before a hook or command supervisor delivers it. Expansion recurses through nested sources to the shared depth bound; an unavailable source or the first source beyond that bound becomes an explicit one-line stub naming the target. The journal retains the original linked directive, while compaction, renewal, and repeated reads deterministically reconstruct the self-contained delivery. |
| <a id="steering-lapsed-items-remain-recoverable"></a>**Lapsed items remain recoverable** | A bounded lifetime moves unanswered intent to a typed lapsed state. Recovery returns the same directive to live with its presentation stage and history intact; lapse never impersonates a decision. |
| <a id="steering-the-journal-inbox-is-authoritative"></a>**The journal inbox is authoritative** | The journal owns directive lifecycle history and current pending heads. Supervisors and the `inbox` command read that authority directly; no filesystem rendering participates in delivery or recovery. |
| <a id="steering-retired-direction-stays-readable-in-a-bounded-window"></a>**Retired direction stays readable in a bounded window** | An inbox read that asks for retirements also returns, per visible lane, its eight most recently retired directives, newest retirement first, each with its identity, key, fanout, sender, preview, authored instant, terminal disposition, and retiring fact position and instant. Text and attachments stay in the journal. The read keeps its principal scope: a lane sees only its own retirements. |
| <a id="steering-operator-direction-history-pages-whole-fanouts"></a>**Operator direction history pages whole fanouts** | An operator-only history read returns operator-authored directions, one group per fanout, newest first by the group's first creating fact. Each group carries its preview, authored instant, and every recipient's lane, key, disposition, and retiring fact position and instant. A text query folded for ASCII case, recipient lanes, dispositions, and an authored-at-or-before cutoff each keep or drop a group whole before a bounded page; anchoring on a directive or fanout returns that group first with older and newer cursors. Peer messages, replies, and resident-authored directives never appear, and an operator head without a fanout refuses the read as corrupt. |
| <a id="steering-lapse-and-terminal-dispositions-are-distinct"></a>**Lapse and terminal dispositions are distinct** | `lapsed` is recoverable and distinct from terminal `acked`, `declined`, and `canceled`. Silence never looks like a decision. |
| <a id="steering-shell-instrumentation-is-one-shot-at-the-agent-s-own-command-boundary"></a>**Shell instrumentation is one-shot at the agent's own command boundary** | Shell instrumentation is one-shot at the agent's own command boundary: the wrapper runs exactly once per agent command and nothing beneath it is instrumented again. |
| <a id="steering-the-exactly-once-gate-is-structural"></a>**The exactly-once gate is structural** | The exactly-once gate is structural — distinct packaged environments rather than a counter — so there is no marker to read, forge, or lose. |
| <a id="steering-a-descendant-process-gets-the-user-s-shell-unmodified"></a>**A descendant process gets the user's shell unmodified** | A descendant process gets the user's shell unmodified, so a script that assumed a plain shell behaves identically inside and outside an agent. |
| <a id="steering-a-sourced-script-is-not-a-descendant-and-shares-the-immediate-shell-s-functions"></a>**A sourced script is not a descendant and shares the immediate shell's functions** | A sourced script is not a descendant and shares the immediate shell's functions: the boundary drawn is the process boundary, not a syntactic one. |
| <a id="steering-supervisor-delivery-reads-journal-authority"></a>**Supervisor delivery reads journal authority** | The command-driven supervisor performs an authenticated journal catch-up when an occupant starts and another read on each resident kick. It writes each changed nonempty rendering to the vendor command stream, suppresses identical bytes, nudges repeated keys according to occupant response, interrupts in-flight commands for unheard keys, and resets occupant-local telling state after compaction. After a compaction it replays pending steering with one recovery instruction and writes nothing over an empty inbox, since the acknowledgment protocol rides the system prompt that compaction keeps. |
| <a id="steering-private-output-relays-end-with-the-immediate-child"></a>**Private output relays end with the immediate child** | The wrapper waits on one immediate process identity through fork, wait, and `exec`. When that identity exits, it revokes inherited stdout/stderr relay writers and drains committed output, so a background descendant cannot retain the wrapper. |
| <a id="steering-the-complete-top-level-command-string-reaches-the-wrapper-exactly-once"></a>**The complete top-level command string reaches the wrapper exactly once** | The complete top-level command string reaches the wrapper exactly once — the last point at which the command is still one string rather than a running process. |
| <a id="steering-reaches-the-next-admitted-agent-boundary"></a>**Steering reaches the next admitted agent boundary** | The command-driven supervisor delivers live content from journal authority. Non-shell tool sequences remain reachable because it interrupts an active host call for unheard direction; without a running supervisor, delivery waits for the next occupant's startup catch-up. |

## Work, claims, and allocation

| Label | Invariant |
| --- | --- |
| <a id="work-at-most-one-active-claim-per-actor"></a>**At most one active claim per actor** | At most one active claim per actor. |
| <a id="work-task-next-honors-existing-possession-before-allocation"></a>**`task next` honors existing possession before allocation** | When its actor already holds exactly one active claim, `task next` reports that task's handle, current phase, and actionable continuation from the read snapshot. It neither enters allocation nor changes the claim, and therefore never describes the actor's own possession as peer-held or as an empty allocator. |
| <a id="work-claiming-is-atomic"></a>**Claiming is atomic** | Claiming is atomic: `claim::won`, the active claim head and owner, and the lease are committed together, so no row projects active possession without an owner. |
| <a id="work-claims-carry-a-bounded-lease-and-an-exact-source-boundary"></a>**Claims carry a bounded lease and an exact source boundary** | A claim records its bounded lease and the lane's exact accounted opening source boundary. Terminal evidence supplies the exact closing boundary. |
| <a id="work-lapse-writes-lapsed-before-readiness-is-derived"></a>**Lapse writes `lapsed` before readiness is derived** | Claim lapse is a typed journal transaction that changes claim disposition from `active` to `lapsed`. Readers then derive readiness from every current eligibility predicate without rewriting claim history. |
| <a id="work-an-explicit-steal-replaces-exactly-the-named-claim"></a>**An explicit steal replaces exactly the named claim** | An explicit steal is immediate and replaces exactly the named current claim or refuses. The displaced claimant learns through a typed ownership refusal on its next claim operation, not a fabricated steering item. |
| <a id="work-every-repository-backed-claim-measures-the-new-holder-s-git-opening"></a>**Every repository-backed claim measures the new holder's Git opening** | Allocator claim, explicit capture, and explicit steal each record the new holder's measured opening Git boundary. Named capture adopts intentional loose commits; a clean named claim synchronizes like allocator possession; steal never reuses the displaced holder's opening. Plan completion therefore admits an untouched named claim and still refuses dirty work or a moved `HEAD`. |
| <a id="work-renew-and-carry-are-distinct-active-claim-facts"></a>**Renew and carry are distinct active-claim facts** | `claim::renewed` extends the same active claim's lease. `claim::carried` moves active possession to a successor occupant without a fresh win, preserving lineage and elapsed work. |
| <a id="work-a-live-lease-rolls-with-its-occupant"></a>**A live lease rolls with its occupant** | The resident rolls a live claim's lease on one rolling horizon while the claim's lane still seats the occupant holding it, independently of how that claim was minted. Renewal stops when the occupant stops being current, so a lapse follows the occupant leaving rather than a long foreground command outliving a fixed lease. The one exception is a lane left vacant by that occupant while one of its deadline-bounded jobs is unfinished: the lease keeps rolling, never past one rolling window beyond the latest such job's deadline plus the keeper's terminate and delivery grace, so the successor the keeper wakes still finds the claim live. Services and ended jobs extend nothing, and no renewal rolls a claim while another occupant holds the seat. A lease iced on the canonical indefinite horizon never rolls. |
| <a id="work-a-witness-record-distinguishes-an-intentional-end"></a>**A witness record distinguishes an intentional end** | A witness record distinguishes an intentional, announced end from no history at all. |
| <a id="work-queue-age-has-one-durable-origin"></a>**Queue age has one durable origin** | Queue age has one durable origin, and unrelated row modifications do not reset it. |
| <a id="work-allocation-ranks-in-a-fixed-ladder"></a>**Allocation ranks in a fixed ladder** | Allocation ranks in a fixed ladder: phase-handoff preference, then last-resort class (the prior independent-phase owner, the actor's own review, and rows it freed), then effective priority, downstream weight, a narrow urgency band, peer spread, and locality. |
| <a id="work-phase-handoffs-use-durable-transition-evidence"></a>**Phase handoffs use durable transition evidence** | A phase transition's current workflow head and causal completion fact define its short ownership window without inspecting a phase name. A continuation prefers and temporarily reserves the row for its prior claimant. A completion that published repository history temporarily reserves the next phase for eligible peers, then admits the prior claimant only as a last resort. Task birth carries no handoff, and every ordinary subscription, dependency, environment, lease, and single-claim admission still applies. |
| <a id="work-a-prerequisite-inherits-the-highest-priority-it-transitively-unblocks"></a>**A prerequisite inherits the highest priority it transitively unblocks** | A prerequisite inherits the highest priority it transitively unblocks. |
| <a id="work-self-authored-review-is-ranked-last-never-excluded"></a>**Self-authored review is ranked last, never excluded** | Self-authored review is ranked last, never excluded; a quiet board hands an actor its own review rather than stalling. |
| <a id="work-a-freed-row-is-ranked-last-never-excluded"></a>**A freed row is ranked last, never excluded** | A row an actor explicitly freed ranks last for that actor until someone claims it; the actor drains other work first but is not barred from taking it back. |
| <a id="work-locality-is-the-final-tie-break-and-never-overrides-the-graph"></a>**Locality is the final tie-break and never overrides the graph** | Locality is the final tie-break and never overrides the graph. |
| <a id="work-every-task-names-an-origin-realm"></a>**Every task names an origin realm** | Every origin has the open wire shape `<nonempty-class>:<nonempty-value>`. `ack:<key>` and `task:<born-stamp>` are the ordinary conventions, and typed system routes conventionally supply proved `gate:<report-digest>` or `doc:<preview-digest>` causes; authored classes outside that roster are preserved rather than rejected. The origin records why the task exists, never who filed it. |
| <a id="work-a-phase-advance-is-a-publication"></a>**A phase advance is a publication** | A phase advance is a publication, recoverable from the authority's own history without a parallel event log. |
| <a id="work-a-review-that-changes-nothing-still-advances-the-phase"></a>**A review that changes nothing still advances the phase** | A review that changes nothing still advances the phase, so absence of a commit is not absence of review. |
| <a id="work-a-review-finding-returns-under-the-task-key"></a>**A review finding returns under the task key** | Feedback to the live phase author begins with the bare `TASK-KEY`, followed by the quoted finding and the existing verbalization guidance. The heading adds no marker, explanatory words, or trailing colon; a quoted feedback context wears a typed REVIEW badge from the feedback's review control. |
| <a id="work-a-task-flow-is-nonempty-unique-and-self-containing"></a>**A task flow is nonempty, unique, and self-containing** | A flow contains at least one unique phase name; each name is one nonempty lowercase ASCII word, and the current phase is a member of that flow. The board has no global phase enumeration or slot ceiling. |
| <a id="work-a-named-flow-outranks-the-review-omission-default"></a>**A named flow outranks the review-omission default** | A task created without a named flow — a review `--then` correction, a `task add` with dependencies, or a document node without `Flow:` — omits its review phase when every reviewed parent or dependency is pending in review, because that parent's own re-review is the closing check and re-fails if the fix falls short. A flow the author names explicitly is created exactly as written, review included. |
| <a id="work-dependency-blocking-is-an-eligibility-predicate-not-a-task-transition"></a>**Dependency blocking is an eligibility predicate, not a task transition** | A pending task with any unsettled dependency remains pending but is ineligible. A prerequisite is settled when its workflow status is `completed` or `deleted`; either completion or withdrawal may make the dependent eligible without writing its workflow transition. |
| <a id="work-dependency-edge-edits-are-guarded-publications"></a>**Dependency edge edits are guarded publications** | Adding or removing named task dependencies publishes one guarded statement revision and preserves every workflow and claim head. Removal names an existing edge exactly; an absent edge refuses rather than advancing the revision. A removal that would leave a plan relying on child acceptance without any pending accepted child refuses before publication. Every accepted edit leaves the complete dependency graph acyclic. |
| <a id="work-the-operator-closes-a-task-with-a-recorded-validation"></a>**The operator closes a task with a recorded validation** | Only an operator principal may close a task. Closure is guarded by the task statement, workflow, and claim heads, requires nonblank validation text, and refuses a task that is unknown, completed, or withdrawn. It writes one `task::closed` fact carrying the validation and the phase it cut short, and moves the workflow to `completed` with its completion instant and no assignment from any phase, review included. A live claim refuses the closure unless forced; a forced closure frees that claim in the same transaction and records the displaced holder. The validation is never recorded as a note; task detail and `task show` read the closure back with its author, phase, validation, and any displaced holder. |
| <a id="work-environmental-blocking-is-an-eligibility-predicate-not-a-task-transition"></a>**Environmental blocking is an eligibility predicate, not a task transition** | A task's canonical AND-conjunction may require a minimum `journal-schema` and/or one exact `trust-grant` digest. The digest is satisfied only by a current `granted` trust head carrying producer-worktree provenance; that provenance is evidence rather than scope. Missing, pended, revoked, or unbound heads leave the pending task ineligible, while a matching repository-shared grant makes it eligible without rewriting or waking the task. |
| <a id="work-an-unmet-trust-grant-ices-the-current-claim-without-a-new-state"></a>**An unmet trust grant ices the current claim without a new state** | When the current holder attaches an unsatisfied exact `trust-grant`, one task/claim/lease/trust-guarded edit retains the claim and moves only lease expiry and maximum to the canonical 2099 horizon. Work-driven automatic starts stop while pending-inbox messages remain wakeable. Grant or authorized blocker removal thaws the same claim during same-lane seating by replacing the sentinel with ordinary bounded lease values; explicit free remains available. |
| <a id="work-only-explicit-defer-and-wake-change-deferral"></a>**Only explicit defer and wake change deferral** | Deferral is durable and its timestamp is advisory rather than self-clearing. Only an explicit wake clears it; dependency settlement does not. Workflow status remains `pending`, and ordinary eligibility is recomputed after the wake. |
| <a id="work-implementation-work-is-refused"></a>**Implementation work is refused** | Implementation work is refused while the actor holds a plan-phase claim. |
| <a id="work-hidden-channels-keep-admissions-off-the-queue"></a>**Hidden channels keep admissions off the queue** | Hidden channels exist so that admitting a mistake is cheap: the row is filed off the default allocation queue rather than into the work an actor is handed. Nothing about it is withheld — every read renders its title, description, acceptance, and notes in full, because an unreadable row cannot be triaged. |
| <a id="work-a-lapsed-claim-is-not-held-by-a-peer"></a>**A lapsed claim is not held by a peer** | Once the lapse transaction is accepted, the exact disposition is `lapsed`, so the row is not counted as peer-held; readiness remains a read-time result of all other predicates. Before acceptance, the exact current claim remains authoritative and readers infer no in-between state. |
| <a id="work-a-dry-allocator-reports-the-board"></a>**A dry allocator reports the board** | A dry allocator reports the board rather than pointing at it: each parked category is named with the reason it is parked, and a populated board is stated to be the expected answer rather than an error or missed work. |
| <a id="work-permission-to-stop-is-bound-to-the-one-condition-that-grants-it"></a>**Permission to stop is bound to the one condition that grants it** | Permission to stop is bound to the one condition that grants it — a dry allocator immediately after asking for work. Lookalikes are called out by name so neither a quiet-looking board nor a low pending count reads as a licence to spin down. |
| <a id="work-affinity-and-anti-affinity-address-one-coordinate"></a>**Affinity and anti-affinity address one coordinate** | Affinity and anti-affinity address one coordinate — the (project, phase) cell — read in two directions, so neither can be tuned into overwhelming the other. |
| <a id="work-anti-affinity-reads-peers-across-the-whole-board"></a>**Anti-affinity reads peers across the whole board** | Anti-affinity reads peers across the whole board, not only through the actor's own route: spreading is about where the agents are, not where this actor's candidates are. |
| <a id="work-anti-affinity-is-a-preference-never-an-exclusion"></a>**Anti-affinity is a preference, never an exclusion** | Anti-affinity is a preference, never an exclusion; when every ready row sits in a crowded cell the actor is still handed one. |
| <a id="work-affinity-is-measured-from-the-actor-s-most-recently-claimed-cell-alone"></a>**Affinity is measured from the actor's most recently claimed cell alone** | Affinity is measured from the actor's most recently claimed cell alone, with no accumulated history, so moving to a new area is paid for exactly once. |
| <a id="work-movement-counts-project-and-phase-separately-and-sums-the-two"></a>**Movement counts project and phase separately and sums the two** | Movement counts project and phase separately and sums the two, so changing both costs strictly more than changing either alone. Leaving a project for the same phase and changing phase inside a project cost the same; only compounding the two is penalised, and that gradient is what makes an agent finish an area. |
| <a id="work-locality-applies-only-inside-a-narrow-urgency-band"></a>**Locality applies only inside a narrow urgency band** | Both locality terms are gated by a narrow urgency band beneath the top of the row's own group and neutralized outside it, because a merely lower rank still decides every comparison the levels above it tie on. |
| <a id="work-tasks-without-acceptance-enter-a-plan-phase"></a>**Tasks without acceptance enter a plan phase** | A task created with neither acceptance nor a named flow has a plan phase prepended to its flow rather than being refused or filed vague: absent acceptance is unfinished thinking, not an error. |
| <a id="work-captured-commits-enter-owned-implementation-atomically"></a>**Captured commits enter owned implementation atomically** | New-task `task capture` records the task, active claim, and exact loose-commit boundary in one guarded transaction and starts at the first non-plan phase. A taste hold or any claim-preparation refusal writes none of them. Ordinary task creation still follows the planning rule above. |
| <a id="work-a-plan-phase-closes-only-when-acceptance-exists"></a>**A plan phase closes only when acceptance exists** | A plan phase closes only when acceptance exists — on the task itself or on at least one pending child carrying acceptance. A child is connected whether the plan depends on it or it depends on the plan; completion witnesses that child's exact statement and workflow in either direction. |
| <a id="work-a-plan-only-flow-must-leave-a-connected-child-carrying-acceptance"></a>**A plan-only flow must leave a connected child carrying acceptance** | A plan-only flow must leave a pending child carrying acceptance connected in either dependency direction, because the board it produces is its entire product. |
| <a id="work-plan-born-children-connect-atomically"></a>**Plan-born children connect atomically** | A lane creating a task with `task add` while it holds a plan claim atomically makes the new child depend on the ambient plan, guarding the parent's statement, workflow and claim authority without editing its prerequisites. Allocation cannot start the child until planning completes. Explicit `task add --depends` supplies the new task's complete prerequisite list and suppresses the implicit gate; include the ambient plan to retain it. A pending accepted child gated behind a plan is sufficient for plan-only completion. Never add the reciprocal plan-to-child edge, which would create a cycle. `task oops` filing records friction rather than a planned child and never links. |
| <a id="work-the-prepended-phase-is-visible-as-a-phase"></a>**The prepended phase is visible as a phase** | The prepended phase is visible as a phase, not as a flag, so the board explains the task's behaviour in a vocabulary the operator already reads. |
| <a id="work-a-taste-hold-is-visible-before-a-task-is-read"></a>**A taste hold is visible before a task is read** | A task held in plan because its statement matches the current taste policy names that hold where a lane first meets it: status carries the held handles, the assignment's next action is the rewording rather than another read, and the refusal that keeps the plan open reports how many revisions the policy has already rechecked, so a second refusal reads differently from the first. |
| <a id="work-the-matched-taste-is-withheld-from-the-statement-s-author"></a>**The matched taste is withheld from the statement's author** | The author reads that taste review holds the statement, never which words matched: the matched token, the column locating it, and the taste's own message are withheld on every lane-facing surface, including the durable audit as the lane reads it, because an author told the word swaps the word instead of rewriting the statement. The operator who owns the policy reads the complete audit, and the field and line remain so the passage is still findable. |
