# Invariant register — Identity, steering, and work

[Invariant register](../invariants.md) · [Spice product model](../README.md)
## Identity and authority

| Label | Invariant |
| --- | --- |
| <a id="identity-a-task-s-born-stamp-is-its-only-stored-identity"></a>**A task's `born` stamp is its only stored identity** | The rendered handle derives a key from the project's rightmost segment and is never stored, so re-homing renames for free. Every surface resolves a handle by its stamp alone: a handle rendered under another project names the same task, the stem never grants or narrows visibility, and answers render the current handle. Stamp order is not creation chronology; journal sequence and durable queue origin are. |
| <a id="identity-an-occupant-address-is-its-birth-position"></a>**An occupant address is its birth position** | An occupant's only peer address is the journal position of the one `lane::started` fact recording its birth. It is derived from that fact, never minted or stored, so occupants started in the same instant keep distinct addresses. Proof reads exactly the addressed position and refuses rather than picking when no birth, a non-birth fact, or a repeated birth is found. |
| <a id="identity-an-address-executes-only-for-its-seated-occupant"></a>**An address executes only for its seated occupant** | An address resolves only while the residency seats that exact occupant on its birth lane; it never follows the lane to a successor. Resident restart adoption keeps the occupant and its address. Every wake, resume, import, and renewal seats a different occupant with its own address, and the predecessor's address expires. |
| <a id="identity-a-discovered-seat-address-resolves-to-the-occupant-shown"></a>**A discovered seat address resolves to the occupant shown** | The session briefing names the reader's own address and its teammates' addresses, and `spice lane list` shows each lane's address. Only a seated occupant whose birth is proved exactly once on that lane shows one, and it is the address the resolver executes; a vacant seat or unproved birth shows as unavailable, never as a guessed or predecessor address. |
| <a id="identity-every-fact-has-exactly-one-authority"></a>**Every fact has exactly one authority** | Every fact has exactly one authority. Consumers ask the owner rather than re-deriving from a cheaper nearby source. |
| <a id="identity-a-resume-cursor-belongs-to-one-exact-stream"></a>**A resume cursor belongs to one exact stream** | One authenticated stream carries an authoritative snapshot followed by accepted facts in monotone sequence within one resident epoch, applied exactly once in that order. A cursor resumes only its exact application generation and resident epoch; a mismatch or gap requires a fresh snapshot rather than a guessed merge. |
| <a id="identity-durable-facts-and-heads-remain-distinct-from-rebuildable-index-rows"></a>**Durable facts and heads remain distinct from rebuildable index rows** | A derived index may share the authority store and transaction, but rebuilding it never mutates immutable facts or heads. |
| <a id="identity-a-projection-family-must-declare-its-source"></a>**A projection family must declare its source** | A projection family declares its source, its progress record, its replay horizon, its refill, and what it can still say when the source no longer reaches back. |

## Steering

| Label | Invariant |
| --- | --- |
| <a id="steering-an-item-is-durable-before-delivery-is-attempted"></a>**An item is durable before delivery is attempted** | An item is accepted as one journal transaction before any delivery reader is notified. Every submission is its own item: identical text sent twice persists as two items, never silently merged. Submit cost does not grow with backlog depth. |
| <a id="steering-the-journal-inbox-is-authoritative"></a>**The journal inbox is authoritative** | The journal owns directive lifecycle history and current pending heads. Supervisors and the `inbox` command read it directly; no filesystem rendering participates in delivery or recovery. |
| <a id="steering-pending-steering-reaches-each-admitted-agent-boundary"></a>**Pending steering reaches each admitted agent boundary** | The command-driven supervisor reads the journal inbox when an occupant starts and on each resident kick, writes each changed rendering once, and interrupts an in-flight command or tool call for unheard direction. A reminder restates a key only when its telling changed by arriving or climbing a stage; another key arriving or retiring restates nothing. After a compaction it replays pending steering with one recovery instruction; an empty inbox writes nothing. A key the occupant's visible prose or tool intent answered is withdrawn from every queued reminder, replay, and briefing as those words are decoded, and nothing names it again until the journal climbs its stage, which says the answer retired nothing. Without a running supervisor, delivery waits for the next occupant's start. |
| <a id="steering-delivery-expands-authenticated-quote-links"></a>**Steering delivery expands authenticated quote links** | Delivery replaces each quote link with its durable source text, recursively to a fixed depth; an unavailable or too-deep source becomes a one-line stub naming its target. The journal keeps the linked original, and every reread reconstructs the same delivery. |
| <a id="steering-a-quote-link-reads-as-its-source"></a>**A quote link reads as its source** | `spice quote TARGET`, and an omp occupant's `read` of a `spice://quote/v1` target, answer from the same resolution delivery uses: the recorded author, then the exact source text, with no side effect. An unresolvable target refuses with its stub; a write to any `spice://` URI other than a [task text](#work-a-task-text-write-replaces-only-the-text-its-writer-read) refuses, naming the index. A withdrawn read is never answered. An omp that refuses the scheme's registration runs on without it. |
| <a id="steering-acknowledgment-evidence-is-assistant-prose-on-the-lane-tape"></a>**Acknowledgment evidence is assistant prose on the lane tape** | An ACK or NAK header anywhere in authored assistant text, or in the intent a tool call declares, retires its key as the prose lands; no acknowledgment command exists. Reasoning, tool arguments, code, quotes, rendered source, negation, hypotheticals, and narration about a header retire nothing. |
| <a id="steering-a-turn-ending-header-retires-at-occupant-exit"></a>**A turn-ending header retires at occupant exit** | When an occupant exits, every live key its final transcript answers retires under the same recognition rules, with the transcript locus as evidence, and no successor wakes to cite it. An unanswered key stays live and wakes a successor, except an MSG addressed to the departed occupant, which [dead-letters](#steering-pending-inbox-terminal-wake-failure-deadletters-the-lane-s-pending-directives). |
| <a id="steering-reads-never-retire-an-item"></a>**Reads never retire an item** | A delivery read is not a disposition. `acked`, `declined` (a reasoned refusal, surfaced wherever acknowledgement is), and `canceled` are distinct terminal dispositions, and every live presentation stage admits each of them. |
| <a id="steering-a-lane-read-is-a-spice-resource"></a>**A lane read is a `spice://` resource** | An omp occupant's `read` of `spice://inbox`, `spice://lane`, and `spice://session/briefing`, `/turns`, `/sweep`, or `/context/SESSION` answers what `inbox`, `lane list`, and the matching `session` read render for that lane, under the occupant's own session identity and the grammar of [board reads](#work-a-board-read-is-a-spice-resource); a typed session page also names its continuation as a `spice://` URL. Reading acknowledges, retires, and redelivers nothing, however often omp reads or greps it. A live session's read of its own context refuses as the CLI does. |
| <a id="steering-only-a-serving-seat-is-taught-spice-urls"></a>**Only a seat that serves `spice://` is taught it** | An omp occupant's first turn waits for omp's answer to the scheme's registration. When omp accepts, that turn and each briefing after a compaction carry the scheme guide (the index, collections ending in member URLs, query flags, `continue:` URLs, line selectors, and that writes and authority acts stay `spice` commands), and the briefing names each quoted read a resource serves as its URL; a `spice://session/briefing` read does the same. A seat whose omp refused, or whose vendor has no host schemes, is never told and reads the commands it reads today, as does any read run in an occupant's shell. |
| <a id="steering-escalation-is-driven-by-silence-measured-from-publication"></a>**Escalation is driven by silence measured from publication** | Escalation is driven by silence measured from publication, on a stable lineage key, in three named stages before expiry. An operator resend keeps the key and re-presents the directive at the stage its silence has reached; it never advances presentation beyond that due stage. |
| <a id="steering-lapsed-items-remain-recoverable"></a>**Lapsed items remain recoverable** | A bounded lifetime moves unanswered intent to `lapsed`, which is never a decision. Recovery returns the same directive to live with its key, lineage, stage, and history intact. |
| <a id="steering-pending-inbox-terminal-wake-failure-deadletters-the-lane-s-pending-directives"></a>**PendingInbox terminal wake failure deadletters the lane's pending directives** | An automatic wake for pending steering that fails terminally to start an occupant moves every pending directive on that lane to `deadlettered`; other wake and delivery failures leave them live. An MSG whose addressed occupant has left its lane stops delivering and dead-letters, so no successor inherits it. Recovery restores a dead-lettered directive with its identity, lineage, and stage, but refuses such an MSG. |
| <a id="steering-retired-direction-stays-readable-in-a-bounded-window"></a>**Retired direction stays readable in a bounded window** | An inbox read that asks for retirements also returns each visible lane's most recently retired directives, newest first, with their dispositions and retiring facts. A lane sees only its own. |
| <a id="steering-operator-direction-history-pages-whole-fanouts"></a>**Operator direction history pages whole fanouts** | An operator-only history read pages operator-authored directions as whole fanouts, newest first, each with every recipient's disposition. Filters keep or drop a fanout whole. Peer messages, replies, and resident-authored directives never appear. |
| <a id="steering-a-peer-message-is-attributed-to-its-sending-lane-and-carries-no-operator-authority"></a>**A peer message is attributed to its sending lane and carries no operator authority** | An authored [MSG](#steering-an-authored-msg-packet-publishes-to-every-named-seated-occupant-or-to-none) is the only peer publication. Its delivery names the sending lane and the exact authoring occupant's address, or `unproved` when no single birth proves one, and frames the text as information that cannot override operator steering or task authority. It mints a key and retires, lapses, and quotes like any directive, but a pending peer message never wakes a lane; only operator steering does. |
| <a id="steering-an-answered-peer-message-replies-once-to-its-sender"></a>**An answered peer message replies once to its sender** | Retiring a live peer message journals, in the same write, one reply to the sending lane whose text is the answering header's clause. Each fanout recipient replies only for its own key. The reply addresses the sending lane rather than the occupant, so it is heard at that lane's next seat without waking it. A reply's own answer produces nothing further, and operator, resident, and taste direction never produce a reply. |
| <a id="steering-an-msg-packet-owns-exactly-its-body-hunk"></a>**An MSG packet owns exactly its body hunk** | `MSG ADDRESS [ADDRESS ...]: BODY` is read by the acknowledgment header grammar with the same exclusions; it names [occupant addresses](#identity-an-occupant-address-is-its-birth-position), never a steering key, and retires nothing. The body runs from the colon to the next placed ACK, NAK, or MSG header or the end of the prose. The first defect refuses the whole packet; a refused packet never guesses or drops a recipient or borrows a neighbor's body. |
| <a id="steering-an-authored-msg-packet-publishes-to-every-named-seated-occupant-or-to-none"></a>**An authored MSG packet publishes to every named seated occupant or to none** | Only a complete assistant text block publishes a packet; reasoning, tool arguments, and tool-call intents never do. Every recipient resolves against one residency, and one guarded write publishes to all of them or refuses the whole packet when any address is unseated, is the author's own, or the author has no proved birth. A refusal is recorded once and told privately to the author; a withheld packet never later publishes. Message identity derives from the packet's transcript locus, so live, exit, and startup rereads publish it at most once. |
| <a id="steering-an-authored-msg-presents-as-an-outgoing-quote"></a>**An authored MSG presents as an outgoing quote** | In its author's Chat card, a well-formed packet whose addresses each prove a birth renders its body as an outgoing quote naming the author and each addressed occupant by its own seat. It states whom the packet addressed, not whether it was delivered. |
| <a id="steering-shell-instrumentation-is-one-shot-at-the-agent-s-own-command-boundary"></a>**Shell instrumentation is one-shot at the agent's own command boundary** | The wrapper receives each complete top-level agent command string exactly once and instruments nothing beneath it. The boundary is the process: a sourced script shares the immediate shell's functions, while an executed descendant gets the user's shell unmodified. Exactly-once is structural, distinct packaged environments rather than a counter, so there is no marker to read, forge, or lose. |
| <a id="steering-private-output-relays-end-with-the-immediate-child"></a>**Private output relays end with the immediate child** | When the immediate command process exits, the wrapper revokes inherited output relays and drains committed output, so a background descendant cannot hold it open. |

## Work, claims, and allocation

| Label | Invariant |
| --- | --- |
| <a id="work-at-most-one-active-claim-per-actor"></a>**At most one active claim per actor** | At most one active claim per actor. `task next` for an actor already holding one reports that task and its next action without entering allocation. |
| <a id="work-claiming-is-atomic"></a>**Claiming is atomic** | The win, active head, owner, and lease commit together, and every repository-backed claim, whether by allocation, explicit capture, or steal, records the holder's measured opening Git boundary. Capture may adopt intentional loose commits; a steal never reuses the displaced holder's opening. Plan completion therefore admits an untouched claim and refuses dirty work or a moved `HEAD`. |
| <a id="work-an-explicit-steal-replaces-exactly-the-named-claim"></a>**An explicit steal replaces exactly the named claim** | An explicit steal is immediate and replaces exactly the named current claim or refuses. The displaced claimant learns through a typed ownership refusal on its next claim operation, not a fabricated steering item. |
| <a id="work-a-live-lease-rolls-with-its-occupant"></a>**A live lease rolls with its occupant** | The resident rolls a claim's lease while its lane seats the occupant holding it, so a lapse follows the occupant leaving rather than a fixed lease running out under long work. A lane that occupant left vacant keeps rolling only until its unfinished deadline-bounded jobs end, so the successor they wake finds the claim live. A successor seated while the claim is live receives it by carry, preserving lineage and elapsed work, not by a fresh win. |
| <a id="work-lapse-writes-lapsed-before-readiness-is-derived"></a>**Lapse writes `lapsed` before readiness is derived** | Lapse and explicit free are typed journal transitions to `lapsed` and `freed`, so an intentional end is distinguishable from silence. Once written, the row is not peer-held and readiness is derived from every current predicate; before then the current claim stays authoritative. |
| <a id="work-queue-age-has-one-durable-origin"></a>**Queue age has one durable origin** | Queue age has one durable origin, and unrelated row modifications do not reset it. |
| <a id="work-allocation-ranks-in-a-fixed-ladder"></a>**Allocation ranks in a fixed ladder** | Allocation ranks by phase-handoff preference, then last-resort class, then effective priority (a prerequisite inherits the highest priority it transitively unblocks), downstream weight, a narrow urgency band, peer spread, and locality. |
| <a id="work-phase-handoffs-use-durable-transition-evidence"></a>**Phase handoffs use durable transition evidence** | A phase transition's workflow head and causal completion fact open a short ownership window without inspecting a phase name. A continuation reserves the row for its prior claimant; a completion that published repository history reserves the next phase for peers and admits the prior claimant only as a last resort. |
| <a id="work-self-authored-review-is-ranked-last-never-excluded"></a>**Self-authored review is ranked last, never excluded** | The actor's own review, the prior independent-phase owner's row, and rows the actor freed rank last for that actor and are never excluded, so a quiet board hands an actor its own review rather than stalling. |
| <a id="work-locality-is-the-final-tie-break-and-never-overrides-the-graph"></a>**Locality is the final tie-break and never overrides the graph** | Only rows within a narrow urgency band of their group's top compare by locality. Among them a (project, phase) cell any peer on the board occupies ranks below a free one, then movement from the actor's most recently claimed cell costs one for a changed project and one for a changed phase. Crowding never excludes a row. |
| <a id="work-every-task-names-an-origin-realm"></a>**Every task names an origin realm** | Every origin has the shape `<class>:<value>` and records why the task exists, never who filed it. `ack:<key>` and `task:<born-stamp>` are the ordinary conventions; unknown classes are preserved rather than rejected. |
| <a id="work-a-task-flow-is-nonempty-unique-and-self-containing"></a>**A task flow is nonempty, unique, and self-containing** | A flow is a nonempty list of unique lowercase phase names containing the current phase. The board has no global phase vocabulary. |
| <a id="work-a-review-that-changes-nothing-still-advances-the-phase"></a>**A review that changes nothing still advances the phase** | A review that changes nothing still advances the phase, so absence of a commit is not absence of review. Review feedback reaches the phase author under the bare task key. |
| <a id="work-a-named-flow-outranks-the-review-omission-default"></a>**A named flow outranks the review-omission default** | A task created without a named flow omits its review phase when every reviewed parent or dependency is pending in review, because that parent's re-review is the closing check. A flow the author names is created exactly as written. |
| <a id="work-dependency-blocking-is-an-eligibility-predicate-not-a-task-transition"></a>**Dependency blocking is an eligibility predicate, not a task transition** | A pending task with an unsettled dependency stays pending but ineligible. A prerequisite settles when completed or deleted, without writing the dependent's workflow. Dependency edits are guarded publications that refuse an absent edge, a cycle, or a removal that leaves a plan relying on child acceptance without a pending accepted child. |
| <a id="work-environmental-blocking-is-an-eligibility-predicate-not-a-task-transition"></a>**Environmental blocking is an eligibility predicate, not a task transition** | A task may require a minimum journal schema and one exact trust-grant digest. Until a current grant satisfies it the pending task is ineligible; a matching grant makes it eligible without rewriting or waking it. |
| <a id="work-an-unmet-trust-grant-ices-the-current-claim-without-a-new-state"></a>**An unmet trust grant ices the current claim without a new state** | When the holder attaches an unsatisfied trust grant, the claim stays held with its lease moved to an indefinite horizon, and work-driven starts stop while pending steering still wakes the lane. A grant or authorized blocker removal thaws the same claim; free remains available. |
| <a id="work-only-explicit-defer-and-wake-change-deferral"></a>**Only explicit defer and wake change deferral** | Deferral is durable and its timestamp is advisory. Only an explicit wake clears it; dependency settlement does not. |
| <a id="work-the-operator-closes-a-task-with-a-recorded-validation"></a>**The operator closes a task with a recorded validation** | Only an operator may close a task, with nonblank validation, from any phase. A live claim refuses closure unless forced; a forced closure frees that claim in the same transaction and records the displaced holder. Task detail reads the closure back with its author, phase, and validation. |
| <a id="work-hidden-channels-keep-admissions-off-the-queue"></a>**Hidden channels keep admissions off the queue** | A hidden channel files a row off the default allocation queue so admitting a mistake is cheap; every read still renders the row in full. |
| <a id="work-a-dry-allocator-reports-the-board"></a>**A dry allocator reports the board** | A dry allocator names each parked category and why it is parked, and states that a populated board is expected. Only a dry allocator immediately after asking for work permits stopping; a quiet board or low pending count does not. |
| <a id="work-tasks-without-acceptance-enter-a-plan-phase"></a>**Tasks without acceptance enter a plan phase** | A task created with neither acceptance nor a named flow gets a visible plan phase prepended rather than being refused. |
| <a id="work-a-plan-phase-closes-only-when-acceptance-exists"></a>**A plan phase closes only when acceptance exists** | A plan phase closes only when the task or a pending child connected in either dependency direction carries acceptance. Implementation work is refused while the actor holds a plan-phase claim. A child the plan holder adds whose origin is the plan or the plan's own origin depends on the plan atomically, so it cannot start until planning completes, unless `--depends` names its prerequisites explicitly; a task of any other origin is unrelated work and gets no edge to the plan. |
| <a id="work-captured-commits-enter-owned-implementation-atomically"></a>**Captured commits enter owned implementation atomically** | `task capture` of a new task records the task, active claim, and loose-commit boundary in one transaction and starts after any plan phase; any refusal writes none of them. |
| <a id="work-a-taste-hold-is-visible-before-a-task-is-read"></a>**A taste hold is visible before a task is read** | A statement matching the taste policy holds its task in plan, and status, assignment, and refusal name the hold where a lane first meets it. The author never learns which words matched, because an author told the word swaps the word instead of rewriting the statement; the operator reads the complete audit. Clearing the hold withdraws a plan phase the hold inserted, keeping any claim; an authored plan phase stays. |
| <a id="work-a-board-read-is-a-spice-resource"></a>**A board read is a `spice://` resource** | An omp occupant's `read` of `spice://board`, `spice://board/graph/VIEW`, `spice://task`, `spice://task/HANDLE` with `/context`, `/history`, `/detail`, or `/ledger`, and `spice://task/HANDLE/artifact` with `/ID` answers what `task status`, `board graph`, `task list`, `task show`, `doc ledger`, and `task artifact list` or `show` render for that lane's actor, with no side effect; `spice://` is the index. Query parameters are the read's own flags; a withheld page's continuation is the `spice://` URL that resumes it, and a collection ends with its child URLs. A line selector selects its lines or refuses; an unknown path, malformed handle, unadmitted or out-of-range parameter, or a path naming a command no resource serves refuses with a reason. A binary artifact answers with the local file holding its bytes, never inline data. |
| <a id="work-a-task-text-write-replaces-only-the-text-its-writer-read"></a>**A task text write replaces only the text its writer read** | An omp occupant's `read` of `spice://task/HANDLE/description` or `/acceptance` answers the current text, acceptance as `- ` items, under a first line naming the write URL and the `?digest=` of that text. A `write` of the whole new text to that URL is the `task modify` intent under the lane's actor, witnessing the statement head whose text the digest names, so it lands only where the CLI's edit would. A write naming a stale or no digest, an empty acceptance, a line selector, or any other `spice://` resource refuses with a reason, a digest refusal reporting the current digest, and the task is unchanged. |
