# Invariant register — Integration, lifecycle, topology, and surface

[Invariant register](../invariants.md) · [Spice product model](../README.md)
## Integration

| Label | Invariant |
| --- | --- |
| <a id="integration-agents-never-pull-and-never-push"></a>**Agents never pull and never push** | Agents never pull and never push. Agent-lane integration touches the lane's worktree at exactly three control-plane boundaries: launch, claim, and phase completion. Release, gate, proof, and installation Git operations belong to other boundaries. |
| <a id="integration-claim-synchronization"></a>**Claim synchronization** | At claim: fast-forward-only to the baseline, then record that point-in-time commit. |
| <a id="integration-phase-completion-integration"></a>**Phase-completion integration** | At phase completion: integrate baseline-first, or fast-forward when the baseline already descends from the local line. |
| <a id="integration-agent-launch-advancement"></a>**Agent-launch advancement** | At agent launch: advance opportunistically and never raise. Dirty, committed, divergent, or unfetchable lanes keep their work and start with a skip note. |
| <a id="integration-content-conflicts-are-framed-as-baseline-overlap"></a>**Content conflicts are framed as baseline overlap** | A real content conflict is the only raw Git synchronization failure surfaced to the agent, and it is framed as an overlap with the baseline rather than a sync with an upstream. Typed product refusals such as footprint and admission failures remain distinct. |
| <a id="integration-activation-is-deliberately-not-a-fourth-boundary"></a>**Activation is deliberately not a fourth boundary** | Activation is deliberately not a fourth boundary. It is replayed after every compaction, so any git work placed there lands mid-session between two of a live agent's own commands, against a tree the lane has just committed. |
| <a id="integration-a-conflict-installs-as-a-complete"></a>**A conflict installs as a complete** | A conflict installs as a complete, recoverable merge state or not at all; the visible terminal state is the untouched pre-merge tree or a recoverable merge. |
| <a id="integration-a-landing-whose-first-parent-diff-leaves-the-task-s-own-footprint-is-refused-with-a-recipe"></a>**A landing whose first-parent diff leaves the task's own footprint is refused with a recipe** | A landing whose first-parent diff leaves the task's own footprint is refused with a recipe. |
| <a id="integration-a-synthesized-tree-must-pass-the-declared-cheap-admission"></a>**A synthesized tree must pass the declared cheap admission** | Landing runs the configured cheap admission command, not the whole verification suite, when integration or a race produces a tree different from the lane's authored tree. A refusal leaves that tree checked out for repair and publishes nothing; an identical tree or an empty command skips the check. |
| <a id="integration-a-publish-race-re-integrates-against-the-newly-fetched-baseline"></a>**A publish race re-integrates against the newly fetched baseline** | A publish race re-integrates against the newly fetched baseline, preserving peer paths, with bounded retries. |
| <a id="integration-the-landing-merge-carries-the-task-s-key"></a>**The landing merge carries the task's key** | Every mutating landing carries the task's key, project, phase, and session, so first-parent history is the ledger of mutating landings. The journal and board remain the complete phase ledger, including clean transitions that publish no merge. |
| <a id="integration-a-recovery-recipe-names-the-resolved-commit-it-applies-to"></a>**A recovery recipe names the resolved commit it applies to** | A recovery recipe names the resolved commit it applies to, not a moving reference. |
| <a id="integration-the-checked-out-branch-cannot-be-rewound-past-commits-already-merged-upstream"></a>**The checked-out branch cannot be rewound past commits already merged upstream** | The checked-out branch cannot be rewound past commits already merged upstream. An update that would abandon them is refused, naming them and directing the work forward as an append rather than an amend or a reset. |
| <a id="integration-the-guard-reads-the-branch-tip-from-the-ref-itself"></a>**The guard reads the branch tip from the ref itself** | The guard reads the branch tip from the ref itself, not from the old value the caller declared. A caller that declares none sends a zero value, under which a rewind would read as a branch being created. |
| <a id="integration-the-upstream-is-resolved-from-the-branch-s-own-local-pairing-and-nowhere-else"></a>**The upstream is resolved from the branch's own local pairing and nowhere else** | The upstream is resolved from the branch's own local pairing and nowhere else — never through an alias a process-local configuration shadow can aim back at the branch itself, and not as a fallback either, since a fallback is exactly where such a shadow returns. |
| <a id="integration-naming-an-upstream-and-resolving-one-are-different-questions"></a>**Naming an upstream and resolving one are different questions** | Naming an upstream and resolving one are different questions. An append gives up no history and passes regardless; a rewind whose upstream does not resolve is refused as unknown rather than cleared. |
| <a id="integration-the-guard-assumes-no-particular-remote-or-branch-name"></a>**The guard assumes no particular remote or branch name** | The guard assumes no particular remote or branch name; whatever the pairing names is the upstream. |

## Lifecycle

| Label | Invariant |
| --- | --- |
| <a id="lifecycle-only-lifecycle-authority-launches-or-renews-occupants"></a>**Only lifecycle authority launches or renews occupants** | Only lifecycle authority decides to launch, restart, or renew an occupant. Detached supervisors record their own process phase and the UI derives lane presentation; rendering, snapshotting, and querying cause no lifecycle decision. |
| <a id="lifecycle-ambient-thread-ids-are-refused-at-launch"></a>**Ambient thread ids are refused at launch** | Ambient thread ids are refused at launch; a lane binds to the thread the launch answer names. |
| <a id="lifecycle-the-launch-prompt-is-neutral"></a>**The launch prompt is neutral** | The launch prompt is neutral; the real ask is recovered from live control-plane state. |
| <a id="lifecycle-capacity-follows-work"></a>**Capacity follows work** | Capacity follows work: a wake decision launches exactly one occupant into one vacant lane, and a later scan must observe that occupancy before capacity grows again. |
| <a id="lifecycle-the-normal-wake-trigger-is-two-ready-tasks"></a>**The normal wake trigger is two ready tasks** | The normal wake trigger is two derived-ready tasks — one to claim, one left on the board — where readiness excludes active claims. |
| <a id="lifecycle-a-lone-ready-task-is-not-stranded"></a>**A lone ready task is not stranded** | A lone derived-ready task is not stranded: after a starvation *age* it can launch one occupant by itself. |
| <a id="lifecycle-a-settle-interval-prevents-a-burst-from-beating-a-running-occupant-s-own-done-then-next-cycle"></a>**A settle interval prevents a burst from beating a running occupant's own done-then-next cycle** | No row is selected before settling. With at least two eligible rows, the newest READY origin in the complete eligible set must age through the settle interval; a newly eligible row extends the horizon. |
| <a id="lifecycle-capacity-selection-claim-and-start-are-one-serialized-decision"></a>**Capacity, selection, claim, and start are one serialized decision** | Capacity, selection, claim, and start are one serialized decision. |
| <a id="lifecycle-lifecycle-decisions-for-one-worktree-are-serialized"></a>**Lifecycle decisions for one worktree are serialized** | Lifecycle decisions for one worktree are serialized while sibling lanes proceed independently. |
| <a id="lifecycle-renewal-is-ordinary-steering"></a>**Renewal is ordinary steering** | Renewal is ordinary steering rather than a forced termination. |
| <a id="lifecycle-renewal-marks-a-lane-and-never-starts-one"></a>**Renewal marks a lane and never starts one** | Renewal records the operator's intent to replace a lane's occupant. It starts nothing: a live predecessor is only asked to hand off, and a vacant lane stays vacant. The mark waits until the next start of that lane — operator wake or any derived wake arm — consumes it and launches a fresh successor, or until the operator withdraws it. |
| <a id="lifecycle-the-lifecycle-reconciler-is-ephemeral"></a>**The lifecycle reconciler is ephemeral** | The lifecycle reconciler is ephemeral: it persists no lane snapshot and reads authoritative state when a decision runs. |
| <a id="lifecycle-vacant-lanes-resume-active-claims"></a>**Vacant lanes resume active claims** | If an occupant exits while its claim disposition remains `active`, the lane is vacant but the row is ineligible for ordinary allocation. The derived `HeldClaim` wake arm launches a successor onto that already-possessed task only once its durable READY origin is at least three seconds old. Claiming, carrying, or replaying the task preserves the origin, including a prior release or lapse; already-aged work incurs no fresh interval. This does not restrict immediate allocation by a running agent or explicit operator-directed wake. |
| <a id="lifecycle-the-held-claim-restart-takes-no-new-work-and-reserves-nothing"></a>**The held-claim restart takes no new work and reserves nothing** | The derived held-claim restart takes no new work and reserves nothing. The active claim stays put — freeing it would expose a task whose worktree still holds the predecessor occupant's uncommitted changes — and the successor decides whether to continue or free it. |
| <a id="lifecycle-the-held-claim-arm-applies-to-every-driven-lane"></a>**The held-claim arm applies to every driven lane** | Because it takes no new work, the held-claim arm applies to every driven lane, not only those permitted to expand onto the board. |
| <a id="lifecycle-the-restart-recovers-the-task-not-the-session"></a>**The restart recovers the task, not the session** | The restart recovers the *task*, not the session, and is explicitly not a wake signal. Agent-facing prose says so because queued steering and recovery of an active claim are distinct inputs even when both launch an occupant into a vacant lane. |
| <a id="lifecycle-one-retry-attempt-bucket-serves-every-wake-arm-for-a-lane"></a>**One retry-attempt bucket serves every wake arm for a lane** | One retry-attempt bucket serves every wake arm for a lane, and consulting the gate spends the attempt. Arms that can decline cheaply are consulted before the gate, so a lane holding nothing cannot throttle the arm behind it. |
| <a id="lifecycle-a-refusal-payload-names-which-wake-arm-produced-it"></a>**A refusal payload names which wake arm produced it** | A refusal payload names which wake arm produced it. |
| <a id="lifecycle-stop-criteria-are-inherited-by-every-arm-through-the-shared-ensure-path"></a>**Stop criteria are inherited by every arm through the shared ensure path** | Stop criteria are inherited by every arm through the shared ensure path rather than recopied. |
| <a id="lifecycle-ending-a-turn-vacates-the-lane"></a>**Ending a turn vacates the lane** | Every turn or process exit, including code zero, ends that occupant and vacates the lane. A kept command remains owned by its detached keeper. If its non-stopped ending remains unheard through the delivery grace, the keeper requests a lane wake; a successor receives the completion during startup catch-up. |
| <a id="lifecycle-background-jobs-survive-turn-exit"></a>**Background jobs survive turn exit** | Waiting is optional lifecycle policy, not protection for the command: use `job wait` when its result blocks current work, while ending the turn neither cancels the job nor loses its completion. A job answer that reports the ending is the agent hearing it, so no completion notice repeats it. |

## Topology

| Label | Invariant |
| --- | --- |
| <a id="topology-a-lane-is-an-independently-steerable-worktree-seat"></a>**A lane is an independently steerable worktree seat** | A lane is an operator-owned seat for exactly one worktree; the agent is its occupant. Renewal swaps the occupant while lane history, drafts, and scroll survive. Task policy belongs to the team and remains on renewal because the team is unchanged; it does not follow a lane moved into another team. |
| <a id="topology-a-team-groups-one-or-more-lanes"></a>**A team groups one or more lanes** | A team groups one or more independently addressable lanes into one console; a team of one is the degenerate case, not a separate type. |
| <a id="topology-topology-is-server-truth"></a>**Topology is server truth** | Membership, member order, and topology revision are server truth. Browser-local presentation may hide a team without changing that topology. |
| <a id="topology-palette-size-does-not-bound-team-membership"></a>**Palette size does not bound team membership** | Org membership is not capped by the finite accent palette. Accent slots may repeat without weakening explicit identity. |
| <a id="topology-a-fused-host-renders-one-merged-stream"></a>**A fused host renders one merged stream** | A fused host renders one merged stream; every member remains its own concrete send address. |
| <a id="topology-member-order-controls-composition-not-identity"></a>**Member order controls composition, not identity** | Chat projects canonical member order from the right control edge: member zero is the main member and each later member sits one place farther left. Global Dash projects the same canonical order from the left control-flow origin, so member zero is farthest left and later members proceed rightward. Order controls surface position and accent slot, but message chronology and explicit lane attribution do not derive from position. |
| <a id="topology-a-member-that-momentarily-fails-to-resolve-keeps-its-seat-and-its-lane"></a>**A member that momentarily fails to resolve keeps its seat and its lane** | A member that momentarily fails to resolve keeps its seat and its lane rather than being ejected. |
| <a id="topology-message-order-is-a-pure-function-of-the-messages"></a>**Message order is a pure function of the messages** | Message order is a pure function of the messages, never of member order. |
| <a id="topology-leave-all-teams-makes-a-member-independent"></a>**Leave all teams makes a member independent** | `Leave all teams` removes one member from its team through the resident. That member becomes an independent agent for every browser, and a team whose last member leaves leaves the lane table; a refusal leaves the team as it was. No browser hides a team locally. |
| <a id="topology-team-mutations-use-optimistic-concurrency-on-a-monotonic-revision"></a>**Org mutations use optimistic concurrency on a monotonic revision** | Org mutations use optimistic concurrency on a monotonic revision; a client that loses re-pulls. |
| <a id="topology-a-failed-enumeration-is-not-evidence-of-absence"></a>**A failed enumeration is not evidence of absence** | A failed enumeration is not evidence of absence: transient discovery failure closes nothing. |

## Surface

| Label | Invariant |
| --- | --- |
| <a id="surface-a-card-whose-position-did-not-change-receives-no-style-write"></a>**A card whose position did not change receives no style write** | A card whose position did not change receives no style write; the write is skipped rather than relying on idempotence. |
| <a id="surface-new-content-places-by-insert"></a>**New content places by insert** | New content places by insert; existing cards are not re-decided, re-measured, or re-spanned. |
| <a id="surface-a-card-s-column-and-span-latch-between-geometry-replays"></a>**A card's column and span latch between geometry replays** | A card's column and span stay latched between full geometry replays; during incremental content changes, only its vertical position settles. |
| <a id="surface-growth-ripples-down-along-the-original-layout"></a>**Growth ripples down along the original layout** | Growth ripples down along the original layout. Frozen-card shrink keeps its reservation; liquid-card shrink adopts the smaller height and replays the liquid region. |
| <a id="surface-layout-is-a-pure-function-of-creation-order"></a>**Layout is a pure function of creation order** | Layout is a pure function of creation order, measured content, and geometry — replayable to identical positions. |
| <a id="surface-pending-images-are-remeasured-after-resolution"></a>**Pending images are remeasured after resolution** | A pending image uses a generic placeholder. Load or error changes its content revision and remeasures the whole card at its latched horizontal span; the resulting height may grow or shrink. |
| <a id="surface-image-failure-is-distinct-from-still-loading"></a>**Image failure is distinct from still loading** | Captured image `load` and `error` events set distinct resolved states before the whole card is remeasured. |
| <a id="surface-a-reader-more-than-80px-from-the-top-is-compensated-in-the-same-frame"></a>**A reader more than 80px from the top is compensated in the same frame** | Scroll positions greater than 80px are protected by same-frame compensation. Positions from 0 through 80px use near-top behavior and show the push-down. |
| <a id="surface-compensation-lands-regardless-of-motion-preference"></a>**Compensation lands regardless of motion preference** | Compensation lands regardless of motion preference; only the transition respects it. |
| <a id="surface-nothing-animates-until-the-board-first-settles"></a>**Nothing animates until the board first settles** | Nothing transitions until the board first settles. An unmeasurable surface renders cards in ordinary base flow but commits no lattice geometry until a measurable width arrives. |
| <a id="surface-a-deferred-render-does-not-commit-its-fingerprint"></a>**A deferred render does not commit its fingerprint** | A deferred render does not commit its fingerprint. |
| <a id="surface-movement-means-change"></a>**Movement means change** | Movement means change: any motion corresponds to something that actually changed. |
| <a id="surface-revealed-affordance-surfaces-open-out-of-flow-and-do-not-reflow-the-board"></a>**Revealed affordance surfaces open out of flow and do not reflow the board** | Revealed menu, picker, overlay, and drag-ghost surfaces open out of flow and do not reflow the board. The agent-menu `<details>` control itself remains in flow and bounded to its shard; its revealed drawer is the out-of-flow surface. |
| <a id="surface-a-changing-region-holds-its-largest-footprint"></a>**A changing region holds its largest footprint** | A region whose contents arrive, change, or leave reserves the block size of its largest item, up to its own cap, so a first arrival, a last departure, or a change between items moves nothing outside it. Loading, unavailable, and empty placeholders reserve that same footprint. Only growth past the cap or an operator's own action may move what follows. |
| <a id="surface-retained-task-detail-does-not-move-for-background-feedback"></a>**Retained task detail does not move for background feedback** | Reconnect, task-detail refresh, relationship refresh, and observation-save feedback use a task-owned out-of-flow toast while admitted detail, map geometry, and the observation form remain in place. Pending task feedback remains until its operation settles even when an unrelated result uses the shared toast; each settled result clears only its own toast. Initial loading and unavailable states still replace absent content explicitly, and a refused observation retains its actionable draft. |
| <a id="surface-deadline-driven-live-text-renders-in-fixed-width-slots"></a>**Deadline-driven live text renders in fixed-width slots** | Relative ages update only at the next instant their visible spelling can change: each second while seconds-old, then once per displayed minute, hour, or day, and never after saturation. Fixed-width slots keep those updates from resizing a box. |
| <a id="surface-task-count-triples-have-dynamic-width"></a>**Task-count triples have dynamic width** | A public global task pill renders an unpadded `ready · active · unavailable` string. All three semantic slots are present, but digit-width changes may resize the content-driven pill. A team header's per-task pills carry no count. |
| <a id="surface-presentation-only-changes"></a>**Presentation fields do not directly remeasure cards** | Recolouring and attribution toggles stay out of card identity and style. Member count is also excluded from direct per-card remeasure identity, but it remains team visual weight: a changed settled host width may trigger one full geometry replay. |
| <a id="surface-prose-card-punctuation-is-presentation-only"></a>**Prose-card punctuation is presentation only** | An assistant prose card presents unpunctuated terminal prose with a period and presents a terminal colon as a period. Other trailing punctuation and cards ending in structured content remain verbatim; the taped message is never rewritten. |
| <a id="surface-programmatic-scroll-is-excluded-from-anything-that-reads-user-intent"></a>**Programmatic scroll is excluded from anything that reads user intent** | Programmatic scroll is excluded from anything that reads user intent. |
| <a id="surface-each-changed-stream-frame-publishes-immediately"></a>**Each changed stream frame publishes immediately** | Displayable taped records are projected on arrival independently of unrelated journal-writer work; durable accounting remains guarded and separate. Tape order and lane, occupant, source, and locus identity survive live publication, catch-up, and reload. Each admitted stream frame that changes runtime state immediately sets the browser surface; no arrival-batch or animation-frame coalescing contract is implied. |
| <a id="surface-completed-acknowledgment-prose-does-not-wait-for-settlement"></a>**Completed acknowledgment prose does not wait for settlement** | Completed authored OMP ACK or NAK prose publishes at `text_end` when the tape source, message identifier, creation timestamp, and content-block index establish its identity. Later settlement, older pages, replay, and reconnect leave one card for that block, keeping the original words even when the provider normalizes commentary into reasoning. A tool-intent fallback for the same scoped message and already represented answer keys is not another response. Reused identifiers, repeated words, and distinct blocks are never text-deduplicated; reasoning and retirement facts never supply a card body. |
| <a id="surface-every-served-page-carries-its-own-observation"></a>**Every served page carries its own observation** | A record with no vendor timestamp displays the durable accounting instant of the batch that read it, whatever window serves the record, so an older page never falls back to the synthetic instant that only orders it. A page reaching past what earlier pages read walks this lane's accounting facts backwards from where the last walk stopped, bounded per page, and accepts only a batch naming the same lane and source generation whose span contains the record. |
| <a id="surface-one-compaction-is-one-boundary"></a>**One compaction is one boundary** | A compaction that the captured stream announces and the vendor's preserved session file also records is one card on every surface, in live publication, older pages, reload, and restart alike. Representations are matched by the identity both records state — the provider entry that replaced the compacted history, otherwise the first entry the compaction kept with the tokens it compacted — never by summary text, so two compactions that summarize alike stay two boundaries. The preserved record represents the compaction whichever record arrived first, because it is the one carrying the vendor's own timestamp. |
| <a id="surface-each-agent-keeps-its-newest-messages"></a>**Each agent keeps its newest messages** | Every agent independently keeps its newest 25 messages on every surface that retains cards, through initial materialization, older pages, live arrival, reconnect, and any eviction; an agent with fewer keeps all of them. The floor counts messages: turn and compaction markers stand among them and never satisfy it on a message's behalf. Neither a card budget nor the compaction horizon, which otherwise drops the context epoch below a compaction, may cut into it, and a busy peer spends only its own floor. It is a floor and not a cap: a surface may retain more. |
| <a id="surface-accent-derives-from-stable-lane-identity"></a>**Accent derives from canonical member position** | Accent begins with green at canonical member zero beside the team controls and advances through the finite palette toward the left. The compact team-light stack likewise starts at the right edge, fills each column bottom-to-top, then grows left. Colours may repeat, so accent is presentation and never the sole attribution channel. |
| <a id="surface-at-most-one-audio-element-sounds-at-a-time"></a>**At most one audio element sounds at a time** | At most one audio element sounds at a time, and stop is immediate, idempotent, and global. Each queued entry retains its originating worktree's admitted speech contract, so sequential agents may use different voices without concurrent playback. |
| <a id="surface-nothing-older-than-the-moment-the-operator-opened-a-lane-auto-plays"></a>**Nothing older than the moment the operator opened a lane auto-plays** | Nothing older than the moment the operator opened a lane auto-plays. |
| <a id="surface-speech-is-best-effort"></a>**Speech is best-effort** | Detected speech failure reports nonblocking `Speech unavailable` state and never blocks the visible stream. External rendering has a deadline; browser system synthesis is callback-settled and a missing terminal callback leaves the active head until global stop. |
| <a id="surface-a-draft-is-restored-intact-on-a-typed-refusal-or-fault"></a>**A draft is restored intact on a typed refusal or fault** | A draft detaches at submit. A typed wake, residency, or write refusal or fault restores it with attachments and quoted material intact; transport loss instead requeues the in-memory submission. |
| <a id="surface-sends-drain-serially-per-lane"></a>**Sends drain serially per lane** | Sends drain serially per lane; a rejection stops the queue and returns every undelivered draft rather than continuing past it. |
| <a id="surface-the-pending-count-is-a-floor-over-backend-truth"></a>**The pending count is a floor over backend truth** | A live acceptance retains its prediction in the pending-count floor until a post-acceptance read covers the same directive and key. That captured identity retires it; decrement and timeout never do. |
| <a id="surface-unsubmitted-intent-resists-loss"></a>**Unsubmitted intent resists loss** | An unsafe draft or queued submission installs a page-leave confirmation guard. |
| <a id="surface-global-direction-history-pages-whole-fanouts"></a>**Global direction history pages whole fanouts** | Global Work reads operator directions as newest-first fanout groups through resident filters and journal keyset cursors. One bounded page replaces another without splitting recipients or retaining a stale-generation answer. Each page reports its offset among matches, so an anchored page shows its true range. A direction route anchors the unfiltered read on one directive, fanout, or key and marks that card. Only the resident's refusal of an unknown anchor, not an absent page, makes the route leave. Recipient state remains per directive; current topology may turn it into an exact team-local Chat link, while absent topology remains visible and inert. |
| <a id="surface-a-late-completion-does-not-take-focus-the-operator-has-since-moved-elsewhere"></a>**A late completion does not take focus the operator has since moved elsewhere** | A late completion does not take focus the operator has since moved elsewhere. |
| <a id="surface-the-composer-strip-reports-state-the-operator-did-not-ask-for"></a>**The composer strip reports state the operator did not ask for** | The composer strip reports state the operator did not ask for — age, run state, pending count, claimed work — so it is a status surface as much as an input. |
| <a id="surface-chat-scroll-passively-controls-composer-exposure"></a>**Chat scroll passively controls composer exposure** | Browser-native wheel, touch, and focused-plane keyboard motion always retains ownership of the message plane. The mounted composer overlays the plane's top spacer and moves exactly as far as the cards scroll, pixel for pixel, until it is fully hidden or revealed; it never cancels input or writes the plane's scroll position, and reaching either exposure limit cannot halt inertia. Home and End set matching exposure and reach the native stream edge in one command. The team toolbar remains visible with the live status ticker between lane lights and the hamburger, drafts and controls retain state, and programmatic Mosaic scroll correction never changes composer exposure. |
