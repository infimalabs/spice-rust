| <a id="lifecycle-due-lanes-wake-in-the-configured-claim-order"></a>**Due lanes follow the configured wake order** | Machine-local `lane.wake_order` is `best-match` (the default), `most-recently-claimed`, or `least-recently-claimed`. Within a due work trigger, ordinary work precedes a lane's own last-resort work. Once message startup has restored retained profiles, each vacant lane selects its work with the allocator's ladder scored by how well the lane's retained sessions match each candidate, through the ranker Design nudges and `task next` use and never counting that task's own cards; the profile lock is taken and the fit made once per reconciliation pass, and a score below the lowest Design invitation floor counts as nothing. Under `best-match`, lanes due for the same work trigger then rank by that score for the task each selected; a lane with no score ranks below every scored lane, and equal or absent scores fall to newest claim first. The recency orders rank by latest durable claim, newest-first or oldest-first; a lane without claims ranks last in newest-first order and first in oldest-first order. Lane identity breaks ties. The rank never overrides trigger precedence, due deadlines, backoff, or holds, and inbox and held-claim wakes rank by recency alone. Before message startup restores retained profiles, every lane selects the unscored ladder and `best-match` ranks by newest claim. |
| <a id="lifecycle-allocation-evidence-follows-task-head-generations"></a>**Allocation evidence follows task-head generations** | The resident derives dependency resolution, inherited priority, and downstream reachability once for one current task-head generation, then shares that evidence across every vacant lane. Unrelated journal commits retain it. Current actor, subscription, residency, hold, environment, and time evidence remain inputs to each wake decision, so sharing computation never freezes authority. |
| <a id="lifecycle-a-resident-assignment-reaches-the-exact-occupant-live"></a>**Assignments reach the exact occupant** | An automatic claim privately announces its task and phase to the current claimant once per claim identity. The notice carries no steering acknowledgment key and cannot reach a successor as its predecessor's assignment. |
| <a id="lifecycle-a-vendor-refusal-does-not-replay-identical-input"></a>**Vendor refusal does not replay identical input** | A vendor refusal holds the lane while its exact resumable session, pending operator direction, and renewal remain unchanged, even after the hold deadline. Explicit operator wake or changed input releases it. A retained vendor hold without that exact input refuses at writable open before runtime can reinterpret it. Operator reads expose bounded failure evidence, not refused prompts or reasoning. |
| <a id="lifecycle-services-belong-to-one-claim-win"></a>**Services have one explicit lifetime owner** | A service launched while the occupant holds an active task records that task and exact claim win. It survives occupant succession and lease renewal under the same win; losing the win or advancing its phase stops it. A service launched without a task records no task and belongs to its launching occupant turn, which stops it on exit. Unreadable task or turn authority cannot authorize continued service. Finite commands record the same optional ambient task but remain lane-owned. |
| <a id="lifecycle-one-workflow-variant-owns-related-state"></a>**One workflow variant owns related state** | A pending workflow owns its review state and any assigned reviewer. A settled workflow owns its terminal instant and a positive-completion, operator-closure, or deletion conclusion. The canonical stored document retains the flat `status`, `review`, `assignment`, and `completion` spelling, but current readers decode only combinations represented by those variants and refuse contradictory combinations rather than interpreting them. Writable admission first crosses retained terminal review spellings once: deletion keeps its negative standing, and a completed workflow retaining an assigned or finding review keeps its prior positive standing without claiming clean review. The original verdict stays in immutable facts; settlement instants, generations, and head positions do not change. Derived task-relationship responses carry the same canonical status as a closed enum, so app projections cannot branch on unchecked workflow text. |
| <a id="lifecycle-one-typed-authority-selects-the-current-oops-design"></a>**One typed authority selects the current OOPS Design** | The repository OOPS generation is vacant or names exactly one open `OpportunisticDesign`. Opening and settling that Design advance the singleton in the same transaction as the task lifecycle facts. Intake witnesses this authority and the exact named Design heads, not a title, project spelling, whole-board barrier, or journal cursor, so unrelated board traffic cannot starve reports. Concurrent first reports retry once against the winner and become Plans under the same generation. Writable admission derives the head once from a unique retained open opportunistic Design and refuses an ambiguous predecessor rather than retaining a release-specific runtime path. |

| Label | Invariant |
| --- | --- |
| <a id="surface-image-failure-is-distinct-from-still-loading"></a>**Image failure is distinct from loading** | A failed image remains distinguishable from an image still loading. |
| <a id="surface-compensation-lands-regardless-of-motion-preference"></a>**Motion preference does not disable anchoring** | Reduced motion removes transitions, not the correction that preserves the reader's position. |
| <a id="surface-a-changing-region-holds-its-largest-footprint"></a>**A changing region holds its largest footprint** | A region whose contents arrive, change, or leave reserves the block size of its largest item, up to its own cap, so a first arrival, a last departure, or a change between items moves nothing outside it. Loading, unavailable, and empty placeholders reserve that same footprint. Only growth past the cap or an operator's own action may move what follows. |
| <a id="surface-chat-scroll-passively-controls-composer-exposure"></a>**Chat scroll passively controls composer exposure** | Browser-native wheel, touch, and keyboard scrolling owns the Chat plane. The composer moves exactly as far as the cards scroll until it is fully hidden or revealed, never cancelling input or halting inertia. Outside the composer's own fields, Home and End fully reveal or hide it as the stream reaches its native edge. Focus entering the composer reveals it fully without moving the cards, and programmatic Mosaic scroll correction never changes exposure. The team toolbar sits outside the plane and stays visible. |
| <a id="surface-retained-task-detail-does-not-move-for-background-feedback"></a>**Background feedback preserves task detail** | Reconnect and observation feedback leave admitted task detail and actionable drafts in place. Refreshing retained reads is silent; pending feedback remains until its own operation settles. Task lifecycle and ordinary action feedback own separate stacked slots in the common lower toast area, so either lifecycle may replace or dismiss only its own message without reflowing task or modal surfaces. |
| <a id="surface-completed-acknowledgment-prose-does-not-wait-for-settlement"></a>**Completed acknowledgment prose publishes before settlement** | Completed authored acknowledgment prose appears without waiting for provider settlement. Its original words and block identity survive settlement, replay, and reconnect; an already represented tool-intent answer adds no duplicate card. Repeated words or reused provider identifiers alone never merge distinct responses. Reasoning and retirement facts supply no card body. |
| <a id="surface-every-served-page-carries-its-own-observation"></a>**Undated records use their accounting time** | A record without a vendor timestamp uses the durable accounting time of the batch that read it, including on older pages. Only accounting evidence for that lane and source generation may supply the time; synthetic ordering time is not observation time. |
| <a id="surface-one-compaction-is-one-boundary"></a>**One compaction is one boundary** | Captured and preserved representations of the same successful compaction produce one boundary, identified by provider identity rather than summary text. A failed provider attempt produces no boundary. The preserved record supplies the vendor timestamp regardless of arrival order, while the captured completion supplies its reported method when the preserved record omits it. That method survives live delivery, replay, and reconnect; absence keeps the plain compaction label. Separate successful compactions with identical summaries remain separate. |
| <a id="surface-each-agent-keeps-its-newest-messages"></a>**Each agent retains its own recent messages** | Retention protects a recent-message floor independently for each agent, even across compaction and eviction. Boundaries do not satisfy that floor, and a busy peer cannot consume it. The floor is not a cap. |
| <a id="surface-at-most-one-audio-element-sounds-at-a-time"></a>**Speech is globally serialized** | Only one speech entry plays at a time. Stop is immediate and global. Each entry uses its originating worktree's admitted speech contract, so sequential agents may use different voices. The installed 200-WPM target maps once to the browser's native `1.0` rate; other targets scale relative to it within the browser's supported bounds. |
| <a id="surface-a-retired-app-generation-reloads-once"></a>**A retired app generation reloads once** | A resident answers every route qualified with a generation it does not hold with 410 Gone naming the generation it serves; an installed resident holds exactly one, the generation linked into its executable, which is the only canvas carrier installation publishes (install schema 18's app sidecars cross forward once and are discarded). A page meeting that answer, whether for its shell module, wasm, or a renderer document or member, reloads once into the served generation with unsent drafts handed off, exactly as when its next connection's bootstrap names another generation, whether or not the app protocol changed. A submission whose result is unknown keeps the page in place. |
