# LATER

This file is the boundary of release one, not a backlog. A waiting surface
enters the corpus only when its recorded trigger exists and the resulting
change can satisfy the standing doctrine, naming law, and proof boundary.
Everything else remains absent.

## Never

| Surface | Doctrine |
| --- | --- |
| Multi-user authority | Spice has one operator capability. It does not arbitrate independent human principals, ownership domains, or competing policy authorities. A product requiring those semantics is not an extension of this appliance. |
| Agent-to-agent messaging | Lanes coordinate through tasks, facts, directives, and visible repository evidence. No private lane channel, addressing scheme, mailbox, or conversational protocol is admitted. |

## Waiting

| Surface | Evidence trigger |
| --- | --- |
| Northbound ACP server | A real external ACP client must attach to Spice, and its identity, consent, reconnect, cancellation, and recovery behavior is captured as executable fixtures. Vendor-side ACP support does not satisfy this trigger. |
| Query DSL | A named operator or lane question cannot be answered by the typed board, fold, thread, or recall surfaces without adding a one-off command or duplicating reduction logic. The question, required bounds, and expected refusal cases must be recorded first. |
| Plugin API | A second independently maintained extension cannot fit a compiled builtin boundary, and both extensions demonstrate the same loading, trust, failure, version, and evidence contract. One prospective extension is not a platform. |
| Multi-machine authority | Two machines must concurrently act on one repository authority and an explicit handoff cannot satisfy the use case. The evidence must include identity, conflict, partition, recovery, and clock behavior. Task synchronization is part of this surface; it is not a separate waiting item. |
| Adversarial isolation | A second Unix identity actually runs a lane and must be prevented from reading or exercising the operator capability. Until that event, actor and trust checks remain cooperative workflow interlocks and attribution. |
| Windows | A named deployment requires Windows and supplies proved replacements for the resident lock, process groups, local transport, shell duplex, path rules, atomic publication, and target proof. General portability interest is not demand. |
| Tape pruning | Measured tape pressure exceeds the declared operating bound, and an operator-approved retention policy defines segment eligibility, citation expiry, backup interaction, incident hold, erasure evidence, and recovery. |
| Migration bridge | An external consumer requires predecessor authority continuity that reviewed task document export, backup, and an empty start cannot provide. The demand must name the predecessor version, identity mapping, validation, failure, and reversal boundary. |
| Lane worktree provisioning | Worktrees are operator-created capacity today, and `lane add` only seats one that already exists — large working trees make automatic creation the wrong default. The trigger is a measured fleet pattern where manual creation is the demonstrated bottleneck, plus an operator-approved provisioning policy naming placement, size posture, and cleanup; even then it arrives off by default. |
| Mounted repository commands | A second real foreign-repository consumer needs the typed execution seam the retired `[commands]` table provided, and both consumers demonstrate the same trust, refusal, and evidence contract. One prospective consumer is not a seam. |
| Settled-statement correction | A settled task's statement is wrong in a way notes and review verdicts cannot carry, observed on a real board. The correction verb must preserve the settled boundary, witness the exact statement head, and leave the erroneous revision as history. |
| Steering attachments | An operator demonstrably needs to steer with non-text evidence — a screenshot, capture, or artifact — that a path or locus reference inside directive text cannot carry. The design must name storage ownership, retention, and rendering scope before any media crosses the wire. |
| Vendor record as tracked data | A vendor field rename that a tracked-data change could absorb forces a full release cycle in practice. Moving the record (versions, required fields, corpus path) under the trust digest must not weaken the compiled decoder's corpus-as-law posture. |

## Predecessor parity ledger

The clean break changes authority storage, not the capability contract. Rust
opens no Python authority bytes; predecessor state is backed up and retained as
forensic evidence. A capability is either **landed** on an executable Rust path
or **pending** on a public task whose acceptance records behavior and recovery
parity. It is not clipped merely because the replacement uses a different
mechanism. Operator direction `ack:1kJWMcnL` establishes that explicit cutover
authorization is a deployment gate, not deletion authority.
